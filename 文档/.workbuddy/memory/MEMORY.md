## 一、修改笔记的铁律（用户明确约定，2026-09-26）

1. **不许删除现有内容。** 用户要求修改笔记时，只能增补、扩充、改错，不得删掉已有的段落、代码块或结论。确有必要删除时，先说明并取得同意。
2. **发现错误先问再改。** 现有内容如有问题（笔误、命令写错、前后矛盾、类型/名称对不上等），必须先把「错在哪 + 建议怎么改」告知用户，得到确认后才动手；不要先改了再汇报。
3. **保留用户的原始表述。** 他自己写过的话（例如案例描述）尽量原样保留，只在其基础上补充。
4. **改写前先 Read 当前文件。** 用户会自己往笔记里加内容，不要基于上下文缓存覆盖。

## 二、文件构成与语言分离

- `ROS学习.md`：主文档。语言无关的概念、通信机制、接口文件格式、C++ 实现、常用工具。
- `ROS学习-Python.md`：Python 专属内容（开发环境、节点写法、ament_python 配置、HelloWorld、自定义接口的 Python 用法）。
- 两份文档之间用**交叉引用**（「见《ROS学习.md》3.6.4」），不复制正文，避免两处不同步。
- 唯一例外：`ROS学习.md` 1.1 保留 `sudo apt install python3-colcon-common-extensions`（colcon 唯一官方安装命令，用户确认保留）。

## 三、命名约定

- 功能包：`pkg_<语义>_<语言>`，如 `pkg_demo_cpp`、`pkg_demo_py`；接口包用 `pkg_<语义>_msg`，如 `pkg_demo_msg`。
- 节点名：`node_<语义>`，如 `node_demo`。
- 不再使用 `0922_1` 这类日期段，一律用通用词。

## 四、操作习惯

## 五、权威信源与已核实结论

**校验信源**（2026-09-26 已用过）：

- 本笔记主干整理自赵虚左的教程站 `https://rzl6.github.io/ROS2_Tuition/`，核对时先取该站原文。
- 官方文档 `docs.ros.org` 有反爬（Anubis），**改从 GitHub 源码仓库取原文**：`https://raw.githubusercontent.com/ros2/ros2_documentation/<分支>/source/...`（Humble 分支路径如 `Tutorials/Beginner-Client-Libraries/Custom-ROS2-Interfaces.rst`、`Concepts/Basic/About-Interfaces.rst`）。

**已核实、勿再凭印象改**：

- msg **支持**字段默认值（`int32 X 123`），是 ROS2 相对 ROS1 的新增特性；例外为字符串数组与嵌套复杂类型。
- msg 常量名**必须**全大写；字段名必须以字母开头、不能以下划线结尾、不能有连续两个下划线。
- `byte` / `char` 与 `uint8` 在官方类型表中并列，**不是** uint8 的别名。
- 支持**有界字符串**：`string<=10 name`、`string<=10[<=5] names`（官方示例原文）；有界数组写法为 `type[<=N]`。
- 字段默认值不支持字符串数组与嵌套复杂类型；字符串默认值必须加引号。
- ROS2 话题是**多对多**关系（参考站与笔记 3.2 一致）。
- 安装 ROS2 设语言环境用的是 `LC_ALL`，不是 `LC`。
- 接口包注册用 `<buildtool_depend>rosidl_default_generators</buildtool_depend>`（官方 Humble 教程口径）；参考站用 `<build_depend>`，**以官方为准，笔记写的是对的**。
- 建接口包时**不要**加 `ros2 pkg create --dependencies rosidl_default_generators`（会生成 `<depend>`，与 `<buildtool_depend>` 重复）。
- 参考站 2.4 原文确认：动作底层是「服务 + 话题」，goal/result 走服务、feedback 走话题。
- `ros2 topic` 官方子命令：list（含 `-t`）、echo、info（含 `--verbose`/`-v`）、pub（默认 1 Hz 持续发布，`--once` 只发一条，`-w N` 等待 N 个订阅匹配）、hz、bw、find；接口定义用 `ros2 interface show <类型>` 查看。

## 六、格式约定（2026-09-26 统一）

**通信四节（3.2 话题 / 3.3 服务 / 3.4 动作 / 3.5 参数）固定顺序**：

定义句（`基于**XX**模式，也即：…`）→ 数量关系句（`一个XX上服务端只能有一个，客户端能有很多个。`）→ `- 例子：…` → 角色句（`X 称之为**中文（英文）**…`）→ 特性 bullet → `适用于**XX**的场景，例如…` → 对比 bullet（**与话题在前**）→ 接口说明 → `**服务端 / 客户端的关键接口**（以 rclcpp 为例）` → `**案例：xxx**` + `一个简单的案例：…` → `常用命令：`

**接口三节（3.6.1 msg / 3.6.2 srv / 3.6.3 action）固定结构**：

`**文件本身**`（bullet）→ `**结构：X段式**`（总述句 + 段/名称/含义三列表格）→ 代码块 → bullet 补充

**通用排版规则**：

- 术语首次出现一律写成「中文（英文）」：`客户端（Client）`、`目标（goal）`、`请求（request）`。
- 案例标题一律用独立加粗行 `**案例：xxx**`，正文以「一个简单的案例：」起头。3.2 有两个案例，用 `**案例一：xxx**` / `**案例二：xxx**`。
- 代码块注释用「中文（英文）」形式。
- 「关键接口」小节标题随该节的角色而定：3.2 为 `**发布方 / 订阅方的关键接口**`，3.3 / 3.4 / 3.5 为 `**服务端 / 客户端的关键接口**`（标题顺序与下方 bullet 顺序一致）。
- 命令块的注释统一对齐到**第 57 列**（`#` 落在第 57 列，命令部分补空格到 56 字符）；**过长命令行不参与对齐**，命令与注释之间留两个空格。
- **动作三要素一律按 `.action` 文件段序写**：目标（goal）→ 结果（result）→ 反馈（feedback），不在概念段改用执行时序。
