## 1. 一页速查（TL;DR）

```bash
# ---------- 一次性准备 ----------
source /opt/ros/humble/setup.bash
mkdir -p ~/ros2_ws/src && cd ~/ros2_ws/src
git clone <repo-url> ros2-patrol-robot-sim
ln -s ros2-patrol-robot-sim/src/* .
cd ~/ros2_ws
bash src/ros2-patrol-robot-sim/scripts/install_deps.sh

# ---------- 每次构建 ----------
cd ~/ros2_ws
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash

# ---------- 首次：建图（只需做一次）----------
ros2 launch patrol_robot_bringup mapping.launch.py
#   → 另开终端遥控走一圈：ros2 run turtlebot3_teleop teleop_keyboard
#   → 保存地图：
ros2 run nav2_map_server map_saver_cli \
  -f ~/ros2_ws/src/patrol_robot_bringup/maps/tb3_world

# ---------- 日常：一键巡逻演示 ----------
ros2 launch patrol_robot_bringup patrol.launch.py
#   → 另开终端开始巡逻：
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"
```

## 2. 仓库与工作空间布局

### 2.1 推荐布局

```
~/ros2_ws/                              ← colcon 工作空间根
├── build/                              ← 编译中间产物（不入 Git）
├── install/                            ← 编译产物（不入 Git）
├── log/                                ← 编译日志（不入 Git）
└── src/                                ← 源码
    ├── patrol_interfaces/              ← 符号链接或直接拷贝
    ├── patrol_robot_core/
    ├── patrol_robot_bringup/
    └── ros2-patrol-robot-sim/          ← Git 仓库（含 docs/ scripts/）
```

**两种放置方式**：

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| A（推荐） | 克隆仓库到 `src/`，再把 `src/ros2-patrol-robot-sim/src/*` 软链到 `src/` | 仓库结构完整（含文档） |
| B（简单） | 直接把仓库 `src/` 下的三个包拷到 `~/ros2_ws/src/` | 只想跑代码 |

### 2.2 方式 A 的具体命令

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
git clone <repo-url> ros2-patrol-robot-sim

# 建立软链接，让 colcon 能在 src/ 下直接看到三个包
ln -s "$PWD/ros2-patrol-robot-sim/src/patrol_interfaces" .
ln -s "$PWD/ros2-patrol-robot-sim/src/patrol_robot_core" .
ln -s "$PWD/ros2-patrol-robot-sim/src/patrol_robot_bringup" .

ls -l    # 确认三个软链接存在且指向有效路径
```

> **为什么用软链接**：这样在仓库里改代码（或 `git pull`）后，工作空间立刻可见，
> 不需要重新拷贝。`colcon build --symlink-install` 也依赖链接来加速迭代。

## 4. 构建

### 4.1 完整构建

```bash
cd ~/ros2_ws
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

### 4.2 常用构建变体

| 场景 | 命令 |
| --- | --- |
| 只编译本项目 | `colcon build --packages-up-to patrol_robot_bringup --symlink-install` |
| 只编译核心包 | `colcon build --packages-select patrol_robot_core --symlink-install` |
| Debug 构建（带符号） | `colcon build --cmake-args -DCMAKE_BUILD_TYPE=Debug` |
| 带 ASAN 检查 | `colcon build --cmake-args -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined"` |
| 单包详细输出 | `colcon build --packages-select patrol_robot_core --event-handlers console_direct+` |
| 清理重编 | `rm -rf build install log && colcon build --symlink-install` |

### 4.3 构建产物校验

```bash
# 可执行文件存在
ls -l install/patrol_robot_core/lib/patrol_robot_core/
# 期望：patrol_node  safety_guard_node  libpatrol_core_lib.so

# 可运行
ros2 run patrol_robot_core patrol_node --help 2>&1 | head -5
# 或直接启动（会因 Nav2 未运行而报 ERROR，属于预期，说明二进制可用）
```

### 4.4 构建命令未找到 package 的排查

```bash
# 1. 确认包在 src 下被 colcon 识别
colcon list
# 期望列出三个包

# 2. 若未列出，检查软链接是否有效
ls -l ~/ros2_ws/src
readlink -f ~/ros2_ws/src/patrol_robot_core

# 3. 确认 package.xml 存在且格式正确
xmllint --noout ~/ros2_ws/src/patrol_robot_core/package.xml
```


```bash

```

## 6. 运行链路 2：建图（首次必做一次）

**用途**：生成 `maps/tb3_world.{pgm,yaml}`，供后续导航使用。

### 6.1 步骤

```bash
# 终端 1：仿真 + SLAM + RViz + 遥控（mapping.launch.py 已含全部）
ros2 launch patrol_robot_bringup mapping.launch.py
```

此时会打开 3 个窗口：Gazebo、RViz2、遥控终端。

```bash
# 终端 2（若 launch 里的遥控没有自动获得焦点，手动启动）
ros2 run turtlebot3_teleop teleop_keyboard
```

**建图操作要点**：

1. 在 RViz 中把 **Fixed Frame** 设为 `map`（左上角下拉框）。
2. 添加 `LaserScan` 显示（Topic 选 `/scan`），确认能实时看到雷达数据。
3. 用键盘**缓慢**驱动机器人绕世界走一圈，重点覆盖所有你想让机器人巡逻的区域。
4. 转弯时放慢速度——过快会导致 SLAM 重影。
5. 感觉地图完整后，停止遥控。

### 6.2 保存地图

```bash
# 终端 3
cd ~/ros2_ws/src/patrol_robot_bringup/maps
ros2 run nav2_map_server map_saver_cli -f tb3_world

ls -lh
# 期望：
# tb3_world.pgm    （图像，几十 KB ~ 几百 KB）
# tb3_world.yaml   （元数据）
```

`tb3_world.yaml` 内容应类似：

```yaml
image: tb3_world.pgm
mode: trinary
resolution: 0.05
origin: [-3.5, -3.2, 0.0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.25
```

### 6.3 地图质量检查

| 检查项 | 合格标准 | 不合格的处理 |
| --- | --- | --- |
| 墙体连续 | 边界清晰、无断裂 | 重新缓慢走一遍 |
| 无重影 | 同一面墙不出现"两层" | 降低行驶速度、减少急转 |
| 覆盖完整 | 所有巡逻区域已被扫描 | 补走未覆盖区域 |
| 坐标原点合理 | `origin` 数值在 ±5 m 内 | 正常，无需处理 |

### 6.4 重要：航点必须在可通行区域内

在地图上选航点时，**必须**选择白色（空闲）区域，且距墙体至少 0.5 m。
可在 RViz 中把鼠标移到目标位置，读状态栏的 `(x, y)` 坐标，填入 `patrol_params.yaml`。

## 7. 运行链路 3：导航（手动点目标）

**用途**：验证 Nav2 链路正常，为巡逻做准备。

```bash
# 终端 1
ros2 launch patrol_robot_bringup navigation.launch.py
```

**操作**：

1. 等 RViz 中地图加载完成（约 5–10 秒）。
2. 用工具栏的 **`2D Pose Estimate`** 在地图上点击并拖拽，设置机器人初始位姿
   （方向要与 Gazebo 中机器人的朝向大致一致）。
3. 观察 `/scan` 点云是否与地图墙体对齐（对齐说明定位正确）。
4. 用工具栏的 **`Nav2 Goal`** 在地图上点击目标点，机器人开始规划路径并移动。

**命令行备选（无需 RViz）**：

```bash
# 设置初始位姿
ros2 topic pub --once /initialpose geometry_msgs/msg/PoseWithCovarianceStamped \
"{header: {frame_id: 'map'}, pose: {pose: {position: {x: 0.0, y: 0.0}, orientation: {w: 1.0}}}}"

# 下发目标
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
"{pose: {header: {frame_id: 'map'}, pose: {position: {x: 1.0, y: 0.5}, orientation: {w: 1.0}}}}" --feedback
```

**校验**：

```bash
ros2 action list | grep navigate_to_pose     # 应列出
ros2 node list | grep -E "planner|controller|bt_navigator"   # 应列出
ros2 lifecycle get /bt_navigator             # 期望 active
```

## 8. 运行链路 4：全自动巡逻（一键演示）

**用途**：演示与验收。

```bash
# 终端 1：一键启动全部（仿真 + Nav2 + 两个自研节点）
ros2 launch patrol_robot_bringup patrol.launch.py
```

**启动后依次执行**：

```bash
# 终端 2：设置初始位姿（若 patrol_params.yaml 中未写死 initial_pose）
ros2 topic pub --once /initialpose geometry_msgs/msg/PoseWithCovarianceStamped \
"{header: {frame_id: 'map'}, pose: {pose: {position: {x: 0.0, y: 0.0}, orientation: {w: 1.0}}}}"

# 终端 3：开始巡逻
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"
#   期望：success=True message='OK' current_mode=1

# 终端 3：观察状态（1 Hz 输出）
ros2 topic echo /patrol/status

# 终端 3：暂停 / 继续 / 停止
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 1}"
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 2}"
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 3}"
```

**RViz 中需要添加的显示**：

| 显示类型 | Topic | 作用 |
| --- | --- | --- |
| Map | `/map` | 栅格地图 |
| LaserScan | `/scan` | 实时雷达 |
| Path | `/plan` | 全局路径 |
| MarkerArray | `/patrol/markers` | **航点与进度**（核心） |
| TF | — | 坐标系 |
| PoseWithCovariance | `/amcl_pose` | 定位结果 |
| Image / Plot | `/safety/nearest_obstacle_distance` | 障碍距离曲线（用 rqt_plot 更合适） |

### 8.1 `auto_start=true` 的免交互演示

若希望**启动即巡逻**（演示时更省事）：

```bash
ros2 launch patrol_robot_bringup patrol.launch.py auto_start:=true
```

或在 `patrol_params.yaml` 中设 `auto_start: true`。

> **注意**：`auto_start` 在导航栈完全激活前可能因初始位姿未设置而失败。
> 若 AMCL 未收到初始位姿，机器人位姿会停在原点，导致航点不可达、触发重试。
> **建议**在 `nav2_params.yaml` 的 `amcl` 段中写死 `initial_pose`，或在演示时用 `2D Pose Estimate`。

### 8.2 安全守护的演示方式

```bash
# 终端 4：观察安全标志
ros2 topic echo /safety/emergency_stop

# 终端 4：手动触发（不插障碍物，直接模拟）
ros2 topic pub --once /safety/emergency_stop std_msgs/msg/Bool "{data: true}"
#   → patrol_node 应暂停导航，状态变为 MODE_SAFETY_HOLD(4)

ros2 topic pub --once /safety/emergency_stop std_msgs/msg/Bool "{data: false}"
#   → patrol_node 应恢复导航
```

> **注意**：手动发布会让安全节点与手动发布者同时写同一话题（QoS 都是 transient_local），
> 之后 `safety_guard_node` 下一次状态翻转时会覆盖你的手动值。
> 仅用于验证联动逻辑，不要作为正式演示手段——正式演示请用 Gazebo 插障碍物的方式。

**正式演示方法（推荐）**：

1. 在 Gazebo 菜单栏 `Insert` → 选择 `Box`。
2. 在机器人正前方约 0.2 m 处点击放置。
3. 观察 `/safety/emergency_stop` 变为 `true`，机器人停下。
4. 右键障碍物 → `Delete`，观察机器人自动恢复巡逻。

## 11. 修改航点的工作流

```
1. 启动 patrol.launch.py 并确保 Nav2 已激活、定位正确
2. 在 RViz 中把鼠标移到候选航点位置，读状态栏的 (x, y)
3. 记下 3~4 个坐标，并确定每个点的朝向 yaw（可用 RViz 的 2D Goal Pose 试探）
4. 编辑 config/patrol_params.yaml 的 waypoint_x / waypoint_y / waypoint_yaw / waypoint_wait
   ★ 四个数组长度必须一致
5. 重启 patrol_node（不需要重新编译）：
   - 方式 A：Ctrl+C 停掉整个 launch，重新 launch
   - 方式 B：只重启任务层
     ros2 lifecycle ... （不适用，本项目非生命周期节点）
     → 推荐方式 A
6. 检查启动日志中的航点列表是否与预期一致
7. 用 /patrol/set_mode {mode: 0} 开始，观察是否正常
```

> **不做动态航点更新的原因**：见 05 文档 §5.3。
> 航点在运行中变化会让状态机语义复杂化，列入 v0.3 Roadmap。

## 12. 常见运行问题排查

### 问题 1：`等待 Nav2 Action Server 'navigate_to_pose' 超时`

| 检查 | 命令 | 处理 |
| --- | --- | --- |
| Nav2 是否启动 | `ros2 node list \| grep bt_navigator` | 未启动 → 检查 launch 是否含 navigation |
| 生命周期是否激活 | `ros2 lifecycle get /bt_navigator` | 非 active → 查看 launch 输出中 lifecycle_manager 的报错 |
| Action 是否注册 | `ros2 action list \| grep navigate_to_pose` | 无 → Nav2 未完整激活 |
| AMCL 是否激活 | `ros2 lifecycle get /amcl` | 非 active → 检查地图文件路径是否存在 |

### 问题 2：`航点参数校验失败：航点参数数组长度不一致`

```bash
ros2 param get /patrol_node waypoint_x
ros2 param get /patrol_node waypoint_y
ros2 param get /patrol_node waypoint_yaw
ros2 param get /patrol_node waypoint_wait
```

四个数组长度必须完全一致。YAML 中漏写一项就会报这个错。

### 问题 3：机器人不动，但状态显示 MOVING

排查顺序（**严格遵守**，从依赖到自研）：

```bash
# 1. Nav2 侧是否正常？（用命令行隔离验证）
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
"{pose: {header: {frame_id: 'map'}, pose: {position: {x: 1.0, y: 0.5}, orientation: {w: 1.0}}}}" --feedback
```

- **走不动** → 问题在 Nav2/定位/TF，不在自研代码。继续查：
  - `ros2 topic hz /scan`（雷达是否在发）
  - `ros2 run tf2_tools view_frames`（TF 是否完整）
  - RViz 中 `/scan` 与地图是否对齐
  - `/cmd_vel` 是否有输出：`ros2 topic echo /cmd_vel`
- **能走** → 问题在自研节点：
  - `ros2 topic echo /patrol/status` 看 `error_code` 与 `mode`
  - patrol_node 日志中是否有"目标已发送"
  - 检查 `action_name` 参数是否为 `navigate_to_pose`

### 问题 4：机器人到达航点但不停留，立刻前往下一个

说明 `waypoint_wait` 配置为 0，或 `wait_start_` 未正确更新。

```bash
ros2 param get /patrol_node waypoint_wait
```

### 问题 5：巡逻完成一轮后不开始第二轮

```bash
ros2 param get /patrol_node loop_count
```

`loop_count=1` 表示只跑一轮。设 `0` 表示无限循环。

### 问题 6：安全标志一直为 true

```bash
ros2 topic echo /safety/nearest_obstacle_distance
```

- 数值长期 < `stop_distance` → 机器人确实贴着障碍物。手动遥控挪开，或用 `2D Pose Estimate` 重新定位。
- 数值为 `0.0` 且不变化 → 未收到有效 `/scan`。检查 `scan_topic` 参数（应为 `scan`，注意不要写成 `/scan` 之外的错误名字）。
- 数值为 `inf` 但标志仍为 true → 可能是残留的 latched 值。重启 safety_guard_node。

### 问题 7：RViz 中看不到航点 Marker

| 检查 | 处理 |
| --- | --- |
| 是否添加了 MarkerArray 显示 | RViz → Add → By topic → `/patrol/markers` → MarkerArray |
| Fixed Frame 是否为 `map` | 左上角 Global Options → Fixed Frame |
| 话题是否有数据 | `ros2 topic echo /patrol/markers --once` |
| QoS 是否匹配 | RViz 的 MarkerArray 显示需设 Durability = Transient Local（本话题是 transient_local） |
| Marker 是否在视野内 | 按 RViz 的 "Zero" 按钮（或键盘 `z`）回到原点视角 |
