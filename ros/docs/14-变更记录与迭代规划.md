### [v0.2.2] — 2026-10-01 — 无界面验收加固与健壮性修复

**修复**（无界面（headless）服务器验收中发现的问题，均已修复并复测）

- `simulation.launch.py` **离线加固**：置空 `GAZEBO_MODEL_DATABASE_URI`，避免 gzserver
  在受限网络下卡在在线模型库（models.gazebosim.org）；修复后本机全链路约 20 s 就绪
- `NavClient` **目标代数（generation）守卫**：`cancel()` / `detach()` 后旧目标的迟到
  响应/反馈/结果一律丢弃，彻底消除"重试读到旧结果"竞态（K-16 强化）
- `NavClient::sendGoal()` 改为**非阻塞**就绪检查（`action_server_is_ready()`）：
  未就绪立即失败并置 `ERR_NAV_SERVER_UNAVAILABLE`，不在 tick 回调内阻塞
  （AS-53 优先；登记豁免 `AS-EXEMPT(AS-60)`，启动期显式等待保留于 `patrol_node`）
- `NavClient::cancel()` 在目标处于终态或从未发送时为空操作，消除 PAUSE/STOP 的噪声取消日志
- 目标被拒（goal_response 返回空句柄）→ `REJECTED` → `ERR_GOAL_REJECTED` + GOAL_FAILED
  （原先错误码 5 无实现路径）
- `PatrolStateMachine` 新增 `resume_state_` 与 `SmCommand.restart_wait`：**等待（WAITING）
  期间**的暂停/安全暂停，恢复后回到 WAITING 并重新计时，不重发目标、不重复计数
  （原先按"走路中暂停"处理，会导致 completed 重复计数）
- `scripts/simtest/cleanup.sh` 排除自身与全部祖先进程：修复 `[.]launch.py` 模式
  误杀同命令行父 shell 的自毁问题

**新增**

- TC-U-04m/n：等待态暂停/恢复、等待态安全暂停/恢复 2 个单元测试 → gtest 用例 34 → **36**

**工程化**

- 三个 `package.xml` 版本号对齐 `0.2.2`，打 tag `v0.2.2`
- 启用 cppcheck 静态检查：环境配置升级 v5，增加
  `AMENT_CPPCHECK_ALLOW_SLOW_VERSIONS=1`（cppcheck 2.7 在本代码库上实测约 1 s 完成、
  0 问题）→ `colcon test-result` 由 `13 skipped` 变为 `0 skipped`

**文档**

| TD-07 | 未做内存泄漏自动化检测 | 测试 | 依赖人工 30 分钟观察 | 引入 ASAN 构建到 CI | 低 |
| TD-08 | 单元测试未覆盖 `NavClient`（依赖 Action 服务端） | 测试 | 该模块只能靠集成测试 | 用 mock action server 测试 | 中 |
| TD-09 | `applyCommand` 存在递归调用 | 代码结构 | 最多 `max_retries` 层，安全但不优雅 | 可改为循环 + 队列 | 低 |
| TD-10 | 无 CI 流水线 | 工程化 | 编译与测试靠手工 | 引入 GitHub Actions（ros-tooling/setup-ros） | 中 |
| TD-11 | 架构适应度函数（16 §15 AF-01 ~ AF-08）尚未脚本化 | 工程化 | 架构约束只能靠人工 Review，会随时间被侵蚀 | 实现 `scripts/arch_check.sh`，与 TD-10 一并接入 CI（v0.2 V2-11） | **高** |

## 8. 代码与文档一致性规则

| CD-01 | 改代码必须同步改文档（04/05/06）；改文档必须同步改代码 |
