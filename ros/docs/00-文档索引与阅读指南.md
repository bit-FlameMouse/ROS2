## 4. 文档约定

1. **编号规则**：
   - 需求类（01 文档）：`FR-xx` = 功能需求，`NFR-xx` = 非功能需求，`AC-xx` = 验收标准；
   - 规范类：`AS-xx` = 架构规范条款（Architecture Specification，见 16 文档），
     `AF-xx` = 架构适应度函数检查项（可自动化执行的架构检查）；
   - 测试类（08 文档）：`TC-U-*` 单元 / `TC-I-*` 集成 / `TC-S-*` 系统 / `TC-P-*` 性能 / `TC-E-*` 编译规范；
   - 记录类：`ADR-xx` 设计决策（02）/ `K-xx` 技术坑、`R-xx` 风险（11）/ `TD-xx` 技术债（14）。
   - **规范条款只增不删**：废弃条款标记 `[DEPRECATED]` 并保留编号，编号不得回收复用。
2. **追溯关系**：每条 FR 在 01 文档末尾的需求追踪矩阵（RTM）中，都能追溯到设计章节与测试用例编号。
3. **设计决策规则**：所有关键选型写入 02 文档的 ADR（Architecture Decision Record）章节，格式为「背景 → 选项 → 决策 → 理由 → 代价」。
4. **代码即文档**：04 文档中的代码清单与仓库 `src/` 目录保持一致；若不一致，视为缺陷，需提 issue 修正。
5. **术语统一**：所有文档使用 15 文档中的术语表，中英混排时首次出现标注英文原文。
6. **变更留痕**：任何文档修改都记录到 14 文档的变更记录中，并同步更新本文档头部的版本号。
7. **规范冲突处理**：16（架构规范）与 07（编码规范）出现冲突时，**以更严格者为准**，并同步在两份文档中互加交叉引用以消除歧义。
8. **局部编号的引用方式**：07 文档中的 `M-xx` / `P-xx` / `C-xx` / `R-xx` / `N-xx` 是**章节内局部编号**（`R-xx` 仅在 07 §8 ROS 2 专项规范中有效），与 11 文档的风险编号 `R-xx` **同名但不同体系**。跨文档引用时必须写全，例如「07 §8 R-04」。
