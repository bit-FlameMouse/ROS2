## 1. 测试环境准备

### 1.1 依赖与构建（一次性）

```bash
source /opt/ros/humble/setup.bash
bash scripts/install_deps.sh          # 安装 Gazebo / TurtleBot3 / Nav2 / SLAM（需要 sudo）
bash scripts/build.sh                 # colcon build（Release + symlink-install）
```

### 1.2 环境变量（每次测试前）

```bash
source /opt/ros/humble/setup.bash
source /usr/share/gazebo/setup.sh
cd <项目根目录> && source install/setup.bash

export TURTLEBOT3_MODEL=burger        # 或缺省由 launch 自动设置
export ROS_DOMAIN_ID=30               # 与其他实验隔离
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp   # 强烈推荐，见 §1.3
```

### 1.3 中间件选择与 `ros2 daemon` 陷阱（本次实测最重要的经验）

| 中间件 | 本机实测表现 |
| --- | --- |
| Fast DDS（默认） | Nav2 生命周期激活极慢（本机 350 s+），偶发 `Failed to change state for node` |
| **CycloneDDS（推荐）** | Nav2 激活约 **4–10 s**，服务/话题稳定 |

> **陷阱**：切换 `RMW_IMPLEMENTATION` 后，如果 `ros2 node list` / `ros2 lifecycle get` 看不到任何
> 节点（返回空），并不是节点没起来，而是常驻的 `ros2 daemon` 还停留在旧中间件上。
>
> **处理**：`ros2 daemon stop`（下一条 CLI 命令会按当前环境自动重建 daemon）。

### 1.4 headless（无 GUI 远程登录）与有 GUI 两种模式

| 场景 | 启动参数 |
| --- | --- |
| 本机/虚拟机有图形界面 | `ros2 launch patrol_robot_bringup patrol.launch.py`（默认 `gui:=true use_rviz:=true`） |
| 远程 SSH 无 X 服务 | `ros2 launch patrol_robot_bringup patrol.launch.py gui:=false use_rviz:=false` |

> 远程无 X 时务必 `unset DISPLAY`（否则 gzserver 会反复尝试连接不存在的 X 服务，
> 终端出现 `xcb_connection_has_error()`，且登录端可能被 X 转发拖住）。
> headless 模式下所有验证都通过话题/服务/日志完成，无需 RViz。

### 1.5 每次测试前后的清理（避免"同名节点 + TF 双发布"污染）

```bash
bash scripts/simtest/cleanup.sh       # 终止 gzserver / Nav2 / slam_toolbox / 任务层等全部相关进程
```

> **为什么必须清理**：上一轮的 gzserver、slam_toolbox、Nav2 容器若残留，会出现
> **同名节点**（服务调用打到旧进程）与 **map→odom 双发布者**（TF 抖动），
> 表现为导航"莫名其妙"失败。本次实测的第一轮排查成本主要来自此。

## 3. 仿真链路（TC-I-01 / TC-I-02）

### 3.1 启动

```bash
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup simulation.launch.py gui:=false   # 有 GUI 时去掉 gui:=false
```

### 3.2 验证点（逐条执行）

```bash
ros2 topic list | grep -E "scan|odom|tf|cmd_vel|clock"
ros2 topic hz /scan          # 期望 5–10 Hz（本机实测 ≈5.0 Hz）
ros2 topic hz /clock         # 期望有稳定输出（本机实测 ≈10 Hz）
ros2 topic hz /odom          # 期望 20–30 Hz（本机实测 ≈28 Hz）
ros2 run tf2_ros tf2_echo odom base_footprint   # 期望持续输出，初始 (-2.00, -0.50, 0.009)
ros2 run tf2_ros tf2_echo base_link base_scan   # 期望固定值（约 z=0.17）
```

### 3.3 遥控链路（TC-I-02）

有 GUI 时：`ros2 run turtlebot3_teleop teleop_keyboard`，按 `w/a/s/d` 观察机器人运动。

无键盘交互环境（脚本等价验证）：直接用速度指令驱动，观察机器人移动与 `/odom` 变化：

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.15}, angular: {z: 0.0}}"      # 前进，Ctrl+C 停止
```

### 4.2 方式 B：自动巡线（headless 可用，本次实测采用）

```bash
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup mapping.launch.py use_rviz:=false gui:=false &
sleep 30
python3 scripts/simtest/drive_perimeter.py     # 原地转 360° + 半径 2.1 m 外环闭环一圈
```

**本次实测结果（2026-09-30）**：13/13 段全部到达；保存地图 112×104 @0.05 m，
origin `[-2.95, -2.58, 0]`，墙体/9 根圆柱/装饰六边形位置与 Gazebo 世界一致，
已作为 `maps/tb3_world.pgm/.yaml` 提交入库。

### 4.3 地图质量检查

| 检查项 | 合格标准 |
| --- | --- |
| 墙体连续 | 六边形轮廓无明显断裂 |
| 圆柱可见 | 中心 3×3 阵列共 9 个障碍斑块 |
| 出生点空闲 | `(-2.0, -0.5)` 处为白色空闲（否则 AMCL 初始位姿需调整） |
| 航点空闲 | `(1.75,0) / (0,1.9) / (-1.75,0)` 均为白色（可用 §6 的检查方法） |

> 用 SLAM 重新采集后请同步更新 `nav2_params.yaml` 中 amcl 的 `initial_pose`
> （应等于 Gazebo 出生点，当前为 `-2.0, -0.5, 0`）。

## 5. 定位（TC-I-04）

```bash
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup navigation.launch.py gui:=false use_rviz:=false &
# 等到 bt_navigator 激活（期望 < 60 s；CycloneDDS 下实测 10 s 内）：
ros2 lifecycle get /bt_navigator              # 期望 active
ros2 run tf2_ros tf2_echo map base_footprint  # 期望 ≈ (-2.00, -0.50)
python3 scripts/simtest/amcl_check.py         # 期望 [PASS] 偏差 < 0.3 m
```

> **注意 /amcl_pose 的 QoS**：其发布端为 `RELIABLE + TRANSIENT_LOCAL`。
> 在 CycloneDDS 下，默认 `VOLATILE` 订阅者**收不到任何消息**（本次实测确认）；
> 订阅 `/amcl_pose` 时必须显式声明 `durability=transient_local`
> （`scripts/simtest/amcl_check.py` 已按此实现）。
>
> `nav2_params.yaml` 中已开启 `amcl.set_initial_pose=true`（初始位姿=出生点），
> 因此一般不需要再手动 `2D Pose Estimate`；若定位漂移，可在 RViz 重新设定。

## 6. 单点导航（TC-I-05）

首选演示航点（外环通道，已用地图校验距障碍 ≥ 0.45 m）：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: 1.75, y: 0.0}, orientation: {w: 1.0}}}}" --feedback
```

或一次跑 5 个目标并统计成功率：

```bash
python3 scripts/simtest/nav_goals.py          # 期望 5/5（目标均可在外环与内环空闲区到达）
```

**本次实测结果（2026-09-30，CycloneDDS）**：

- 演示航点连续 3 个目标：**3/3 到达**（22.4 s / 17.0 s / 17.2 s）。
- ⚠️ 经验：目标点若选在**圆柱阵列内部的窄通道**（间隙仅 0.8 m，膨胀后 ~0.2 m），
  DWB 容易陷入"Failed to make progress"→旋转恢复→碰撞检查退出，最终失败。
  **选点原则**：优先外环通道（离墙与圆柱均 ≥ 0.45 m）。

排障辅助：

```bash
python3 scripts/simtest/watch_cmd_vel.py 20   # 导航时看 /cmd_vel 频率与机器人位置变化
```

> **下发目标的坑**：目标消息 `pose.header.stamp` 必须留空（=0）。
> 若填了系统时间（客户端未启用 use_sim_time），Nav2 会报
> `Transform data too old when converting from map to odom` 并返回空路径。

## 7. 自定义接口与服务（TC-I-06 / TC-I-07 / TC-I-08）

```bash
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup patrol_nodes.launch.py use_sim_time:=false auto_start:=false
```

（`patrol_nodes.launch.py` 不含仿真与 Nav2；单独调试需先启动 `navigation.launch.py`。）

```bash
# TC-I-07 接口字段核对
ros2 interface show patrol_interfaces/msg/PatrolStatus
ros2 interface show patrol_interfaces/srv/SetPatrolMode

# TC-I-06 参数与 Marker
ros2 param get /patrol_node waypoint_x
ros2 topic echo /patrol/status --once          # 默认 1 Hz；total_waypoints=3
ros2 topic echo /patrol/markers --once         # 1 个 DELETEALL + 3 球 + 3 标签

# TC-I-08 五种模式（预期响应）
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"  # START  → success=True current_mode=1
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"  # 再次 START → NO_STATE_CHANGE
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 1}"  # PAUSE  → current_mode=3
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 2}"  # RESUME → current_mode=1
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 3}"  # STOP   → current_mode=0
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 4}"  # RESET  → OK
```

（以上交互也已用 mock Nav2 Action Server 在无仿真环境验证，21/21 断言通过。）

## 8. 自动巡逻与可视化（TC-S-01 / TC-S-02 / TC-S-03）

### 8.1 一键启动与开跑

```bash
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup patrol.launch.py gui:=false use_rviz:=false \
  patrol_params:=<绝对路径>/patrol_params.yaml
# 等 Nav2 激活 + 任务层延迟 8 s 启动后：
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"
ros2 topic echo /patrol/status            # 观察 mode/index/completed/distance_remaining
```

**TC-S-01 判定**：3 航点 × 2 轮（把 `loop_count` 设为 2）全程无人工干预，
`completed_waypoints` 累计到 6，随后回 IDLE，日志出现"巡逻任务全部完成"。
日志中每个航点的"前往航点 [i]"与状态迁移成对出现（见任务层终端输出）。

### 8.2 模式控制（TC-S-02）

| 操作 | 命令 | 预期 |
| --- | --- | --- |
| 暂停 | `"{mode: 1}"` | 机器人停车（`/cmd_vel` 归零），`mode=3`，`current_waypoint_index` 不变 |
| 继续 | `"{mode: 2}"` | 从同一航点重新发起导航，`mode=1` |
| 停止 | `"{mode: 3}"` | `mode=0`，索引归零 |
| 重新开始 | `"{mode: 0}"` | 从航点 0 开始 |

### 8.3 航点可视化（TC-S-03）

有 GUI 时：RViz 中添加 MarkerArray（Topic `/patrol/markers`，
**Durability 需设为 Transient Local**，见 09 文档 §12 问题 7）。

headless 验证（等价断言）：

```bash
ros2 topic echo /patrol/markers --once
```

- 巡逻中：当前目标球体颜色 `(1.0, 0.85, 0.0)` 黄，已完成 `(0.2, 0.85, 0.3)` 绿，未访问 `(0.6, 0.6, 0.6)` 灰；
- 全部完成后：所有球体为绿（本次实现会在"跑完全部循环回 IDLE"时全绿）。

## 9. 安全守护（TC-S-04）

### 9.1 方式 A：Gazebo GUI `Insert`（有界面时最直观）

在机器人正前方约 0.2–0.25 m 插入 Box → 观察 `/safety/emergency_stop` 变 `true`、
`/patrol/status` 的 `mode` 变 `4`（SAFETY_HOLD）、机器人停车；右键删除 Box 后自动恢复。

### 9.2 方式 B：命令行插障碍物（headless 推荐）

```bash
# 1) 生成一个小方块模型文件
cat > /tmp/safety_box.sdf <<'EOF'
<sdf version="1.6">
  <model name="safety_box">
    <static>true</static>
    <link name="link">
      <collision name="collision">
        <geometry><box><size>0.2 0.2 0.4</size></box></geometry>
      </collision>
      <visual name="visual">
        <geometry><box><size>0.2 0.2 0.4</size></box></geometry>
      </visual>
    </link>
  </model>
</sdf>
EOF

# 2) 计算"正前方 0.25 m"的坐标（脚本会直接给出可复制的插入命令）
python3 scripts/simtest/front_point.py 0.25

# 3) 用脚本输出的命令插入（示例坐标以实际输出为准）
ros2 run gazebo_ros spawn_entity.py -entity safety_box -file /tmp/safety_box.sdf -x 1.45 -y 0.30 -z 0.2

# 4) 观察
ros2 topic echo /safety/emergency_stop      # 期望 true（置位后锁存，晚订阅也能收到）
ros2 topic echo /patrol/status              # 期望 mode=4 SAFETY_HOLD，机器人停止

# 5) 删除障碍物并确认恢复
ros2 service call /delete_entity gazebo_msgs/srv/DeleteEntity "{name: safety_box}"
ros2 topic echo /safety/emergency_stop      # 期望 false
ros2 topic echo /patrol/status              # 期望回到 mode=1（从当前航点自动继续）
```

安全节点终端日志应出现成对记录：
`前方障碍过近（0.xx m < 0.30 m），置位紧急标志` / `前方畅通（x.xx m > 0.60 m），解除紧急标志`。

### 9.3 方式 C：无仿真的逻辑验证（等价于 09 文档 §8.2）

```bash
ros2 topic pub --once /safety/emergency_stop std_msgs/msg/Bool "{data: true}"   # 期望 → SAFETY_HOLD(4)
ros2 topic pub --once /safety/emergency_stop std_msgs/msg/Bool "{data: false}"  # 期望 → MOVING(1)
```

> 单节点验证（不启动仿真）：`ros2 run patrol_robot_core safety_guard_node`
> + 假激光话题；或直接观察参数校验：`stop_distance=0.8, resume_distance=0.6` 时
> 节点应 `FATAL` 退出且退出码非 0（`bash scripts/arch_check.sh` 的 AF-09 会自动检查）。

## 10. 失败重试与跳过（TC-S-05）

1. 复制 `config/patrol_params.yaml` 为 `/tmp/patrol_retry.yaml`，把其中一个航点改到墙体内
   （例如 `waypoint_y` 的 W1 改为 `-2.80`，该点在墙体环内，不可达）；
2. 设 `max_retries: 2`、`skip_failed_waypoint: true`、`waypoint_timeout_sec: 20`；
3. 启动并开始巡逻：

```bash
ros2 launch patrol_robot_bringup patrol.launch.py gui:=false use_rviz:=false patrol_params:=/tmp/patrol_retry.yaml
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"
ros2 topic echo /patrol/status
```

**预期**：该航点失败 → WARN 日志"航点导航超时/按失败处理"→ 重试（`retry_count` 增至 1）→
重试超限后跳过（`current_waypoint_index` +1，任务继续，不进入 FAILED）。

## 13. 常见问题速查（本次实测踩坑汇总）

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | `ros2 node list` / `ros2 lifecycle get` 空结果 | `ros2 daemon` 与当前 RMW 不一致 | `ros2 daemon stop` 后重试 |
| 2 | Nav2 激活要几分钟、偶发 `Failed to change state` | Fast DDS 在多节点下的发现/心跳开销 | 使用 `RMW_IMPLEMENTATION=rmw_cyclonedds_cpp` |
| 3 | 终端刷 `xcb_connection_has_error()` | 远程无 X 服务但 DISPLAY 指向 X | `unset DISPLAY`；launch 加 `gui:=false use_rviz:=false` |
| 4 | 目标下发后不动、日志 `Transform data too old ...` | 目标 `stamp` 填了系统时间 | 目标 `stamp` 留空（=0） |
| 5 | `/amcl_pose` 收不到（CycloneDDS） | 发布端 Durability=TRANSIENT_LOCAL，订阅端默认 VOLATILE | 订阅端声明 `durability=transient_local`（RViz MarkerArray 同理） |
| 6 | 导航中途 `Failed to make progress` | 目标点选在圆柱阵列内部窄通道 | 目标点选外环通道（距障碍 ≥ 0.45 m） |
| 7 | 机器人乱跳/导航莫名失败 | 上一轮残留进程导致同名节点、map→odom 双发布 | `bash scripts/simtest/cleanup.sh` |
| 8 | SLAM 地图右端顶点外侧有小缺口 | SLAM 图幅边界（不影响可通行区域） | 正常现象；如需完整边界可用 `scripts/generate_map_from_world.py` 重建 |
| 9 | Ctrl+C 后仍有 gzserver/Nav2 残留 | launch 子进程未全部回收 | 再次执行 `scripts/simtest/cleanup.sh` |
