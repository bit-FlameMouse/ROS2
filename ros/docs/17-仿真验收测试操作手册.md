## 0. 先看这里：30 秒了解任务，3 分钟选定路线

### 0.1 这个项目是干什么的？

想象一个**遥控玩具车 + 扫地机器人**的结合体：

- 它在一个 3D 仿真场地里（像游戏地图）跑；
- 它能**自己画地图**（边走边记录哪里有墙）；
- 它能**知道自己站在哪**；
- 你告诉它几个"停车点"，它能**自己排队跑圈**；
- 它前面突然出现障碍物，它会**急刹车**，障碍物拿开又会**自动继续**。

这个"玩具"由电脑里的 5 个部分组成：**仿真场地**（Gazebo）、**地图与定位**、**导航系统**（Nav2）、**巡逻指挥中心**（我们自己写的 `patrol_node`）、**安全员**（我们自己写的 `safety_guard_node`）。

本手册就是带你**亲手把上面每一句话验证一遍**。

### 0.2 三条测试路线（按你的时间选）

| 路线 | 适合谁 | 做哪几关 | 预计耗时 |
| --- | --- | --- | --- |
| **A 快速体检** | 只想确认"能用" | 第 1、2、4、5、7 关 | 约 30 分钟 |
| **B 完整验收** | 要交作业/验收，需要逐项打勾 | 第 1 ~ 11 关全部 | 2 ~ 3 小时 |
| **C 演示前准备** | 马上要给别人演示 | 第 15 章"演示前 15 分钟检查" | 15 分钟 |

> 每关都有：**在测什么 → 怎么做 → 通过标志 → 失败怎么办**。
> 建议边做边在本手册 §14 的登记表里打勾（最终要抄进 08 文档存档）。

### 0.3 本机约定（先知道这两件事）

1. **项目放在哪**：本机路径是 `/home/lich/ROS2/ros`
   （里面能看到 `src/`、`scripts/`、`docs/`、`README.md` 这些文件夹/文件）。
   下文所有命令都假设你**已经在这个目录里**。
2. **有没有图形界面**：远程 SSH 登录、没有桌面的情况，命令里要带
   `gui:=false use_rviz:=false`（意思是"不弹 3D 窗口、不弹仪表盘"，只用文字和数字验证）。
   如果你自己电脑上有桌面，把这两个选项**删掉**即可看到完整画面。

## 1. 开工前先认识 10 个词（用生活里的事打比方）

| 词 | 打个比方 | 在本项目里指的是 |
| --- | --- | --- |
| **终端** | 一个"用打字下命令"的操作台 | 你接下来所有操作都在这里完成 |
| **命令** | 对着操作台说的一句话，回车执行 | 手册里灰底代码块中的每一行 |
| **节点** | 一个会干活的小机器人程序 | 整个系统由十几个"节点"组成，各干各的 |
| **话题（topic）** | 一个广播频道，谁都能听 | 比如 `/scan` 频道上，雷达不停"喊"它看到的距离 |
| **服务（service）** | 点单窗口：你问一句，它答一句 | 比如"开始巡逻"就是给指挥中心发一条服务请求 |
| **动作（Action）** | 派一个长活儿，中途还能看进度、能喊停 | "走到某个点"就是给导航系统派一个动作 |
| **TF / 坐标系** | 换算表：A 物体相对于 B 物体在哪 | 让"地图坐标"和"机器人自己的坐标"能对上 |
| **建图（SLAM）** | 蒙着眼睛在房间里边走边画平面图 | 机器人边走边把墙的位置画成一张"格子地图" |
| **定位（AMCL）** | 看着地图问"我现在在图上的哪个点" | 让机器人知道自己在地图里的精确位置 |
| **QoS** | 邮局的投递规则（挂号信 by 平信） | 决定消息"丢了要不要重发、晚来的人能不能补看" |

还有两个名字会经常出现：

- **Gazebo**：3D 仿真场地软件（我们的"游戏世界"）。
- **RViz**：3D 仪表盘软件（有桌面时用来看地图、看机器人、看路线）。

> 记不住没关系，用到哪条回来查哪条，本手册 §16 还有一份速查表。

## 2. 开始前的一次性准备（约 10 分钟）

### 2.1 认识终端窗口

1. **打开终端**：
   - 有桌面的 Ubuntu：按 `Ctrl` + `Alt` + `T`；
   - 远程 SSH：你登录后看到的黑底/白底文字框就是终端。
2. **复制粘贴**（终端里和别处不一样）：
   - 复制：`Ctrl` + `Shift` + `C`；
   - 粘贴：`Ctrl` + `Shift` + `V`；
   - 也可以直接用鼠标右键菜单。
3. **停止正在运行的程序**：在终端里按 `Ctrl` + `C`。
   命令跑不完、想中断、演示结束，都按它。
4. **可以同时开多个终端窗口**：后面有的步骤需要"一个窗口开着机器人，另一个窗口观察数据"。
   每个新窗口都要先做 §2.2 的准备（做完 §2.2 后就不用管了，新窗口自动就绪）。

### 2.2 让每个终端自动"准备就绪"（强烈建议做一次）

> **这句话在干什么**：ROS 2 运行需要一个"环境配置"，不配置的话系统会不认识 `ros2` 命令、
> 也找不到我们的项目。把配置写进 `~/.bashrc`（每开一个新终端都会自动执行的个人配置文件），
> 以后就不用每次敲了。

复制下面整段，粘贴到终端执行（只在第一次做；脚本里已加防重复判断）：

```bash
grep -q "patrol-robot-sim 环境" ~/.bashrc || cat >> ~/.bashrc <<'EOF'
# ===== patrol-robot-sim 环境（由 docs/17 手册添加）=====
export PROJECT_ROOT=/home/lich/ROS2/ros
source /opt/ros/humble/setup.bash
source /usr/share/gazebo/setup.sh 2>/dev/null
[ -f "$PROJECT_ROOT/install/setup.bash" ] && source "$PROJECT_ROOT/install/setup.bash"
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
# 本机没有 3D 桌面，所以取消 DISPLAY（有桌面的电脑请删除下面这一行）
unset DISPLAY
EOF
source ~/.bashrc
```

做完后**验证一下**：

```bash
cd /home/lich/ROS2/ros
pwd
```

- `pwd` 这句话在干什么：问系统"我现在在哪个文件夹"。
- 应该看到：`/home/lich/ROS2/ros`。不是的话，就把 `cd /home/lich/ROS2/ros` 再执行一遍。

> 如果你的项目放在别的位置，把上面两处的 `/home/lich/ROS2/ros` 换成你的实际路径。

### 2.3 第一次编译：把代码变成能运行的程序

> **这句话在干什么**：我们拿到的是一堆"源代码"（给程序员看的文字），电脑不能直接跑。
> "编译"就是把它翻译成电脑能执行的程序，类似把菜谱做成菜。

```bash
cd /home/lich/ROS2/ros
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
```

- 应该看到最后一行类似：`Summary: 3 packages finished [...]`。
- **第一次比较慢（1~2 分钟）正常**；以后再编译只要几秒。
- 如果看到红色的 `error`，先跳到 §15 查现象，不要继续往下做。

编译成功后，让当前终端也能用上新程序：

```bash
source install/setup.bash
```

### 2.4 认识 4 个常用"开关"（launch 参数）

启动命令后面可以加"开关"，格式是 `名字:=值`。常用的就 4 个：

| 开关 | 作用 | 什么时候用 |
| --- | --- | --- |
| `gui:=false` | 不打开 Gazebo 3D 画面 | 无桌面/远程时用（省资源） |
| `use_rviz:=false` | 不打开 RViz 仪表盘 | 无桌面/远程时用 |
| `auto_start:=true` | 启动后立刻开始巡逻，不等你发令 | 想省事时用 |
| `patrol_params:=/路径/xx.yaml` | 换一份"巡逻设置文件"（航点、超时等） | 测试重试/自定义航点时用 |

> 有桌面时什么都不用加，直接启动就是完整画面（默认 `gui:=true use_rviz:=true`）。

## 3. 第 1 关：代码体检（编译 + 单元测试）

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-E-01/02/03、TC-U-01~06 |
| 前置 | §2.3 编译成功 |
| 耗时 | 约 3 分钟 |
| 这一关在测什么 | 程序能不能零警告编译；99 项自动检查（含 34 个"迷你测试"）能不能全过 |

> 什么是"单元测试"？把程序里每个小零件单独拿出来按按钮，看它反应对不对。
> 比如"安全员算法"：给一个 0.2 米远的障碍物，它必须说"危险"；给 0.8 米，必须说"安全"。

**第 1 步：** 跑测试

```bash
cd /home/lich/ROS2/ros
colcon test --packages-select patrol_interfaces patrol_robot_core patrol_robot_bringup
```

> 这句话在干什么：让系统自动跑一遍全部迷你测试。

**第 2 步：** 看成绩单

```bash
colcon test-result --all
```

> 这句话在干什么：把测试结果汇总成一张表，重点是最后一行。

**✅ 通过标志**：最后一行是 `Summary: 99 tests, 0 errors, 0 failures`
（个别条目显示 `13 skipped` 是正常的：那是"环境里缺一个可选检查工具"而自动跳过的，
不算失败）。

**❌ 失败怎么办**：把这一行连同上面几行红字复制到记事本，对照 §15；绝大多数是"没有先执行
§2.3 编译"或"没有 source 环境"。

**📝 登记**：在 §14 表格第 1 行打勾。

## 4. 第 2 关：让机器人"活过来"（仿真世界）

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-I-01、TC-I-02 |
| 前置 | 第 1 关通过 |
| 耗时 | 约 5 分钟 |
| 这一关在测什么 | 3D 世界里能不能出现一台带雷达的机器人，雷达/时钟/里程计数据正常 |

### 4.1 启动仿真（这个命令会一直运行，别关掉）

```bash
bash scripts/simtest/cleanup.sh      # 先打扫干净，防止上次没关的程序捣乱
ros2 launch patrol_robot_bringup simulation.launch.py gui:=false
```

- **第一句**：把上次遗留在后台的旧程序全部关掉（就像上台前清场）。
  看到 `环境已清理（无残留进程）` 就放心了。
- **第二句**：启动仿真。它会**一直运行不退出**，占用当前终端 —— 这是正常的。
  想结束它就按 `Ctrl` + `C`（或另开终端跑 `cleanup.sh`）。
- 启动需要 **20~40 秒**，期间会刷很多文字，**不要慌**，等它稳定下来。

> 用 `linux` 术语说，这就是"打开了一个叫仿真世界的程序"。它内部会自己启动：
> 物理引擎（算碰撞）、机器人模型、雷达传感器、时钟等。

### 4.2 另开一个终端，开始体检

新开一个终端（§2.2 做完后新终端自动就绪），逐条执行。每条命令都告诉你在问什么：

```bash
cd /home/lich/ROS2/ros
```

**检查 1：都有哪些"频道"在广播？**

```bash
ros2 topic list
```

> 在干什么：列出系统里所有正在广播的话题频道。
> 应该看到 `/scan`（雷达）、`/odom`（里程计）、`/tf`（坐标换算）、`/clock`（仿真时钟）等。

**检查 2：雷达每秒发多少次数据？**

```bash
ros2 topic hz /scan
```

> 在干什么：统计 `/scan` 频道每秒来几条件，像数水龙头滴几滴水。
> 应该看到：`average rate: 5.0` 左右（3~10 之间都算正常）。
> 按 `Ctrl` + `C` 结束这条命令。

**检查 3：仿真时钟在不在走？**

```bash
ros2 topic hz /clock
```

> 在干什么：仿真世界有它自己的"时间"，这条命令确认它一直在走。
> 应该看到：`average rate: 10.0` 左右。如果完全没有输出，说明仿真没起来。

**检查 4：机器人"腿动没动"的数据源正常吗？**

```bash
ros2 topic hz /odom
```

> 在干什么：`/odom` 是机器人自己的"我移动了多少"记录，导航全靠它。
> 应该看到：约 28 次/秒。

**检查 5：机器人身体的各个部位"拼装"正确吗？**

```bash
ros2 run tf2_ros tf2_echo odom base_footprint
```

> 在干什么：`tf2_echo` 是"坐标换算查询器"。这句话在问："机器人身体（base_footprint）
> 相对于它的出发点（odom）在哪里？"
> 应该看到：类似 `Translation: [-2.000, -0.500, 0.009]` 的一行（数字含义：x=-2 米、y=-0.5 米）。
> 按 `Ctrl` + `C` 结束。

**检查 6（可选）：让机器人动一下**

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.15}, angular: {z: 0.0}}"
```

> 在干什么：往"速度指令"频道按每秒 10 次的频率发送"往前走"。
> 机器人应该在仿真里向前移动（无画面时看下一句）。
> 按 `Ctrl` + `C` 让它停下（发送停止指令也可以：`ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"`）。

再运行一次 `ros2 run tf2_ros tf2_echo odom base_footprint`，应该看到 x 坐标比刚才大了。

**✅ 通过标志**：前 5 项检查里 `/scan` 约 5 次/秒、`/clock` 约 10 次/秒、`/odom` 约 28 次/秒，
坐标查询有数字输出。

**📝 结束时**：回到第一个终端按 `Ctrl` + `C`，或者在新终端执行 `bash scripts/simtest/cleanup.sh`。

## 5. 第 3 关：让机器人画地图（SLAM 建图）

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-I-03 |
| 前置 | 第 2 关通过 |
| 耗时 | 约 5 分钟（含 3 分钟自动巡线） |
| 这一关在测什么 | 机器人能不能一边走一边把房间的墙、柱子画成地图文件 |

> 打比方：蒙着眼睛在房间里走，边走边用手摸墙，最后在纸上画出一张平面图。

### 5.1 启动"边跑边画图"模式

```bash
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup mapping.launch.py gui:=false use_rviz:=false
```

> 这条命令启动了：仿真世界 + 画图程序（SLAM Toolbox）。
> 同样会一直运行，先放着别动。

**另开终端**，等约 30 秒后执行：

```bash
cd /home/lich/ROS2/ros
python3 scripts/simtest/drive_perimeter.py
```

> 这句话在干什么：请一个"代驾脚本"帮机器人走一圈 ——
> 先原地转 360°（把四周都扫一遍），再沿着房间外圈走 12 段路回到起点。
> 走完会打印 `路径完成: 13/13 段`。
> 全程约 3 分钟，你能看到一行行"航点 x/12 到达"，**这是正常现象**。

### 5.2 把地图保存成文件

**在当前终端**（就是刚跑完巡线脚本的那个）执行：

```bash
ros2 run nav2_map_server map_saver_cli -f /tmp/my_map
```

> 这句话在干什么：把机器人刚画好的地图"拍照存盘"，
> 存成两个文件：`/tmp/my_map.pgm`（图）和 `/tmp/my_map.yaml`（说明：分辨率、原点等）。
> 应该看到：`Map saved successfully`。

### 5.3 检查地图质量（可选，用一条命令看一眼大小）

```bash
ls -lh /tmp/my_map.pgm
```

> 应该看到文件大小在 10~300 KB 之间（太小说明地图几乎是空的）。

**✅ 通过标志**：`路径完成: 13/13 段` + `Map saved successfully`。

> 说明：仓库里已经带了一张实测地图（`src/patrol_robot_bringup/maps/tb3_world.pgm`），
> 所以即使不重新画图，后面的关卡也能直接跑。你刚画的是"自己动手版"，供对比。

**🔎 如果自动巡线没走完**（比如打印"超时"）：多半是仿真启动还不够稳定，
执行 `bash scripts/simtest/cleanup.sh` 全部重来一次即可。

**📝 结束**：`Ctrl` + `C` 停掉第一个终端，或 `bash scripts/simtest/cleanup.sh`。

## 6. 第 4 关：让机器人知道"我在哪"（定位）

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-I-04 |
| 前置 | 第 2 关通过；仓库自带地图存在 |
| 耗时 | 约 5 分钟 |
| 这一关在测什么 | 机器人看着地图，能不能算出自己在地图上的精确位置（误差 < 0.3 米） |

> 打比方：拿着商场平面图站在门口问自己"我现在在图上的哪个位置"——
> 机器人用雷达看到的墙的位置，去和地图里的墙对齐，从而找到自己。

### 6.1 启动"导航总系统"

```bash
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup navigation.launch.py gui:=false use_rviz:=false
```

> 这条命令启动了：仿真世界 + 导航系统（Nav2，含定位、规划、控制等一堆小节点）。
> 启动需要 10~60 秒（本机实测约 10 秒）。

**另开终端**，做两个检查：

**检查 1：导航系统的"大脑"睡醒了吗？**

```bash
cd /home/lich/ROS2/ros
ros2 lifecycle get /bt_navigator
```

> 在干什么：问导航大脑当前的状态。
> 应该看到：`active [3]`（意思是"已激活、在岗"）。
> 如果看到 `unconfigured` / `inactive`，等 10 秒再问一次；一直是别的状态就看 §15。

**检查 2：机器人算出来的位置准不准？**

```bash
python3 scripts/simtest/amcl_check.py
```

> 在干什么：把机器人"自己以为的位置"和"仿真里的真实位置"做对比，算误差。
> 应该看到：`[PASS] AMCL 位姿偏差 = 0.0xx m（阈值 0.3 m，样本 20）`。

> **为什么不用手动校准？** 启动文件里已经把"出生点坐标（-2.0, -0.5）"告诉了定位程序；
> 如果你在有画面的电脑上做，也可以用 RViz 顶部的 `2D Pose Estimate` 按钮重新校准。

**✅ 通过标志**：`active [3]` + `[PASS] ... < 0.3 m`。

**📝 结束**：`bash scripts/simtest/cleanup.sh`。

```bash
# ① 开始巡逻（回复 success=True，current_mode=1 表示"MOVING 正在走"）
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"

ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"

# ③ 暂停（回复 current_mode=3 "PAUSED 已暂停"，机器人就地停车，但记住当前走到第几个点）
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 1}"

# ④ 继续（回复 current_mode=1，从刚才那个点接着走）
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 2}"

```

> **什么是"幂等"**：像电梯按钮，电梯已经在上去时你再按一下，它不会"重新再上去一次"，
> 只会告诉你"不用重复"。②就是验证这个。

## 13. 第 11 关：性能与"连续跑 30 分钟"

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-P-01/02/03、TC-S-06 |
| 前置 | 第 9 关通过 |
| 耗时 | 快测 5 分钟；长稳测试 30 分钟 |
| 这一关在测什么 | 状态报告频率是否达标；两个自研节点吃多少 CPU/内存；长时间跑会不会崩 |

### 13.1 频率与延迟（TC-P-01）

```bash
ros2 topic hz /patrol/status        # 应该 ≈1.0 次/秒（0.9~1.1 都算过）
ros2 topic delay /patrol/status     # 应该小于 200 毫秒（0.2 秒）
```

> `hz` 量"多久发一次"，`delay` 量"消息从产生到你收到过了多久"（像查快递时效）。

### 13.2 两个自研节点吃多少资源（TC-P-02）

```bash
top -p $(pgrep -d, -f patrol_node)          # 看"指挥中心"的 CPU/内存，按 q 退出
ps -o rss= -p $(pgrep -f patrol_node) $(pgrep -f safety_guard_node)
```

> 在干什么：`top` 像任务管理器，看这个程序占多少 CPU；`ps` 报它的内存占用（单位 KB）。
> 判定标准：CPU 低于 5%（单个核心的 5%）；两个程序内存加起来增加不超过 50 MB（≈51200 KB）。

### 13.3 启动要多久（TC-P-03）

> 从执行 `ros2 launch patrol.launch.py ...` 那一刻起，到
> `ros2 service call /patrol/set_mode ...` 能成功应答为止，应小于 60 秒。
> 本机实测：CycloneDDS 下约 10 秒。

### 13.4 连续跑 30 分钟（TC-S-06）

1. 用默认设置（无限循环）启动：`ros2 launch patrol_robot_bringup patrol.launch.py gui:=false use_rviz:=false`
2. 开始巡逻，然后**放着不管**；
3. 每 5 分钟执行一次下面这条，把数字抄进表格：

```bash
ps -o rss= -p $(pgrep -f patrol_node)
```

| 时间点 | 内存 KB | 备注 |
| --- | --- | --- |
| 0 分钟 | | |
| 5 分钟 | | |
| 10 分钟 | | |
| 15 分钟 | | |
| 20 分钟 | | |
| 25 分钟 | | |
| 30 分钟 | | |

> 判定：30 分钟内程序不崩；内存数字有波动但**没有持续上涨**的趋势
> （比如一直在 20000 → 21000 → 22000 → … 就不对）；`ros2 topic echo /patrol/status`
> 一直在更新。

## 15. 出问题了先看这里（按"我看到了什么"来找）

### 15.1 通用排查三步

1. **看最后 5 行红字**：错误信息里通常有一个关键词（比如 `not found`、`No such file`、`Timed out`），
   先拿关键词对照下表；
2. **重来一遍**：`bash scripts/simtest/cleanup.sh`，然后完全按照手册的命令再走一次
   （80% 的问题来自"上次没关干净"或"漏了 source"）；
3. **还不行**：把**你执行的命令 + 完整报错**复制给我/发给管理员，并说明做到第几关。

### 15.2 现象对照表

| 你看到的现象 | 大概原因 | 一句话解决 |
| --- | --- | --- |
| `ros2: command not found`（找不到 ros2） | 终端没有加载 ROS 环境 | 执行 §2.2，然后新开一个终端 |
| `bash: scripts/simtest/cleanup.sh: No such file or directory` | 当前文件夹不是项目根目录 | `cd /home/lich/ROS2/ros` 再执行 |
| `source: install/setup.bash: No such file` | 还没编译，或不在项目根目录 | 先做 §2.3 编译 |
| `ros2 node list` 什么都不显示 | 命令行"小助手"还记着旧配置 | `ros2 daemon stop`，几秒后重试 |
| 导航大脑一直是 `unconfigured`，启动很慢、日志里反复 `Failed to change state` | 通信中间件选得不对（Fast DDS 在本机很慢） | 确认 `export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`（§2.2 已加），重来 |
| 终端刷 `xcb_connection_has_error()` | 远程没有 3D 桌面，但程序试图连它 | `unset DISPLAY`（§2.2 已加）；启动加 `gui:=false` |
| Nav2 启动了但机器人不动；`/patrol/status` 报 error_code=3 | 目标点太难走（柱子缝里） | 换外圈的目标点（§7.2） |
| `/amcl_pose` 没有数据 | 这个频道的"邮局规则"需要订"挂号信" | 用 `scripts/simtest/amcl_check.py`（它已按规则订阅）；RViz 里看的话把 Durability 设为 Transient Local |
| `ros2 topic pub` 后机器人不动 | 仿真没启动 / 话题名不对 | 回到第 2 关先验证 `/scan` 有数据 |
| 放箱子后不刹车 | 箱子放太远（超过 0.3 米） | 用 `front_point.py 0.25` 重新算坐标 |
| `spawn_entity.py` 报 `Service /spawn_entity unavailable` | 仿真世界没在运行 | 先启动仿真再做第 9 关 |
| 机器人"哆嗦"、走走停停 | 上次的旧程序还在抢控制权 | `bash scripts/simtest/cleanup.sh` 清场重来 |
| 每次都要重新 source，很烦 | 没做 §2.2 | 做一次 §2.2，以后新终端自动就绪 |

### 16.1 名词速查（一句话版）

终端=打字操作台；命令=一句话；节点=小机器人程序；话题=广播频道；服务=点单窗口；
