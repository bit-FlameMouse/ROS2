## 0. 先看这里：30 秒了解任务，3 分钟选定路线

### 0.1 这个项目是干什么的？

想象一个**遥控玩具车 + 扫地机器人**的结合体：

- 它在一个 3D 仿真场地里（像游戏地图）跑；
- 它能**自己画地图**（边走边记录哪里有墙）；
- 它能**知道自己站在哪**；
- 你告诉它几个"停车点"，它能**自己排队跑圈**；
- 它前面突然出现障碍物，它会**急刹车**，障碍物拿开又会**自动继续**。

这个"玩具"由电脑里的 5 个部分组成：**仿真场地**（Gazebo）、**地图与定位**、**导航系统**（Nav2）、**巡逻指挥中心**（我们自己写的 `patrol_node`）、**安全员**（我们自己写的 `safety_guard_node`）。

本手册就是带你**亲手把上面每一句话验证一遍**。

### 0.2 三条测试路线（按你的时间选）

| 路线 | 适合谁 | 做哪几关 | 预计耗时 |
| --- | --- | --- | --- |
| **A 快速体检** | 只想确认"能用" | 第 1、2、4、5、7 关 | 约 30 分钟 |
| **B 完整验收** | 要交作业/验收，需要逐项打勾 | 第 1 ~ 11 关全部 | 2 ~ 3 小时 |
| **C 演示前准备** | 马上要给别人演示 | 第 15 章"演示前 15 分钟检查" | 15 分钟 |

> **有界面的电脑**（本机桌面 / 带桌面的虚拟机 / VNC 远程桌面）做测试最直观：
> 屏幕上能同时看到 3D 场地（Gazebo）和仪表盘（RViz），
> 手册里标了 **🖥 有界面时你能看到** 的段落就是给这种环境准备的。

> 每关都有：**在测什么 → 怎么做 → 通过标志 → 失败怎么办**。
> 建议边做边在本手册 §14 的登记表里打勾（最终要抄进 08 文档存档）。

   （里面能看到 `src/`、`scripts/`、`docs/`、`README.md` 这些文件夹/文件）。
   下文所有命令都假设你**已经在这个目录里**。

## 1. 开工前先认识 10 个词（用生活里的事打比方）

| 词 | 打个比方 | 在本项目里指的是 |
| --- | --- | --- |
| **终端** | 一个"用打字下命令"的操作台 | 你接下来所有操作都在这里完成 |
| **命令** | 对着操作台说的一句话，回车执行 | 手册里灰底代码块中的每一行 |
| **节点** | 一个会干活的小机器人程序 | 整个系统由十几个"节点"组成，各干各的 |
| **话题（topic）** | 一个广播频道，谁都能听 | 比如 `/scan` 频道上，雷达不停"喊"它看到的距离 |
| **服务（service）** | 点单窗口：你问一句，它答一句 | 比如"开始巡逻"就是给指挥中心发一条服务请求 |
| **动作（Action）** | 派一个长活儿，中途还能看进度、能喊停 | "走到某个点"就是给导航系统派一个动作 |
| **TF / 坐标系** | 换算表：A 物体相对于 B 物体在哪 | 让"地图坐标"和"机器人自己的坐标"能对上 |
| **建图（SLAM）** | 蒙着眼睛在房间里边走边画平面图 | 机器人边走边把墙的位置画成一张"格子地图" |
| **定位（AMCL）** | 看着地图问"我现在在图上的哪个点" | 让机器人知道自己在地图里的精确位置 |
| **QoS** | 邮局的投递规则（挂号信 by 平信） | 决定消息"丢了要不要重发、晚来的人能不能补看" |

还有两个名字会经常出现：

- **Gazebo**：3D 仿真场地软件（我们的"游戏世界"）。
- **RViz**：3D 仪表盘软件（有桌面时用来看地图、看机器人、看路线）。

> 记不住没关系，用到哪条回来查哪条，本手册 §16 还有一份速查表。

## 2. 开始前的一次性准备（约 10 分钟）

### 2.1 认识终端窗口

1. **打开终端**：
   - 有桌面的 Ubuntu：按 `Ctrl` + `Alt` + `T`；
   - 远程 SSH：你登录后看到的黑底/白底文字框就是终端。
2. **复制粘贴**（终端里和别处不一样）：
   - 复制：`Ctrl` + `Shift` + `C`；
   - 粘贴：`Ctrl` + `Shift` + `V`；
   - 也可以直接用鼠标右键菜单。
3. **停止正在运行的程序**：在终端里按 `Ctrl` + `C`。
   命令跑不完、想中断、演示结束，都按它。
4. **可以同时开多个终端窗口**：后面有的步骤需要"一个窗口开着机器人，另一个窗口观察数据"。
   每个新窗口都要先做 §2.2 的准备（做完 §2.2 后就不用管了，新窗口自动就绪）。

### 2.2 让每个终端自动"准备就绪"（强烈建议做一次）

> **这句话在干什么**：ROS 2 运行需要一个"环境配置"，不配置的话系统会不认识 `ros2` 命令、
> 也找不到我们的项目。把配置写进 `~/.bashrc`（每开一个新终端都会自动执行的个人配置文件），
> 以后就不用每次敲了。

复制下面整段，粘贴到终端执行（只在第一次做；脚本已做防重复处理）：

```bash
# 1) 清理可能存在的旧版本配置（没有旧配置也不报错）
sed -i '/# ===== patrol-robot-sim 环境/,/^unset DISPLAY$/d' ~/.bashrc 2>/dev/null || true

# 2) 写入新配置
cat >> ~/.bashrc <<'EOF'
# ===== patrol-robot-sim 环境 v2（由 docs/17 手册添加）=====
export PROJECT_ROOT=/home/lich/ROS2/ros
source /opt/ros/humble/setup.bash
source /usr/share/gazebo/setup.sh 2>/dev/null
[ -f "$PROJECT_ROOT/install/setup.bash" ] && source "$PROJECT_ROOT/install/setup.bash"
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

# ── 测试模式开关：按“当前电脑”二选一（详见手册 §2.4）──
# ① 有界面（本机桌面 / 虚拟机桌面 / VNC）：用下面两行
# export GUI_OPTS="gui:=true"
# export RVIZ_OPTS="use_rviz:=true"
# ② 无界面（SSH 远程、没有桌面）：用下面两行
export GUI_OPTS="gui:=false"
export RVIZ_OPTS="use_rviz:=false"
unset DISPLAY
EOF
source ~/.bashrc
```

> 上面默认选的是 **② 无界面**（本机当前就是远程无桌面）。
> 以后换到**有界面的电脑**测试时，把 ② 的两行和 `unset DISPLAY` 一起注释掉，
> 把 ① 的两行取消注释即可（§2.5 有逐步说明）。

做完后**验证一下**：

```bash
cd /home/lich/ROS2/ros
pwd
```

- `pwd` 这句话在干什么：问系统"我现在在哪个文件夹"。
- 应该看到：`/home/lich/ROS2/ros`。不是的话，就把 `cd /home/lich/ROS2/ros` 再执行一遍。

> 如果你的项目放在别的位置，把上面两处的 `/home/lich/ROS2/ros` 换成你的实际路径。

### 2.3 第一次编译：把代码变成能运行的程序

> **这句话在干什么**：我们拿到的是一堆"源代码"（给程序员看的文字），电脑不能直接跑。
> "编译"就是把它翻译成电脑能执行的程序，类似把菜谱做成菜。

```bash
cd /home/lich/ROS2/ros
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
```

- 应该看到最后一行类似：`Summary: 3 packages finished [...]`。
- **第一次比较慢（1~2 分钟）正常**；以后再编译只要几秒。
- 如果看到红色的 `error`，先跳到 §15 查现象，不要继续往下做。

编译成功后，让当前终端也能用上新程序：

```bash
source install/setup.bash
```

### 2.4 一个"总开关"：选「有界面」还是「无界面」

为了让同一份手册在两种电脑上都能用，我们把"开不开窗口"收进了两个环境变量里
（§2.2 已经配好，默认是"无界面"）：

| 模式 | 变量设置 | 启动后的现象 |
| --- | --- | --- |
| **有界面**（本机桌面 / 虚拟机桌面 / VNC） | `GUI_OPTS="gui:=true"`、`RVIZ_OPTS="use_rviz:=true"` | 弹出 Gazebo 3D 场地窗口 + RViz 仪表盘 |
| **无界面**（SSH 远程、没有桌面） | `GUI_OPTS="gui:=false"`、`RVIZ_OPTS="use_rviz:=false"` | 不弹窗口，只用文字和数字验证 |

**怎么切换**（两种办法，任选）：

- **临时切换**（只对当前终端有效，适合试一下）：

```bash
# 临时改成“有界面”
export GUI_OPTS="gui:=true"
export RVIZ_OPTS="use_rviz:=true"

# 临时改回“无界面”
export GUI_OPTS="gui:=false"
export RVIZ_OPTS="use_rviz:=false"
```

- **永久切换**：编辑 `~/.bashrc`（用 `nano ~/.bashrc`），按 §2.2 里的注释说明
  把 ① / ② 两组注释对调，保存后执行 `source ~/.bashrc`。

> 手册后面所有启动命令里出现的 `$GUI_OPTS $RVIZ_OPTS`，
> 就是自动展开成你上面选的模式 —— **命令本身不用改**。

> **小提示**：如果这两个变量没有设置，命令会"不加任何窗口参数"执行，
> 效果相当于有界面模式。测试前可以随时用 `echo $GUI_OPTS $RVIZ_OPTS`
> 确认当前处于哪种模式。

另外两个常用参数（和模式无关）：

| 参数 | 作用 | 什么时候用 |
| --- | --- | --- |
| `auto_start:=true` | 启动后立刻开始巡逻，不等你发令 | 想省事时用 |
| `patrol_params:=/路径/xx.yaml` | 换一份"巡逻设置文件"（航点、超时等） | 测试重试/自定义航点时用 |

### 2.5 在有界面的电脑上，先确认这 3 件事

**第 1 件：确认你确实在"桌面会话"里**

```bash
echo $DISPLAY
```

> 在干什么：查"显示服务"的地址。有桌面时通常显示 `:0` 或 `:1`；
> 如果是空的，说明你人在桌面之外（比如 SSH 进来且没加 `-X`），窗口弹不出来。

**第 2 件：确认 3D 显示能力**

```bash
# 如果提示找不到 glxinfo，先装一个小工具（一次性）：
sudo apt install -y mesa-utils
glxinfo -B | grep -i renderer
```

> 在干什么：问显卡"你叫什么名字"。
> 看到 `llvmpipe`（软件模拟，能跑但慢）、`VMware/SVGA3D`、`Intel`、`NVIDIA` 等都属于正常；
> 报错"无法连接显示服务"则回到第 1 件。

**第 3 件：确认 Gazebo 不卡（卡就按下面调）**

> 虚拟机上跑 3D 需要"开启 3D 加速"（见 03 文档 §2）。如果动画明显卡顿：
> 打开 Gazebo 菜单 `World` → `Physics`，把 `real_time_update_rate` 从 1000 调到 500；
> 再在 `Scene` 里关闭 `Shadows`（阴影）。这属于正常的性能调优，不影响测试结论。

**如果这台"有界面电脑"不是当前这台机器（比如是你自己的笔记本）：**

1. 把整个项目文件夹复制过去（U 盘 / 共享文件夹 / Git 均可），确认目录里有
   `README.md`、`src/`、`scripts/`、`docs/`；
2. 在目标电脑上依次执行：

```bash
source /opt/ros/humble/setup.bash
bash scripts/install_deps.sh     # 安装仿真依赖（需要 sudo，第一次约 10 分钟）
bash scripts/build.sh            # 编译（第一次 1~2 分钟）
```

3. 按 §2.2 配置环境变量 —— **注意**：如果项目路径不是 `/home/lich/ROS2/ros`，
   把 §2.2 里的 `PROJECT_ROOT=...` 改成实际路径；
   同时把模式开关改成 **① 有界面** 的那两行（`gui:=true` / `use_rviz:=true`）。

## 4. 第 2 关：让机器人"活过来"（仿真世界）

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-I-01、TC-I-02 |
| 前置 | 第 1 关通过 |
| 耗时 | 约 5 分钟 |
| 这一关在测什么 | 3D 世界里能不能出现一台带雷达的机器人，雷达/时钟/里程计数据正常 |

### 4.1 启动仿真（这个命令会一直运行，别关掉）

```bash
bash scripts/simtest/cleanup.sh      # 先打扫干净，防止上次没关的程序捣乱
ros2 launch patrol_robot_bringup simulation.launch.py $GUI_OPTS
```

- **第一句**：把上次遗留在后台的旧程序全部关掉（就像上台前清场）。
  看到 `环境已清理（无残留进程）` 就放心了。
- **第二句**：启动仿真。它会**一直运行不退出**，占用当前终端 —— 这是正常的。
  想结束它就按 `Ctrl` + `C`（或另开终端跑 `cleanup.sh`）。
- 启动需要 **20~40 秒**，期间会刷很多文字，**不要慌**，等它稳定下来。

> 用 `linux` 术语说，这就是"打开了一个叫仿真世界的程序"。它内部会自己启动：
> 物理引擎（算碰撞）、机器人模型、雷达传感器、时钟等。

> **🖥 有界面时你能看到**：弹出一个深色背景的 3D 窗口（Gazebo），中间是一个**六边形房间**，
> 房间里摆着 **3×3 共 9 根柱子**（就是障碍物）；一辆"小坦克"样子的 TurtleBot3 停在房间左下角。
> 鼠标滚轮缩放、按住左键拖动可以换视角。画面里能看到它，说明仿真世界正常。

> **🖥 有界面时，遥控也更好玩**（第 2 关的"让机器人动一下"可以直接用键盘）：
> 另开终端执行 `ros2 run turtlebot3_teleop teleop_keyboard`，
> 然后按终端提示的按键（常见是 `w/a/s/d` 或 `i/j/k/l`）开车，按 `Ctrl+C` 退出。

### 4.2 另开一个终端，开始体检

新开一个终端（§2.2 做完后新终端自动就绪），逐条执行。每条命令都告诉你在问什么：

```bash
cd /home/lich/ROS2/ros
```

**检查 1：都有哪些"频道"在广播？**

```bash
ros2 topic list
```

> 在干什么：列出系统里所有正在广播的话题频道。
> 应该看到 `/scan`（雷达）、`/odom`（里程计）、`/tf`（坐标换算）、`/clock`（仿真时钟）等。

**检查 2：雷达每秒发多少次数据？**

```bash
ros2 topic hz /scan
```

> 在干什么：统计 `/scan` 频道每秒来几条件，像数水龙头滴几滴水。
> 应该看到：`average rate: 5.0` 左右（3~10 之间都算正常）。
> 按 `Ctrl` + `C` 结束这条命令。

**检查 3：仿真时钟在不在走？**

```bash
ros2 topic hz /clock
```

> 在干什么：仿真世界有它自己的"时间"，这条命令确认它一直在走。
> 应该看到：`average rate: 10.0` 左右。如果完全没有输出，说明仿真没起来。

**检查 4：机器人"腿动没动"的数据源正常吗？**

```bash
ros2 topic hz /odom
```

> 在干什么：`/odom` 是机器人自己的"我移动了多少"记录，导航全靠它。
> 应该看到：约 28 次/秒。

**检查 5：机器人身体的各个部位"拼装"正确吗？**

```bash
ros2 run tf2_ros tf2_echo odom base_footprint
```

> 在干什么：`tf2_echo` 是"坐标换算查询器"。这句话在问："机器人身体（base_footprint）
> 相对于它的出发点（odom）在哪里？"
> 应该看到：类似 `Translation: [-2.000, -0.500, 0.009]` 的一行（数字含义：x=-2 米、y=-0.5 米）。
> 按 `Ctrl` + `C` 结束。

**检查 6（可选）：让机器人动一下**


```bash

ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"

ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"

# ③ 暂停（回复 current_mode=3 "PAUSED 已暂停"，机器人就地停车，但记住当前走到第几个点）
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 1}"

# ④ 继续（回复 current_mode=1，从刚才那个点接着走）
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 2}"

# ⑤ 停止（回复 current_mode=0 "IDLE 空闲"，从头再来）
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 3}"

# （附）复位：把统计数字清零、把错误状态清掉（恒回复 OK）

```

> **什么是"幂等"**：像电梯按钮，电梯已经在上去时你再按一下，它不会"重新再上去一次"，

## 11. 第 9 关：安全员上岗（障碍物急刹车）

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-S-04 |
| 前置 | 第 9 关的系统还在运行（巡逻中效果最直观） |
| 耗时 | 约 10 分钟 |
| 这一关在测什么 | 机器人正前方 0.3 米内出现障碍 → 立刻停车并报"危险"；拿开 → 自动恢复巡逻 |

> 打比方：安全员盯着雷达，前方 30 厘米内有人或有箱子就吹哨；箱子搬走、前方 60 厘米
> 内干净了，才解除警报。30 和 60 之间是"缓冲带"，防止在临界值上反复吹哨（抖动）。

### 11.1 先知道"危险"怎么表示

```bash
ros2 topic echo /safety/emergency_stop
```

> 在干什么：盯住"危险旗"频道。平时它不吭声（这是设计：只有状态变化才说话），
> 置位后会显示 `data: true`，且**后来才开始听的人也能立刻听到**（锁存机制）。
> 按 `Ctrl` + `C` 结束，等会儿再来看。

### 11.2 方式 A：🖥 有 Gazebo 画面时（最直观，推荐）

> 前提：第 9 关的系统正在运行，机器人正在巡逻（RViz 里黄色小球就是它当前的目标）。

1. 先找到机器人：在 Gazebo 窗口里用滚轮放大到能看清机器人（小坦克）和它前进的方向；
2. 在 Gazebo 菜单栏点 `Insert`，在弹出的小面板里选 `Box`；
3. 把鼠标移到机器人**正前方约半个车身（0.2 米）**的位置，点一下放下箱子 ——
   放下的瞬间能看到箱子出现在机器人前面；
4. 观察两个现象：
   - 机器人约 0.2 秒内**立刻刹停**，原地不动；
   - 另开终端执行 `ros2 topic echo /safety/emergency_stop`，出现 `data: true`；
     `ros2 topic echo /patrol/status` 的 `mode` 变成 **4**（SAFETY_HOLD 遇险停车）；
   - 指挥中心终端里出现日志：`前方障碍过近（0.2x m < 0.30 m），置位紧急标志`；
5. **留证**：把"箱子挡在机器人前面、机器人停着"的画面按 `PrtSc` 截图；
6. 验证**自动恢复**：在 Gazebo 里**右键点箱子 → `Delete`** 删掉它；
   - 稍等 1~2 秒：机器人重新起步，`mode` 回到 `1`，
     日志出现 `前方畅通（x.xx m > 0.60 m），解除紧急标志`；
7. **留证**：把"箱子已删除、机器人继续走"再截一张图。

**✅ 通过标志**：放下箱子 → 停车 + `true` + `mode=4`；删除箱子 → 恢复 + `false` + `mode=1`。
两张截图 + 两段日志就是本关的完整证据。

### 11.4 方式 C：连仿真都不开，1 分钟逻辑验证（可选）

> ⚠️ 前提：机器人正在巡逻（`/patrol/status` 的 `mode=1` 或 `2`）时才能看到模式变化；


> 在干什么：假装自己就是安全员，直接发危险/安全旗，看指挥中心听不听话。

> 也可以在指挥中心终端看到成对的日志：`安全标志变化: emergency=true / false`。

**✅ 通过标志**：放箱子 → 停车 + `true` + `mode=4`；拿开 → 恢复 + `false` + `mode=1`。

## 13. 第 11 关：性能与"连续跑 30 分钟"

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-P-01/02/03、TC-S-06 |
| 前置 | 第 9 关通过 |
| 耗时 | 快测 5 分钟；长稳测试 30 分钟 |
| 这一关在测什么 | 状态报告频率是否达标；两个自研节点吃多少 CPU/内存；长时间跑会不会崩 |

### 13.1 频率与延迟（TC-P-01）

```bash
ros2 topic hz /patrol/status        # 应该 ≈1.0 次/秒（0.9~1.1 都算过）
ros2 topic delay /patrol/status     # 应该小于 200 毫秒（0.2 秒）
```

> `hz` 量"多久发一次"，`delay` 量"消息从产生到你收到过了多久"（像查快递时效）。

### 13.2 两个自研节点吃多少资源（TC-P-02）

```bash
top -p $(pgrep -d, -f patrol_node)          # 看"指挥中心"的 CPU/内存，按 q 退出
ps -o rss= -p $(pgrep -f patrol_node) $(pgrep -f safety_guard_node)
```

> 在干什么：`top` 像任务管理器，看这个程序占多少 CPU；`ps` 报它的内存占用（单位 KB）。
> 判定标准：CPU 低于 5%（单个核心的 5%）；两个程序内存加起来增加不超过 50 MB（≈51200 KB）。

### 13.3 启动要多久（TC-P-03）

> 从执行 `ros2 launch patrol.launch.py ...` 那一刻起，到
> `ros2 service call /patrol/set_mode ...` 能成功应答为止，应小于 60 秒。
> 本机实测：CycloneDDS 下约 10 秒。

### 13.4 连续跑 30 分钟（TC-S-06）

1. 用默认设置（无限循环）启动：`ros2 launch patrol_robot_bringup patrol.launch.py $GUI_OPTS $RVIZ_OPTS`
2. 开始巡逻，然后**放着不管**；
3. 每 5 分钟执行一次下面这条，把数字抄进表格：

```bash
ps -o rss= -p $(pgrep -f patrol_node)
```

| 时间点 | 内存 KB | 备注 |
| --- | --- | --- |
| 0 分钟 | | |
| 5 分钟 | | |
| 10 分钟 | | |
| 15 分钟 | | |
| 20 分钟 | | |
| 25 分钟 | | |
| 30 分钟 | | |

> 判定：30 分钟内程序不崩；内存数字有波动但**没有持续上涨**的趋势
> （比如一直在 20000 → 21000 → 22000 → … 就不对）；`ros2 topic echo /patrol/status`
> 一直在更新。

### 15.2 现象对照表

| 你看到的现象 | 大概原因 | 一句话解决 |
| --- | --- | --- |
| `ros2: command not found`（找不到 ros2） | 终端没有加载 ROS 环境 | 执行 §2.2，然后新开一个终端 |
| `bash: scripts/simtest/cleanup.sh: No such file or directory` | 当前文件夹不是项目根目录 | `cd /home/lich/ROS2/ros` 再执行 |

终端=打字操作台；命令=一句话；节点=小机器人程序；话题=广播频道；服务=点单窗口；
Action=派长活儿；TF=坐标换算表；SLAM=边走边画图；AMCL=看着地图找自己；
Nav2=自动驾驶系统；QoS=邮局投递规则；Gazebo=3D 世界；RViz=3D 仪表盘；
headless=不开画面。

### 16.2 常用命令速查

| 我想…… | 命令 |
| --- | --- |
| 切换"有界面 / 无界面"模式 | `export GUI_OPTS="gui:=true"; export RVIZ_OPTS="use_rviz:=true"`（无界面用 `false`，详见 §2.4） |
| 看有哪些频道 | `ros2 topic list` |
| 看某频道每秒几条 | `ros2 topic hz /patrol/status` |
| 看某频道的内容 | `ros2 topic echo /patrol/status` |
| 看某频道的一条内容 | `ros2 topic echo /patrol/markers --once` |
| 给指挥中心下指令 | `ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"` |
| 让机器人去某点 | `ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{...}" --feedback` |
| 看看某个程序状态 | `ros2 lifecycle get /bt_navigator` |
| 紧急清场 | `bash scripts/simtest/cleanup.sh` |

### 16.3 测试脚本清单（`scripts/simtest/`）

| 脚本 | 一句话说明 | 对应关卡 |
| --- | --- | --- |
| `cleanup.sh` | 把上一轮遗留的程序全部关掉 | 每次测试前 |
| `drive_perimeter.py` | 自动带机器人绕场一圈，供建图 | 第 3 关 |
| `amcl_check.py` | 量"机器人以为自己在哪"和真实位置差多少 | 第 4 关 |
| `nav_goals.py` | 自动连走 5 个目标点并统计成功率 | 第 5 关 |
| `watch_cmd_vel.py` | 观察速度指令和位置变化（排障） | 第 5、7 关 |
| `front_point.py` | 算出机器人正前方 N 米的坐标（放箱子用） | 第 9 关 |
