## 0. 先看这里：30 秒了解任务，3 分钟选定路线

### 0.1 这个项目是干什么的？

想象一个**遥控玩具车 + 扫地机器人**的结合体：

- 它在一个 3D 仿真场地里（像游戏地图）跑；
- 它能**自己画地图**（边走边记录哪里有墙）；
- 它能**知道自己站在哪**；
- 你告诉它几个"停车点"，它能**自己排队跑圈**；
- 它前面突然出现障碍物，它会**急刹车**，障碍物拿开又会**自动继续**。

这个"玩具"由电脑里的 5 个部分组成：**仿真场地**（Gazebo）、**地图与定位**、**导航系统**（Nav2）、**巡逻指挥中心**（我们自己写的 `patrol_node`）、**安全员**（我们自己写的 `safety_guard_node`）。

本手册就是带你**亲手把上面每一句话验证一遍**。

### 0.2 三条测试路线（按你的时间选）

| 路线 | 适合谁 | 做哪几关 | 预计耗时 |
| --- | --- | --- | --- |
| **A 快速体检** | 只想确认"能用" | 第 1、2、4、7、9 关 | 约 30 分钟 |
| **B 完整验收** | 要交作业/验收，需要逐项打勾 | 第 1 ~ 11 关全部 | 2 ~ 3 小时 |
| **C 演示前准备** | 马上要给别人演示 | 第 15.3 节"演示前 15 分钟检查" | 15 分钟 |

> **本手册按"无界面服务器"编写**（就是你现在这台：用 Xshell 连上去，只有黑底白字的终端）：
> 测试全程**看不到 3D 画面**，我们用**终端的文字和数据**代替眼睛 —— 机器人动没动、在哪、
> 有没有刹车，全部有对应的命令可以"看到"（每关都写好了）。结论一样严谨，只是"看"的方式不同。

> 每关都有：**在测什么 → 怎么做 → 通过标志 → 失败怎么办**。
> 建议边做边在本手册 §14 的登记表里打勾（最终要抄进 08 文档存档）。

### 0.3 本机约定（先知道这 3 件事）

1. **项目放在哪**：本机路径是 `/home/lich/ROS2/ros`
   （里面能看到 `src/`、`scripts/`、`docs/`、`README.md` 这些文件夹/文件）。
   下文所有命令都假设你**已经在这个目录里**。
2. **"窗口 1 / 窗口 2"的说法**：本手册几乎所有关卡都是这个套路 ——
   **窗口 1**（一个 Xshell 标签页）用来**运行机器人系统**（一跑起来就占住窗口、一直不退出，这是正常的）；
   **窗口 2**（另一个标签页）用来**敲检查命令**。
   开新标签页的方法：Xshell 菜单 `文件` → `新建标签页`（或工具栏的 `+`）。
3. **千万不要关掉正在跑机器人的窗口**：直接关窗口/断开 Xshell 连接，会把里面的机器人一起关掉。
   正确做法是：在窗口 2 里执行 `bash scripts/simtest/cleanup.sh`，或者在窗口 1 里按 `Ctrl` + `C`。

## 1. 开工前先认识 10 个词（用生活里的事打比方）

| 词 | 打个比方 | 在本项目里指的是 |
| --- | --- | --- |
| **终端 / Xshell** | 一个"用打字下命令"的操作台；Xshell 是你连接这台服务器的"遥控器" | 你接下来所有操作都在这里完成 |
| **命令** | 对着操作台说的一句话，回车执行 | 手册里灰底代码块中的每一行 |
| **节点** | 一个会干活的小机器人程序 | 整个系统由十几个"节点"组成，各干各的 |
| **话题（topic）** | 一个广播频道，谁都能听 | 比如 `/scan` 频道上，雷达不停"喊"它看到的距离 |
| **服务（service）** | 点单窗口：你问一句，它答一句 | 比如"开始巡逻"就是给指挥中心发一条服务请求 |
| **动作（Action）** | 派一个长活儿，中途还能看进度、能喊停 | "走到某个点"就是给导航系统派一个动作 |
| **TF / 坐标系** | 换算表：A 物体相对于 B 物体在哪 | 让"地图坐标"和"机器人自己的坐标"能对上 |
| **建图（SLAM）** | 蒙着眼睛在房间里边走边画平面图 | 机器人边走边把墙的位置画成一张"格子地图" |
| **定位（AMCL）** | 看着地图问"我现在在图上的哪个点" | 让机器人知道自己在地图里的精确位置 |
| **QoS** | 邮局的投递规则（挂号信 by 平信） | 决定消息"丢了要不要重发、晚来的人能不能补看" |

还有两个名字会经常出现：

- **Gazebo**：3D 仿真场地软件（我们的"游戏世界"）。无界面模式下它**在后台默默运行物理和传感器**，只是不显示画面。
- **headless（无界面）**：就是"没有图形画面、只有文字"的运行方式。本手册所有启动命令都带 `gui:=false` 开关，就是告诉 Gazebo"不用开画面"。

> 记不住没关系，用到哪条回来查哪条，本手册 §16 还有一份速查表。

## 2. 开始前的一次性准备（约 10 分钟）

### 2.1 认识 Xshell 窗口（复制粘贴和中断）

1. **新建标签页**：菜单 `文件` → `新建标签页`（或工具栏 `+`）。
   测试时至少要开 **2 个**：一个跑机器人（窗口 1），一个敲命令（窗口 2）。
2. **复制**：用鼠标**拖动选中**想复制的内容，松开就复制好了（Xshell 默认行为）。
3. **粘贴**：在窗口里**点鼠标右键**，选"粘贴"；或者按 `Shift` + `Insert`。
4. **停止正在运行的程序**：按 `Ctrl` + `C`。
   它只会中断"正在前台跑的那条命令"，**不会**断开你的 SSH 连接。
5. **断开服务器**：输入 `exit`。提醒：断开前先清理机器人进程（见 §0.3 第 3 条）。

### 2.2 让每个终端自动"准备就绪"（强烈建议做一次）

> **这句话在干什么**：ROS 2 和本项目都需要一份"环境配置"，不配置的话系统会不认识 `ros2` 命令、
> 也找不到我们的项目。这里把配置写进 `~/.bashrc`（每开一个新终端都会自动执行的个人配置文件），
> 以后新开的标签页就自动准备好了，不用每次手敲。

复制下面整段，粘贴到终端执行（只在第一次做；脚本会自动清理旧版本，重复执行也安全）：

```bash
# 第 1 步：清理可能存在的旧版本配置（没有旧配置也不报错）
python3 - <<'PY'
import os
import re
path = os.path.expanduser('~/.bashrc')
text = open(path, encoding='utf-8').read()
# 删除旧版手册写入的配置块（新老格式都能清理）
text = re.sub(
    r'# ===== patrol-robot-sim.*?# ===== patrol-robot-sim 环境 v\d+ 结束[^\n]*\n',
    '', text, flags=re.S)
text = re.sub(
    r'# ===== patrol-robot-sim.*?^unset DISPLAY$\n',
    '', text, flags=re.S | re.M)
open(path, 'w', encoding='utf-8').write(text)
PY

# 第 2 步：写入新配置（v5，无界面服务器专用）
cat >> ~/.bashrc <<'EOF'
# ===== patrol-robot-sim 环境 v5（由 docs/17 手册添加）=====
export PROJECT_ROOT=/home/lich/ROS2/ros
source /opt/ros/humble/setup.bash
source /usr/share/gazebo/setup.sh 2>/dev/null
[ -f "$PROJECT_ROOT/install/setup.bash" ] && source "$PROJECT_ROOT/install/setup.bash"
export ROS_DOMAIN_ID=30
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export AMENT_CPPCHECK_ALLOW_SLOW_VERSIONS=1   # 让 cppcheck 静态检查真正执行（见 §3）
unset DISPLAY    # 无界面服务器：禁止程序尝试连接不存在的图形显示
# ===== patrol-robot-sim 环境 v5 结束 =====
EOF

# 第 3 步：让当前窗口立刻生效
source ~/.bashrc
echo "配置完成：ROS_DOMAIN_ID=$ROS_DOMAIN_ID RMW=$RMW_IMPLEMENTATION"
```

> **说明**：这段配置让每个新开的标签页自动准备好运行环境。
> 以前按旧版手册配过的话，第 1 步会先把它删掉再写新的，不会冲突。
> 最后一行应该显示：`配置完成：ROS_DOMAIN_ID=30 RMW=rmw_cyclonedds_cpp`。

做完后**验证一下**：

```bash
cd /home/lich/ROS2/ros
pwd
```

- `pwd` 这句话在干什么：问系统"我现在在哪个文件夹"。
- 应该看到：`/home/lich/ROS2/ros`。不是的话，就把 `cd /home/lich/ROS2/ros` 再执行一遍。

> 如果你的项目放在别的位置，把上面两处的 `/home/lich/ROS2/ros` 换成你的实际路径。

### 2.3 第一次编译：把代码变成能运行的程序

> **这句话在干什么**：我们拿到的是一堆"源代码"（给程序员看的文字），电脑不能直接跑。
> "编译"就是把它翻译成电脑能执行的程序，类似把菜谱做成菜。

```bash
cd /home/lich/ROS2/ros
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
```

- 应该看到最后一行类似：`Summary: 3 packages finished [...]`。
- **第一次比较慢（1~2 分钟）正常**；以后再编译只要几秒。
- 如果看到红色的 `error`，先跳到 §15 查现象，不要继续往下做。

编译成功后，让当前窗口也能用上新程序：

```bash
source install/setup.bash
```

### 2.4 启动命令里的两个常用小开关

启动命令后面可以加"开关"，格式是 `名字:=值`。本手册常用这两个：

| 参数 | 作用 | 什么时候用 |
| --- | --- | --- |
| `auto_start:=true` | 启动后立刻开始巡逻，不等你发令 | 想省事时用 |
| `patrol_params:=/路径/xx.yaml` | 换一份"巡逻设置文件"（航点、停留时间等） | 测试自定义设置时用 |

> **本手册默认用法**：所有启动命令都带 `gui:=false use_rviz:=false`
> （意思是"不要图形画面、不要 3D 仪表盘"—— 这正是无界面服务器需要的）。
> 缺省时这两个开关是 `true`，在有桌面的电脑上会弹出 Gazebo 和 RViz 窗口（见 §16.4）。

## 4. 第 2 关：让机器人"活过来"（无界面仿真世界）

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-I-01、TC-I-02 |
| 前置 | 第 1 关通过 |
| 耗时 | 约 5 分钟 |
| 这一关在测什么 | 3D 世界里能不能出现一台带雷达的机器人，雷达/时钟/里程计数据正常 |

### 4.1 启动仿真（在"窗口 1"执行，这个命令会一直运行，别关掉）

```bash
cd /home/lich/ROS2/ros
bash scripts/simtest/cleanup.sh
ros2 launch patrol_robot_bringup simulation.launch.py gui:=false 2>&1 | tee /tmp/patrol_boot.log
```

- **第一句**：把上次遗留在后台的旧程序全部关掉（就像上台前清场）。
  看到 `环境已清理（无残留进程）` 就放心了。
- **第二句**：启动仿真。它会**一直运行不退出**，占用当前窗口 —— 这是正常的。
  想结束它就按 `Ctrl` + `C`，或到窗口 2 执行 `cleanup.sh`。
- 命令末尾的 `2>&1 | tee /tmp/patrol_boot.log` 是个"小抄写员"：屏幕上的字照常显示，
  同时**自动抄一份**到 `/tmp/patrol_boot.log`，后面查证据用（没有它也行，但强烈建议带上）。
- 启动需要 **20~40 秒**，期间会刷很多文字，**不要慌**，等它稳定下来。

> 用 `linux` 术语说，这就是"打开了一个叫仿真世界的程序"。它内部会自己启动：
> 物理引擎（算碰撞）、机器人模型、雷达传感器、时钟等。

> **无界面模式下没有 3D 窗口可看**，怎么确认"机器人生出来了"？看刚才那份日志里有没有这一行：
>
> ```bash
> grep "Successfully spawned" /tmp/patrol_boot.log
> ```
>
> 应该看到（约 15~20 秒后出现）：
> `[spawn_entity.py-3] ... Spawn status: SpawnEntity: Successfully spawned entity [burger]`
> 意思是"一台 burger 型号的 TurtleBot3 已放进世界"。

### 4.2 另开一个标签页（"窗口 2"），开始体检

新开一个 Xshell 标签页（§2.2 做完后新标签页自动就绪），逐条执行。每条命令都告诉你在问什么：

```bash
cd /home/lich/ROS2/ros
```

**检查 1：都有哪些"频道"在广播？**

```bash
ros2 topic list
```

> 在干什么：列出系统里所有正在广播的话题频道。
> 应该看到 `/scan`（雷达）、`/odom`（里程计）、`/tf`（坐标换算）、`/clock`（仿真时钟）等。

**检查 2：雷达每秒发多少次数据？**

```bash
ros2 topic hz /scan
```

> 在干什么：统计 `/scan` 频道每秒来几条件，像数水龙头滴几滴水。
> 应该看到：`average rate: 5.0` 左右（3~10 之间都算正常）。
> 按 `Ctrl` + `C` 结束这条命令。

**检查 3：仿真时钟在不在走？**

```bash
ros2 topic hz /clock
```

> 在干什么：仿真世界有它自己的"时间"，这条命令确认它一直在走。
> 应该看到：`average rate: 10.0` 左右。如果完全没有输出，说明仿真没起来。

**检查 4：机器人"腿动没动"的数据源正常吗？**

```bash
ros2 topic hz /odom
```

> 在干什么：`/odom` 是机器人自己的"我移动了多少"记录，导航全靠它。
> 应该看到：约 28 次/秒。

**检查 5：机器人身体的各个部位"拼装"正确吗？**

```bash
ros2 run tf2_ros tf2_echo odom base_footprint
```

> 在干什么：`tf2_echo` 是"坐标换算查询器"。这句话在问："机器人身体（base_footprint）
> 相对于它的出发点（odom）在哪里？"
> 应该看到：类似 `Translation: [-2.000, -0.500, 0.009]` 的一行（数字含义：x=-2 米、y=-0.5 米，
> 正是我们设定的出生点；z≈0.01 是车身高度）。
> 按 `Ctrl` + `C` 结束。

**检查 6（可选）：让机器人动一下**

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.15}, angular: {z: 0.0}}"
```

> 在干什么：往"速度指令"频道按每秒 10 次的频率发送"往前走"。
> 无界面下你看不到它走，但可以用数据验证：另开一个标签页再跑一次
> `ros2 run tf2_ros tf2_echo odom base_footprint`，x 坐标应该比刚才大了（比如从 -2.000 变成 -1.8）。
> 结束这条命令按 `Ctrl` + `C`，**然后再补一条停止指令**（否则机器人会一直往前）：
>
> ```bash
> ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{}"

### 8.2 五个指令的"点单"练习

先在窗口 1 启动**完整系统**（用第 7 关 §9.1 的启动命令），等日志出现

> ```

### 11.3 方式 B：手动注入危险信号（可选，1 分钟）

> ⚠️ 前提：机器人正在巡逻（`/patrol/status` 的 `mode=1` 或 `2`）时才能看到模式变化；
> 如果它处于空闲（mode=0）或人工暂停（mode=3），危险旗只会被"锁存"（安全员记下了），
> 不会改变 mode —— 这属于正常设计：旗子只是"情报"，怎么处理由指挥中心按当前任务决定。

```bash
# 手动报"危险"：注意加上 --qos-durability transient_local（和指挥中心的"收信规则"一致）
ros2 topic pub --once --qos-durability transient_local /safety/emergency_stop std_msgs/msg/Bool "{data: true}"

# 手动报"安全"：
ros2 topic pub --once --qos-durability transient_local /safety/emergency_stop std_msgs/msg/Bool "{data: false}"
```

> 在干什么：假装自己就是安全员，直接发危险/安全旗，看指挥中心听不听话。
> 巡逻中执行第一条：`mode` 变 4（停车）；执行第二条：`mode` 回到 1（继续）。
> 也可以在窗口 1 看到成对的日志：`安全标志变化: emergency=true / false`。

**✅ 通过标志**：放箱子 → 停车 + `true` + `mode=4`；拿开 → 恢复 + `false` + `mode` 回到 2/1。

**📝 登记**：TC-S-04 打勾。

## 13. 第 11 关：性能与"连续跑 30 分钟"

| 项 | 说明 |
| --- | --- |
| 对应用例 | TC-P-01/02/03、TC-S-06 |
| 前置 | 第 7 关通过 |
| 耗时 | 快测 5 分钟；长稳测试 30 分钟 |
| 这一关在测什么 | 状态报告频率是否达标；两个自研节点吃多少 CPU/内存；长时间跑会不会崩 |

### 13.1 频率与延迟（TC-P-01）

先按第 7 关启动系统并开始巡逻，然后在窗口 2：

```bash
ros2 topic hz /patrol/status        # 应该 ≈1.0 次/秒（0.9~1.1 都算过）
ros2 topic delay /patrol/status     # 应该小于 200 毫秒（0.2 秒）
```

> `hz` 量"多久发一次"，`delay` 量"消息从产生到你收到过了多久"（像查快递时效）。

### 13.2 两个自研节点吃多少资源（TC-P-02）

```bash
top -p $(pgrep -d, -f patrol_node)          # 看"指挥中心"的 CPU/内存，按 q 退出
ps -o rss= -p $(pgrep -f patrol_node) $(pgrep -f safety_guard_node)
```

> 在干什么：`top` 像任务管理器，看这个程序占多少 CPU；`ps` 报它的内存占用（单位 KB，
> 两个数字分别对应指挥中心和安全员）。
> 判定标准：CPU 低于 5%（单个核心的 5%）；两个程序内存加起来增加不超过 50 MB（≈51200 KB）。

### 13.3 启动要多久（TC-P-03）

> 从执行 `ros2 launch patrol.launch.py ...` 那一刻起，到
> `ros2 service call /patrol/set_mode ...` 能成功应答为止，应小于 60 秒。
> 本机实测：约 20 秒。

### 13.4 连续跑 30 分钟（TC-S-06）

1. 用默认设置（无限循环）启动：`ros2 launch patrol_robot_bringup patrol.launch.py gui:=false use_rviz:=false`
2. 开始巡逻，然后**放着不管**；
3. 每 5 分钟执行一次下面这条，把数字抄进表格：

```bash
ps -o rss= -p $(pgrep -f patrol_node)
```

| 时间点 | 内存 KB | 备注 |
| --- | --- | --- |
| 0 分钟 | | |
| 5 分钟 | | |
| 10 分钟 | | |
| 15 分钟 | | |
| 20 分钟 | | |
| 25 分钟 | | |
| 30 分钟 | | |

> 判定：30 分钟内程序不崩；内存数字有波动但**没有持续上涨**的趋势
> （比如一直在 20000 → 21000 → 22000 → … 就不对）；`ros2 topic echo /patrol/status`

### 15.2 现象对照表

| 你看到的现象 | 大概原因 | 一句话解决 |
| --- | --- | --- |
| `ros2: command not found`（找不到 ros2） | 终端没有加载 ROS 环境 | 执行 §2.2，然后新开一个标签页 |
| `bash: scripts/simtest/cleanup.sh: No such file or directory` | 当前文件夹不是项目根目录 | `cd /home/lich/ROS2/ros` 再执行 |
| `source: install/setup.bash: No such file` | 还没编译，或不在项目根目录 | 先做 §2.3 编译 |
| `ros2 node list` 什么都不显示 | 命令行"小助手"还记着旧配置 | `ros2 daemon stop`，几秒后重试 |
| 新标签页里一切正常，旧标签页里不行 | `~/.bashrc` 只对**新开**的窗口生效 | 在旧窗口里执行 `source ~/.bashrc`，或新开标签页 |
| 启动后卡住超过 2 分钟，日志停在加载世界附近，后面什么话题都没有 | Gazebo 在尝试联网拉取在线模型库，被网络环境卡住 | 本仓库启动文件已内置"离线加固"（自动禁用在线模型库）；如果你手动改过 launch 文件，检查 `GAZEBO_MODEL_DATABASE_URI` 那一行还在不在 |
| 日志里出现 `process has died ... exit code -9` | 进程被 `cleanup.sh` 主动结束了（正常的"清场"） | 如果你刚运行过 cleanup，忽略即可；否则用 `free -h` 看看内存是不是被占满了 |
| 导航大脑一直是 `unconfigured`，启动很慢、日志里反复 `Failed to change state` | 通信中间件选得不对（Fast DDS 在本机很慢） | 确认 `export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`（§2.2 已加），重来 |
| Nav2 启动了但机器人不动；`/patrol/status` 报 error_code=3 | 目标点太难走（柱子缝里） | 换外圈的目标点（§7.2） |
| `/amcl_pose` 没有数据 | 这个频道的"邮局规则"需要订"挂号信" | 用 `scripts/simtest/amcl_check.py`（它已按规则订阅） |
| `ros2 topic pub` 后机器人不动 | 仿真没启动 / 话题名不对 | 回到第 2 关先验证 `/scan` 有数据 |
| 放箱子后不刹车 | 箱子放太远（超过 0.3 米）或机器人已经开走了 | 按 §11.2 等 `mode: 2` 的 15 秒窗口重试；用 `front_point.py 0.25` 重新算坐标 |
| `spawn_entity.py` 报 `Service /spawn_entity unavailable` | 仿真世界没在运行，或还没启动完 | 先启动仿真，并等日志出现 `Successfully spawned` 后再操作 |
| 机器人"哆嗦"、走走停停 | 上次的旧程序还在抢控制权 | `bash scripts/simtest/cleanup.sh` 清场重来 |
| 把 cleanup 和启动命令写在了同一行 | 本仓库的 cleanup 已做防护（会自动跳过自身所在的命令行），但仍建议分两行敲 | 分两行敲，每步结果看得更清楚 |
| Xshell 断线重连后，仿真没了 | 断开连接会连带关闭里面的程序 | 重连后 `cleanup.sh` 清场，再从对应关卡重新启动 |
| 屏幕上刷一大堆文字，还有黄色 WARN | 各节点开工时的正常"报到" | 不用怕，按每关的"通过标志"判断即可 |

## 16. 附录

### 16.1 名词速查（一句话版）

终端=打字操作台；Xshell=连接服务器的遥控器；无界面/headless=没有画面、只看数据；
命令=一句话；节点=小机器人程序；话题=广播频道；服务=点单窗口；
Action=派长活儿；TF=坐标换算表；SLAM=边走边画图；AMCL=看着地图找自己；
Nav2=自动驾驶系统；QoS=邮局投递规则；Gazebo=3D 世界（本手册里它在后台默默运行）。

### 16.2 常用命令速查

| 我想…… | 命令 |
| --- | --- |
| 看有哪些频道 | `ros2 topic list` |
| 看某频道每秒几条 | `ros2 topic hz /patrol/status` |
| 看某频道的内容 | `ros2 topic echo /patrol/status` |
| 看某频道的一条内容 | `ros2 topic echo /patrol/markers --once` |
| 给指挥中心下指令 | `ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"` |
| 让机器人去某点 | `ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{...}" --feedback` |
| 看看某个程序状态 | `ros2 lifecycle get /bt_navigator` |
| 启动全系统（无界面） | `ros2 launch patrol_robot_bringup patrol.launch.py gui:=false use_rviz:=false` |
| 紧急清场 | `bash scripts/simtest/cleanup.sh` |

### 16.3 测试脚本清单（`scripts/simtest/`）

| 脚本 | 一句话说明 | 对应关卡 |
| --- | --- | --- |
| `cleanup.sh` | 把上一轮遗留的程序全部关掉（会自动跳过自身及所在命令行，"清理命令"和"启动命令"分开敲或写在一起都安全） | 每次测试前 |
| `drive_perimeter.py` | 自动带机器人绕场一圈，供建图 | 第 3 关 |
| `amcl_check.py` | 量"机器人以为自己在哪"和真实位置差多少 | 第 4 关 |
| `nav_goals.py` | 自动连走 5 个目标点并统计成功率 | 第 5 关 |
| `watch_cmd_vel.py` | 观察速度指令和位置变化（排障） | 第 5、7 关 |
| `front_point.py` | 算出机器人正前方 N 米的坐标（放箱子用） | 第 9 关 |

### 16.4 如果你用的是"有界面"电脑

本手册的所有步骤在有桌面的电脑上同样适用，只需两处小改动：

1. 启动命令**删掉** `gui:=false use_rviz:=false`（例如
   `ros2 launch patrol_robot_bringup patrol.launch.py patrol_params:=/tmp/patrol_2laps.yaml`），
   就会自动弹出 Gazebo 3D 窗口和 RViz 仪表盘（RViz 已预置航点小球显示）；
2. 第 8 关的"颜色验证"和 §14 的证据可以直接用**截图**代替文本（其余判定标准完全相同）。
