| 类别 | 风格 | 示例 |
| --- | --- | --- |
| 包名 | `snake_case` | `patrol_robot_core` |

| 常量 / `constexpr` | `kPascalCase` | `kPi`、`kDeg2Rad` |
| 宏 | 全大写下划线（**尽量不用**） | `PATROL_ROBOT_CORE__NAV_CLIENT_HPP_` |
| ROS 话题 / 参数名 | `snake_case` | `waypoint_x`、`/patrol/set_mode` |
| 命名空间 | `snake_case` | `patrol_robot_core` |
| 类型别名 | `PascalCase` | `using GoalHandle = ...` |

### 2.1 头文件保护

必须使用**全大写、含包名的路径式**宏，避免冲突：

```cpp
#ifndef PATROL_ROBOT_CORE__WAYPOINT_LOADER_HPP_
#define PATROL_ROBOT_CORE__WAYPOINT_LOADER_HPP_
// ...
#endif  // PATROL_ROBOT_CORE__WAYPOINT_LOADER_HPP_
```

注意：包名与文件名之间用**双下划线**分隔（ROS 2 官方约定）。

## 3. 文件组织

### 3.1 头文件结构模板

```cpp
// 文件用途：一句话说明本文件的职责
// 依赖：列出关键外部依赖（可选）
#ifndef PATROL_ROBOT_CORE__EXAMPLE_HPP_
#define PATROL_ROBOT_CORE__EXAMPLE_HPP_

// 1. 标准库（按字母序）
#include <memory>
#include <string>
#include <vector>

// 2. 第三方库（ROS 2）
#include "rclcpp/rclcpp.hpp"

// 3. 本项目头文件
#include "patrol_robot_core/waypoint_loader.hpp"

namespace patrol_robot_core
{

/// @brief 一句话类说明
/// @details 详细说明（可选）
class Example
{
public:
  /// @brief 构造函数
  /// @param node 宿主节点（不持有所有权）
  explicit Example(rclcpp::Node * node);

  // ... 公有接口

private:
  // ... 私有实现
  rclcpp::Node * node_{nullptr};
};

}  // namespace patrol_robot_core

#endif  // PATROL_ROBOT_CORE__EXAMPLE_HPP_
```

### 3.2 include 顺序

1. 对应的头文件（`xxx.cpp` 中第一个 include 自己的 `xxx.hpp`）；
2. C 标准库；
3. C++ 标准库；
4. 其他库（ROS 2）；
5. 本项目头文件。

各组之间空一行，组内按字母序。

## 4. 资源与内存管理

| 规则 | 说明 |
| --- | --- |
| M-01 | **禁止**裸 `new` / `delete`。使用 `std::make_unique` / `std::make_shared` |
| M-02 | 所有权唯一时用 `std::unique_ptr`；共享所有权时才用 `std::shared_ptr` |
| M-03 | **不持有所有权**的指针参数用裸指针或引用，并在注释中说明 |
| M-04 | ROS 2 消息用 `::SharedPtr` / `::ConstSharedPtr`；只读回调参数用 const 引用 |
| M-05 | 优先 `std::vector`、`std::string`，避免 C 风格数组与 `char*` |
| M-06 | 禁止 `std::auto_ptr`、`std::bind1st` 等 C++17 已移除/弃用设施 |
| M-07 | 定时器、订阅、发布者等句柄必须作为成员保存，否则会被立即销毁（ROS 2 常见错误） |

### 4.1 典型错误示例

```cpp
// ✗ 错误：临时对象立即析构，订阅实际不生效
PatrolNode() {
  create_subscription<std_msgs::msg::Bool>(
    "flag", 10, std::bind(&PatrolNode::onFlag, this, std::placeholders::_1));
}

// ✓ 正确：句柄保存为成员（哪怕不显式使用）
rclcpp::Subscription<std_msgs::msg::Bool>::SharedPtr flag_sub_;

PatrolNode() {
  flag_sub_ = create_subscription<std_msgs::msg::Bool>(
    "flag", 10, std::bind(&PatrolNode::onFlag, this, std::placeholders::_1));
}
```

## 5. 参数使用规范

| 规则 | 说明 |
| --- | --- |
| P-01 | **先 `declare_parameter` 再 `get_parameter`**；未声明直接获取会抛异常 |
| P-02 | `declare_parameter` 必须提供默认值，保证零参数也能启动 |
| P-03 | 参数名与「含义 + 单位」对齐：`waypoint_timeout_sec`、`stop_distance`（单位 m 体现在文档与注释中） |
| P-04 | **禁止魔法数字**。所有可调量必须参数化（NFR-06） |
| P-05 | 参数校验失败必须**显式失败**（抛异常/报 ERROR 并拒绝服务），不得静默降级（NFR-09） |
| P-06 | 参数值在构造期缓存到成员变量，避免在热路径反复调用 `get_parameter` |

```cpp
// ✓ 推荐写法
declareParameters():
  stop_distance_ = declare_parameter<double>("stop_distance", 0.30);
  resume_distance_ = declare_parameter<double>("resume_distance", 0.60);
  
  std::string error;
  if (!SafetyEvaluator::validateConfig(cfg, error)) {
    RCLCPP_FATAL(get_logger(), "安全参数非法：%s", error.c_str());
    throw std::invalid_argument(error);
  }
```

## 6. 日志规范

| 级别 | 使用场景 | 频率约束 |
| --- | --- | --- |
| `DEBUG` | 逐帧反馈、循环内部变量 | 允许高频 |
| `INFO` | 状态迁移、航点切换、启动信息、任务完成 | 低频（< 1 Hz） |
| `WARN` | 可恢复异常：超时、重试、跳过航点、安全触发 | 中频（事件驱动） |
| `ERROR` | 服务失败、参数非法、Action Server 不可用 | 低频 |
| `FATAL` | 无法继续运行，即将退出 | 仅启动期 |

### 6.1 日志格式约定

```cpp
// ✓ 好：包含定位信息（哪个航点、什么数值、什么阈值）
RCLCPP_WARN(get_logger(), "航点 %u 导航超时（%.1fs），触发重试", sm_->waypointIndex(), elapsed);

// ✓ 好：状态迁移必须成对记录
RCLCPP_INFO(get_logger(), "服务 %s → %s (%s)", toString(event), toString(sm_->state()), msg.c_str());

// ✗ 差：无信息量
RCLCPP_INFO(get_logger(), "error");

// ✗ 差：高频刷屏（在 100ms 定时器里打 INFO）
RCLCPP_INFO(get_logger(), "tick");   // 10 Hz 刷屏，严禁
```

### 6.2 禁止事项

- ✗ 在传感器回调里无条件打 `INFO`（`/scan` 有 10 Hz）；
- ✗ 用日志代替错误处理（打日志但流程继续）；
- ✗ 在析构函数里打日志（此时 logger 可能已失效）；
- ✗ `printf` / `std::cout`（ROS 2 节点中一律用 `RCLCPP_*`）。

## 7. 并发与线程安全

| 规则 | 说明 |
| --- | --- |
| C-01 | 明确执行器类型。本项目 `patrol_node` 使用 `MultiThreadedExecutor(2)` |
| C-02 | 跨线程共享的数据成员必须有明确保护策略（`std::mutex` 或"单点更新"模型） |
| C-03 | **禁止**在回调中阻塞等待 Action 结果（`.get()`），会导致死锁 |
| C-04 | 加锁范围尽量小，锁内不做日志、不调用其他加锁方法 |
| C-05 | 不使用递归锁；如需，说明理由 |
| C-06 | 状态机等核心逻辑采用"单点更新"模型：只有 `tick()` 修改状态，回调只置标志 |
| C-07 | 定时器周期 ≥ 10 ms，避免占用过多 CPU（本项目 100 ms） |

### 7.1 单点更新模型（本项目的核心并发策略）

```
              Action result_callback (线程 B)
                        │  只更新 NavClient 内部状态（自带 mutex）
                        ▼
                    NavClient
                        │
              tick timer (线程 A)  │ 轮询 nav_->state()
                        ▼
                 PatrolStateMachine   ← 只有线程 A 访问，无需加锁
```

**收益**：状态机完全无锁，逻辑可独立单元测试，不存在数据竞争。

## 8. ROS 2 专项规范

| 规则 | 说明 |
| --- | --- |
| R-01 | 节点名、话题名、参数名通过参数暴露，不硬编码 |
| R-02 | QoS 必须显式声明，并附注释说明选择理由 |
| R-03 | 发布者/订阅者/服务/定时器句柄必须作为成员保存 |
| R-04 | 时间相关运算一律用 `this->now()`，禁止 `system_clock`（见 06 §4.4） |
| R-05 | **禁止**自研节点发布 TF（除非明确设计为 TF 提供者） |
| R-06 | 禁止自研节点发布 `/cmd_vel`（除非参数显式开启） |
| R-07 | 头文件只 include 必需的，尽量前置声明 |
| R-08 | 消息类型 include 用完整路径：`#include "nav2_msgs/action/navigate_to_pose.hpp"` |
| R-09 | 不修改 `install/` 目录下生成的文件；不手动编辑 `build/` |
| R-10 | 所有面向用户的可执行文件必须能通过 `--ros-args` 设置参数 |

## 9. 代码风格细节

| 项 | 约定 |
| --- | --- |
| 缩进 | 2 空格，禁用 Tab |
| 行宽 | ≤ 100 字符 |
| 大括号 | 函数、类、命名空间另起一行（Allman 风格，ROS 2 官方风格） |
| 指针/引用 | 与类型贴合：`Node * node`、`const std::string & name` |
| `if`/`for` 单行体 | **必须**加大括号 |
| 空行 | 逻辑块之间 1 行，函数之间 1 行 |
| 尾随空格 | 禁止 |
| 文件末尾 | 必须有且仅有一个换行 |
| `auto` | 允许用于迭代器、复杂类型；禁止用于掩盖类型 |
| `const` | 尽可能使用；只读参数与成员函数加 `const` |
| 类型转换 | 用 `static_cast` / `dynamic_cast` / `reinterpret_cast`，禁止 C 风格转换 |
| 异常 | 仅用于启动期致命错误；运行期用返回值与日志 |
| 数字字面量 | 浮点明确写小数点：`1.0` 而非 `1.`；`nullptr` 而非 `NULL`/`0` |

## 10. 注释规范

```cpp
/// @brief 一句话说明函数用途（Doxygen 风格，用于头文件）
/// @param x 目标 x 坐标（m）
/// @param yaw 目标偏航角（rad），内部自动转四元数
/// @return 是否成功提交目标（**不代表导航成功**）
bool sendGoal(double x, double y, double yaw);
```

| 规则 | 说明 |
| --- | --- |
| N-01 | 每个文件头部有一行用途说明 |
| N-02 | 所有公有方法有 Doxygen 注释 |
| N-03 | 私有方法可用 `//` 简洁注释 |
| N-04 | 注释解释 **why**，代码解释 **what**；不要写 `i++;  // i 加一` |
| N-05 | 涉及阈值、单位、边界的注释必须写清数值与单位 |
| N-06 | 已知缺陷必须用 `// TODO(owner): 说明` 标注，且不能阻塞主流程 |
| N-07 | 非直观的设计决策注释原因，并指向文档章节（如 `// 见 02 文档 ADR-06`） |

## 11. Git 规范

### 11.1 分支模型

| 分支 | 用途 |
| --- | --- |
| `main` | 可运行、可演示的稳定版本，**每个提交都应能跑通** |
| `feature/<主题>` | 单个功能开发（如 `feature/safety-guard`） |
| `fix/<问题>` | 缺陷修复 |

### 11.2 提交信息（Conventional Commits）

```
<type>(<scope>): <简短描述>

[可选的详细说明]

[可选的关联文档/需求编号]
```

| type | 含义 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档变更 |
| `refactor` | 重构（不改行为） |
| `test` | 测试相关 |
| `chore` | 构建、依赖、配置 |
| `perf` | 性能优化 |

**示例**：

```
feat(patrol_node): 实现航点循环巡逻状态机

- 支持 6 状态迁移（IDLE/MOVING/WAITING/PAUSED/SAFETY_HOLD/FAILED）
- 支持失败重试与超时保护
- 补充 SetPatrolMode 服务的 5 种模式处理

Refs: FR-06, FR-07, FR-11
```

```
fix(nav_client): 修复目标未接受时 cancel 无效的问题

cancel() 中 goal_handle_ 为空时回退到 async_cancel_all_goals()
Refs: 04§4.5 K-15
```

## 13. 静态分析与格式化命令

```bash
# 1. 格式化全部源码
find src -name "*.cpp" -o -name "*.hpp" | xargs clang-format -i

# 2. 检查格式（不修改，仅报告）
find src -name "*.cpp" -o -name "*.hpp" | xargs clang-format --dry-run -Werror

# 3. 运行 ament_lint（含 cpplint / uncrustify / xmllint / lint_cmake）
colcon test --packages-select patrol_robot_core patrol_interfaces patrol_robot_bringup
colcon test-result --verbose

# 4. 单独跑 cpplint
ament_cpplint src/patrol_robot_core/src src/patrol_robot_core/include

# 5. 单独跑 uncrustify
ament_uncrustify --reformat src/patrol_robot_core/src src/patrol_robot_core/include
```

### 13.1 常用忽略项说明

`cpplint` 对 ROS 2 代码可能报以下内容，可按需在包内 `CPPLINT.cfg` 中放宽：

```ini
# src/patrol_robot_core/CPPLINT.cfg
filter=-build/c++11,-runtime/references,-legal/copyright
linelength=100
```

> 放宽必须有理由并写在注释里；不允许整包禁用所有检查。
> `-legal/copyright` 的理由：本项目约定注释全中文，文件头使用中文版权行，
> 版权声明与 Apache-2.0 许可证原文由仓库根目录 `LICENSE` 文件承载。
