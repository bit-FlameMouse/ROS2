## 2. 技术避坑清单（20 条）

> 按"踩坑概率 × 排查耗时"排序。**这 20 条是本项目最可能浪费时间的部分。**

### 坑 1：在回调里调用 `future.get()` 等待 Action 结果

**症状**：节点启动后完全没反应，没有报错，没有日志，`Ctrl+C` 才能退出。

**原因**：`async_send_goal` 返回的 future 需要一个执行器线程触发回调才能完成，
而你在回调里阻塞了那个线程。

**正确做法**：

```cpp
// ✗ 死锁
auto future = client_->async_send_goal(goal);
auto handle = future.get();     // 永久阻塞

// ✓ 非阻塞
client_->async_send_goal(goal, options);   // options 含 result_callback
// 之后通过 result_callback 更新标志，主循环轮询标志
```

**预防**：见 [04 §4.2](04-详细设计说明书.md)。

---

### 坑 2：单线程执行器下服务回调阻塞定时器

**症状**：调用 `/patrol/set_mode` 后，状态话题停止更新，机器人卡住不动。

**原因**：`MoveIt`… 不对，原因是服务回调执行时间长（如内部等 Action），
单线程执行器无法同时跑定时器。

**正确做法**：`rclcpp::executors::MultiThreadedExecutor executor(rclcpp::ExecutorOptions(), 2);`

---

### 坑 3：订阅者/发布者句柄没保存为成员

**症状**：订阅了话题但回调从不触发；节点日志正常。

**原因**：`create_subscription` 返回的 `SharedPtr` 是临时对象，语句结束即析构。

**正确做法**：句柄必须赋给成员变量，哪怕你不用它。

---

### 坑 4：`use_sim_time` 不一致

**症状**：TF 报 `extrapolation into the future`；Nav2 一直规划不出路径；
或者 `/clock` 明明在跑但节点用的是系统时间。

**排查**：

```bash
ros2 topic hz /clock                                  # 是否在发布
ros2 param get /patrol_node use_sim_time               # 期望 True
ros2 param get /controller_server use_sim_time         # 期望 True
ros2 param get /amcl use_sim_time                      # 期望 True
ros2 param get /robot_state_publisher use_sim_time     # 期望 True
```

**正确做法**：所有节点统一用同一个时间基准。launch 里用同一个 `use_sim_time` 变量传递。

---

### 坑 5：`/scan` 的 QoS 不匹配

**症状**：`ros2 topic list` 有 `/scan`，`ros2 topic echo /scan` 有数据，
但自己的节点订阅不到。

**原因**：你是 RELIABLE 订阅者，发布者是 BEST_EFFORT（或反之）。

**正确做法**：

```cpp
scan_sub_ = create_subscription<sensor_msgs::msg::LaserScan>(
  scan_topic, rclcpp::SensorDataQoS(),   // best_effort，兼容性最好
  std::bind(&SafetyGuardNode::onScan, this, std::placeholders::_1));
```

**排查命令**：`ros2 topic info /scan --verbose` 看双方的 QoS。

---

### 坑 6：安全标志晚启动收不到

**症状**：先启动 `safety_guard_node`，后启动 `patrol_node`，
`patrol_node` 有一段时间不知道当前安全状态（可能带着危险标志开始巡逻）。

**原因**：默认 QoS 是 VOLATILE，晚加入的订阅者收不到历史消息。

**正确做法**：紧急标志用 `transient_local`（详见 [05 §2.3](05-接口设计说明书.md)）。

```cpp
rclcpp::QoS emergency_qos(1);
emergency_qos.transient_local();
```

---

### 坑 7：两个节点同时发布 `/cmd_vel`

**症状**：机器人抖动、走走停停、行为不连续。

**原因**：安全节点和 Nav2 控制器同时在写 `/cmd_vel`。

**正确做法**：安全节点只发状态标志，由任务层决定动作（ADR-06）。
参数 `allow_cmd_vel_override` 默认 `false`。

**排查**：`ros2 topic info /cmd_vel --verbose` 看发布者列表。

---

### 坑 8：节点抢发 TF

**症状**：机器人位置在 RViz 里跳变。

**原因**：自研节点也发了 `map → odom`，与 AMCL 冲突。

**正确做法**：自研节点**绝不**发布 TF（见 [06 §6](06-坐标变换与TF设计.md)）。

---

### 坑 9：目标在 Nav2 激活前发送被静默丢弃

**症状**：`patrol_node` 日志显示"目标已发送"，但机器人不动，
也没收到任何 result。

**原因**：Nav2 的 Action Server 由生命周期节点提供，未 activate 前不响应。

**正确做法**：

```cpp
// 启动期：显式等待一次（10 s 超时，失败 FATAL 退出）——AS-60
if (!nav_->waitForServer(10s)) { ... }

// 运行期（tick 回调内）：非阻塞就绪检查，未就绪立即失败——AS-53 禁止回调内阻塞
if (!client_->action_server_is_ready()) { ... }   // 置 ERR_NAV_SERVER_UNAVAILABLE
```

配合 launch 中的 `TimerAction(period=8.0)` 延迟启动任务层（见 [04 §9.5](04-详细设计说明书.md)；
运行期非阻塞检查的豁免留痕见 04 §14.2 #1）。

---

### 坑 10：航点落在障碍物内 → 无限重试

**症状**：机器人卡在某处反复尝试，永远不前进。

**原因**：航点坐标不可达，Nav2 每次都 ABORTED。

**正确做法**：三重保护

1. `max_retries`：限制尝试次数；
2. `waypoint_timeout_sec`：限制单点耗时；
3. `skip_failed_waypoint=true`：超限后跳过。

**根本解决**：选航点时用 RViz 读坐标，确保在白色（空闲）区域且距墙 ≥ 0.5 m。

---

### 坑 11：重试时读到上一轮的旧结果

**症状**：某个航点明明失败了，状态却显示 SUCCEEDED。

**原因**：`NavClient` 内部状态还是上一次的结果，新目标发出后、
`goal_response_callback` 到达前，`tick()` 读到了旧的 SUCCEEDED。

**正确做法**：`sendGoal` 前先 `detach()` 重置状态，并为回调引入**代数（generation）守卫**
——cancel/detach 之后，旧目标的迟到响应/反馈/结果一律丢弃
（见 [04 §4.5](04-详细设计说明书.md)、§14.2 #2）。

---

### 坑 12：`cancel()` 时目标还没被接受

**症状**：调用 PAUSE 后机器人继续走。

**原因**：`goal_handle_` 还是 `nullptr`（服务器还没响应 goal），
`async_cancel_goal(nullptr)` 无效。

**正确做法**：回退到 `async_cancel_all_goals()`（K-15）；目标已处于终态或从未发送时
直接返回（空操作），避免噪声取消（04 §14.2 #3）。

---

### 坑 13：Marker 的 `ns` 冲突

**症状**：RViz 中只显示球体不显示文字，或反之。

**原因**：`patrol_waypoints` 和 `patrol_labels` 用了相同 ID 但不同 ns 才对；
如果 ns 相同，同 ID 的 Marker 会互相覆盖。

**正确做法**：不同用途用不同 `ns` + 相同 ID 空间。

---

### 坑 14：Marker 的 `frame_id` 与 RViz Fixed Frame 不一致

**症状**：RViz 里看不到 Marker，状态栏显示 "No transform"。

**正确做法**：Marker 用 `map`，RViz 的 Fixed Frame 也设 `map`。

---

### 坑 15：Marker 的 `orientation` 未初始化

**症状**：Marker 姿态随机，或 `SPHERE` 显示异常。

**正确做法**：显式设置 `m.pose.orientation.w = 1.0;`

---

### 坑 16：`get_parameter` 未先 `declare_parameter`

**症状**：节点启动时抛出 `rclcpp::exceptions::ParameterNotDeclaredException`。

**正确做法**：所有参数先 `declare_parameter(name, default)`，再读取。
统一在 `declareParameters()` 里完成。

---

### 坑 17：C++ 编译报"未使用参数"

**症状**：`-Wall -Wextra` 下出现 `unused parameter` 警告，违反零警告要求。

**正确做法**：省略参数名，或 `[[maybe_unused]]`，或真正用上参数。

---

### 坑 18：TurtleBot3 模型加载失败（Gazebo 找不到模型）

**症状**：Gazebo 打开后世界里没有机器人，终端报模型 URI 找不到。

**正确做法**：

```bash
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:/opt/ros/humble/share/turtlebot3_gazebo/models
echo $GAZEBO_MODEL_PATH    # 确认包含上述路径
```

若模型库损坏：`rm -rf ~/.gazebo/models` 后重启。

> **受限网络注意**：gzserver 启动时还会尝试访问在线模型库（models.gazebosim.org），
> 内网/无外网环境会卡住数分钟。本项目 `simulation.launch.py` 已内置离线加固
> （置空 `GAZEBO_MODEL_DATABASE_URI`，见 04 §14.2 #6）；手工启动 gazebo 时先
> `export GAZEBO_MODEL_DATABASE_URI=""`。

---

### 坑 19：仿真时间与真实时间混淆

**症状**：超时判断永远不触发，或者瞬间触发。

**原因**：用了 `std::chrono::system_clock` 而不是 `this->now()`。

**正确做法**：

```cpp
// ✓ 遵循 use_sim_time
const double elapsed = (now() - goal_start_).seconds();

// ✓ 成员初始化时指定时钟类型
rclcpp::Time wait_start_{0, 0, RCL_ROS_TIME};

// ✗ 错误
auto t = std::chrono::system_clock::now();
```

---

### 坑 20：改代码后行为不变

**症状**：修改了 C++ 源码，重新 launch 后行为还是旧的。

**原因**：① 忘记 `colcon build`；② 忘记 `source install/setup.bash`；
③ 有旧节点进程还在跑（同名的两个节点）。

**正确做法**：

```bash
cd ~/ros2_ws
colcon build --packages-select patrol_robot_core --symlink-install
source install/setup.bash
ros2 node list           # 确认没有重复节点
killall -9 gzserver gzclient rviz2   # 清理残留
```

## 3. 排障决策树

```
机器人不动
    │
    ├─ /patrol/status 有输出吗？
    │      ├─ 无 → patrol_node 没起来或崩溃 → 看节点日志、ros2 node list
    │      └─ 有 →
    │            ├─ mode 是什么？
    │            │     ├─ 0 (IDLE)   → 没发 START，调用服务 mode:0
    │            │     ├─ 3 (PAUSED) → 调用 RESUME
    │            │     ├─ 4 (SAFETY_HOLD) → 移除障碍或检查 /scan 数据
    │            │     ├─ 5 (FAILED) → 调用 RESET，检查 error_code
    │            │     └─ 1 (MOVING) → 目标已发，问题在 Nav2 侧 ↓
    │            └─ error_code 是多少？（见 05 §6.4）
    │
    └─ Nav2 侧验证（隔离测试）
           ros2 action send_goal /navigate_to_pose ... --feedback
               │
               ├─ 也走不动 → 问题在 Nav2/定位/TF
               │     ├─ ros2 topic hz /scan          雷达正常吗
               │     ├─ ros2 topic hz /clock         仿真时钟正常吗
               │     ├─ ros2 run tf2_tools view_frames   TF 树完整吗
               │     ├─ ros2 lifecycle get /bt_navigator  激活了吗
               │     └─ RViz 中 /scan 与地图对齐吗（定位是否收敛）
               │
               └─ 能走 → 问题在 patrol_node
                     ├─ action_name 参数是否为 navigate_to_pose
                     ├─ 日志中"目标已发送"是否出现
                     └─ /patrol/markers 是否显示当前目标（确认索引正确）
```

## 4. 应急预案卡（打印贴在桌上）

### 4.1 演示前 5 分钟发现跑不起来

```
1. 深呼吸，不要在演示中现场 debug
2. 若有快照 → 立即回滚到 03-demo-ready（约 3 分钟）
3. 若无快照 → 播放提前录好的 demo.mp4，边播边讲解架构
4. 话术："我准备了一段录屏，先从这里看整体效果，然后我们看代码。"
```

### 4.2 Gazebo 崩溃

```bash
killall -9 gzserver gzclient
rm -rf ~/.gazebo/lock
ros2 launch patrol_robot_bringup patrol.launch.py
```

### 4.3 定位丢失（机器人位姿跳到墙外）

```bash
# 方式 1：RViz 用 2D Pose Estimate 重新设定
# 方式 2：命令行重置
ros2 topic pub --once /initialpose geometry_msgs/msg/PoseWithCovarianceStamped \
"{header: {frame_id: 'map'}, pose: {pose: {position: {x: 0.0, y: 0.0}, orientation: {w: 1.0}}}}"
# 方式 3：停止巡逻，重新开始
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 3}"
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"
```

### 4.4 磁盘满

```bash
sudo apt clean
sudo journalctl --vacuum-size=200M
rm -rf ~/ros2_ws/build ~/ros2_ws/log
df -h /          # 确认
```

### 4.5 整个系统卡死无响应

```bash
# 从宿主机重启虚拟机（最可靠）
# 重启后：source 环境 → 重新 launch
```

## 5. 已知限制（诚实声明，不要掩盖）

| 编号 | 限制 | 原因 | 影响 |
| --- | --- | --- | --- |
| L-01 | 仅支持仿真，未在真机验证 | 时间约束（01 §2.2） | 迁移真车需重新标定雷达与底盘参数 |
| L-02 | 使用 TurtleBot3 官方模型，非自定义机器人 | 时间约束 | 无法展示 URDF 建模能力 |
| L-03 | 参数需重启节点生效，不支持动态修改 | 有意设计（05 §5.3） | 调参需重启，演示中不便 |
| L-04 | 单机器人，无多机协同 | 范围外 | 无影响 |
| L-05 | 不使用视觉传感器 | 范围外（列入 v0.3） | 演示维度单一 |
| L-06 | 未做安全认证级的功能安全设计 | 本项目为学习/展示性质 | 不可用于真实安全场景 |
| L-07 | 航点需要人工在地图上选取 | 未实现自动巡检路径生成 | 演示前需准备坐标 |
