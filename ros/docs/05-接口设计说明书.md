## 2. 话题接口

### 2.1 `/patrol/status` — 巡逻状态

| 项 | 内容 |
| --- | --- |
| 消息类型 | `patrol_interfaces/msg/PatrolStatus` |
| 方向 | `patrol_node` → 外部（发布） |
| 频率 | ≥ 1 Hz（参数 `status_publish_hz`，默认 1.0） |
| QoS | Reliability: RELIABLE；Durability: VOLATILE；History: KEEP_LAST(10) |
| 话题名 | 参数 `status_topic` 可覆盖（默认 `/patrol/status`） |
| 用途 | 上位机/日志/演示观察巡逻进度 |

**字段定义**：

| 字段 | 类型 | 含义 | 取值 |
| --- | --- | --- | --- |
| `header.stamp` | `builtin_interfaces/Time` | 发布时刻 | 仿真时间 |
| `header.frame_id` | `string` | 参考坐标系 | `map` |
| `mode` | `uint8` | 当前运行模式 | 0=IDLE, 1=MOVING, 2=WAITING, 3=PAUSED, 4=SAFETY_HOLD, 5=FAILED |
| `current_waypoint_index` | `uint32` | 当前目标航点索引 | 0 基 |
| `total_waypoints` | `uint32` | 航点总数 | ≥ 0 |
| `completed_waypoints` | `uint32` | 累计到达的航点数 | ≥ 0，含跨轮次累计 |
| `current_loop` | `uint32` | 已完成的循环轮次 | 0 表示第 1 轮进行中 |
| `retry_count` | `int32` | 当前航点已重试次数 | ≥ 0 |
| `distance_remaining` | `float32` | 距目标剩余距离（m） | ≥ 0；-1.0 表示未知 |
| `error_code` | `uint16` | 最近错误码 | 见 §3.1 |
| `error_message` | `string` | 最近错误描述 | 无错误时为空串 |

### 2.2 `/patrol/markers` — 航点可视化

| 项 | 内容 |
| --- | --- |
| 消息类型 | `visualization_msgs/msg/MarkerArray` |
| 方向 | `patrol_node` → RViz2 |
| 频率 | 事件驱动（状态迁移时发布），非周期 |
| QoS | Reliability: RELIABLE；Durability: **TRANSIENT_LOCAL**；History: KEEP_LAST(1) |
| 话题名 | 参数 `markers_topic` 可覆盖 |

**Marker 定义**：

| ns | id | type | 含义 |
| --- | --- | --- | --- |
| `patrol_waypoints` | 航点索引 | `DELETEALL`（仅首元素） | 清理上一帧 |
| `patrol_waypoints` | 航点索引 | `SPHERE` | 航点球体，`scale=0.25`，`z=0.15` |
| `patrol_labels` | 航点索引 | `TEXT_VIEW_FACING` | 文本 `WPn`，`scale.z=0.22`，`z=0.45` |

**颜色约定**：

| 状态 | RGB | 说明 |
| --- | --- | --- |
| 未访问 | (0.60, 0.60, 0.60) | 灰 |
| 当前目标 | (1.00, 0.85, 0.00) | 黄（在 MOVING/WAITING/PAUSED/SAFETY_HOLD 时生效） |
| 已完成 | (0.20, 0.85, 0.30) | 绿 |
| 文本 | (1.00, 1.00, 1.00) | 白 |

### 2.3 `/safety/emergency_stop` — 紧急停车标志

| 项 | 内容 |
| --- | --- |
| 消息类型 | `std_msgs/msg/Bool` |
| 方向 | `safety_guard_node` → `patrol_node` / 外部 |
| 发布频率 | **仅状态变化时发布**（边沿触发，非周期） |
| QoS | Reliability: RELIABLE；Durability: **TRANSIENT_LOCAL**；History: KEEP_LAST(1) |
| `true` 语义 | 前向扇区最小距离 < `stop_distance`，请求暂停导航 |
| `false` 语义 | 前向扇区最小距离 > `resume_distance`，可恢复导航 |
| 话题名 | 参数 `emergency_topic` 可覆盖 |

> **契约要点**：
> ① 这是**状态标志而非命令**——语义是"前方危险"，具体动作（cancel / 停车）由订阅方决定。
> ② 必须使用 `transient_local`，否则 `patrol_node` 启动晚于安全节点时会丢失当前状态，
> 导致机器人带着危险标志继续前进。
> ③ 订阅方必须容忍"长时间收不到消息"（标志未变化时不发布），
> 因此**必须**在启动时通过 `transient_local` 获取最新值，而不能依赖周期刷新。

### 2.4 `/safety/nearest_obstacle_distance` — 最近障碍距离

| 项 | 内容 |
| --- | --- |
| 消息类型 | `std_msgs/msg/Float32` |
| 方向 | `safety_guard_node` → 外部（调参/可视化用） |
| 频率 | 与 `/scan` 同频（约 5–10 Hz） |
| QoS | Reliability: RELIABLE；Durability: VOLATILE；History: KEEP_LAST(10) |
| 单位 | 米（m） |
| 特殊值 | `inf` = 扇区内无障碍；`0.0` = 未收到有效数据 |

**用途**：

- 用 `rqt_plot` 观察距离曲线，辅助调试阈值；
- 录制演示视频时展示数值变化；
- 作为 `/safety/emergency_stop` 的"可解释性"补充。

## 3. 服务接口

### 3.1 `/patrol/set_mode` — 巡逻模式控制

| 项 | 内容 |
| --- | --- |
| 服务类型 | `patrol_interfaces/srv/SetPatrolMode` |
| 方向 | 外部 → `patrol_node` |
| 服务名 | 参数 `mode_service` 可覆盖（默认 `/patrol/set_mode`） |
| QoS | 默认（服务不可配置 QoS） |
| 幂等性 | **是**（重复发同一请求不会产生额外副作用，见响应语义表） |

**请求字段**：

| 字段 | 类型 | 含义 | 取值 |
| --- | --- | --- | --- |
| `mode` | `uint8` | 目标模式 | 0=START, 1=PAUSE, 2=RESUME, 3=STOP, 4=RESET |

**响应字段**：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `success` | `bool` | 是否产生了有效状态变更 |
| `message` | `string` | `OK` / `NO_STATE_CHANGE` / `NO_WAYPOINTS` / `TIMEOUT`（服务侧等待 tick 处理超时）/ `未知的模式取值: N` |
| `current_mode` | `uint8` | 处理后的实际模式（对应 `PatrolStatus.mode`） |

**请求语义与前置条件**：

| mode | 前置状态 | 结果 | 失败 message |
| --- | --- | --- | --- |
| `START`(0) | IDLE 且航点有效 | → MOVING，发送当前航点目标 | `NO_WAYPOINTS`（航点无效） |
| `START`(0) | 非 IDLE | 状态不变 | `NO_STATE_CHANGE` |
| `PAUSE`(1) | MOVING / WAITING | → PAUSED（记录暂停前状态），取消导航目标（无活动目标时为空操作） | `NO_STATE_CHANGE` |
| `RESUME`(2) | PAUSED | 暂停前在 MOVING → 回到 MOVING，重新发送当前航点目标；暂停前在 WAITING → 回到 WAITING，**重新计时**停留（不重发目标、不重复计数） | `NO_STATE_CHANGE` |
| `STOP`(3) | 任意非 IDLE | → IDLE，取消目标，索引归零 | `NO_STATE_CHANGE`（已在 IDLE） |
| `RESET`(4) | 任意 | 清零统计/错误；若为 FAILED 则 → IDLE | 恒为 `OK` |

**调用示例**：

```bash
# 开始巡逻
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"

# 暂停
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 1}"

# 继续
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 2}"

# 停止
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 3}"

# 复位
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 4}"
```

### 3.2 客户端的正确处理方式

```bash
# ✓ 正确：检查 success 与 current_mode
ros2 service call /patrol/set_mode patrol_interfaces/srv/SetPatrolMode "{mode: 0}"
# 期望输出：success=True message='OK' current_mode=1
```

```cpp
// ✓ C++ 客户端示例
auto client = node->create_client<patrol_interfaces::srv::SetPatrolMode>("/patrol/set_mode");
if (!client->wait_for_service(std::chrono::seconds(3))) {
  RCLCPP_ERROR(node->get_logger(), "服务不可用");
  return;
}
auto req = std::make_shared<patrol_interfaces::srv::SetPatrolMode::Request>();
req->mode = patrol_interfaces::srv::SetPatrolMode::Request::REQ_START;
auto future = client->async_send_request(req);
```

## 4. 依赖接口使用约定（外部）

### 4.1 `/navigate_to_pose`（Nav2 Action）— 本项目最关键的依赖接口

| 项 | 内容 |
| --- | --- |
| 类型 | `nav2_msgs/action/NavigateToPose` |
| 服务端 | `nav2_bt_navigator`（由 `lifecycle_manager` 激活） |
| 客户端 | `patrol_node`（通过 `NavClient` 封装） |
| Action 名 | 参数 `action_name` 可覆盖（默认 `navigate_to_pose`） |

**Goal 字段（本项目使用的部分）**：

| 字段 | 类型 | 本项目取值 |
| --- | --- | --- |
| `pose.header.frame_id` | `string` | `map`（参数 `global_frame`） |
| `pose.header.stamp` | `Time` | `node->now()`（仿真时间） |
| `pose.pose.position.x/y` | `double` | 航点配置值 |
| `pose.pose.position.z` | `double` | `0.0` |
| `pose.pose.orientation` | `Quaternion` | 由 `yaw` 经 `tf2::Quaternion::setRPY(0,0,yaw)` 生成 |
| `behavior_tree` | `string` | 空串（使用 Nav2 默认行为树） |

**Feedback 字段（本项目消费的部分）**：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `distance_remaining` | `float32` | 转发到 `PatrolStatus.distance_remaining` |
| `number_of_recoveries` | `int16` | 记录恢复行为次数，用于识别"挣扎中"的导航 |
| `navigation_time` | `Duration` | 保留，可用于超时判断（本项目用自身计时器） |
| `estimated_time_remaining` | `Duration` | 保留 |

**Result 字段**：`nav2_msgs/action/NavigateToPose` 的 Result 为空（`std_msgs/Empty`），
**成功/失败必须通过 `rclcpp_action::ResultCode` 判断**，而不是读 Result 内容。

**结果码到本项目的映射**：

| `ResultCode` | `NavTaskState` | 巡逻节点处理 |
| --- | --- | --- |
| `SUCCEEDED` | `SUCCEEDED` | 触发 `GOAL_SUCCEEDED`，进入 WAITING |
| `ABORTED` | `ABORTED` | 触发 `GOAL_FAILED`，进入重试 |
| `CANCELED` | `CANCELED` | 若为主动取消则忽略；否则按失败处理 |
| `UNKNOWN` | `ABORTED`（保守处理） | 触发 `GOAL_FAILED` |

**调用示例（命令行，用于隔离验证 Nav2 侧是否正常）**：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: 'map'}, pose: {position: {x: 1.0, y: 0.5}, orientation: {w: 1.0}}}}" \
  --feedback
```

> **排障黄金法则**：如果上面这条命令都走不通，问题一定在 Nav2/定位/TF，而不在自研代码。
> 先用命令行确认 Nav2 正常，再查自研节点。

### 4.2 `/scan`（激光雷达）

| 项 | 内容 |
| --- | --- |
| 类型 | `sensor_msgs/msg/LaserScan` |
| 发布者 | Gazebo 的 `ray` 传感器插件 |
| 订阅者 | `safety_guard_node`、`slam_toolbox`、Nav2 代价地图 |
| 频率 | 约 5–10 Hz（仿真） |
| 订阅 QoS | 必须用 `rclcpp::SensorDataQoS()`（BEST_EFFORT） |
| TurtleBot3 参数 | `angle_min=-π`, `angle_max=π`, `angle_increment≈0.0175 rad`（约 360 点/圈）, `range_min=0.12`, `range_max=3.5` |

> **QoS 兼容性说明**：BEST_EFFORT 订阅者可以接收 RELIABLE 发布者的数据（订阅者要求更弱），
> 反之则不行。因此统一用 `SensorDataQoS` 最安全。

### 4.3 `/odom`（里程计）

| 项 | 内容 |
| --- | --- |
| 类型 | `nav_msgs/msg/Odometry` |
| 发布者 | Gazebo 的 `planar_move` / 差速驱动插件 |
| 订阅者 | `slam_toolbox`、Nav2、本项目（预留） |
| 坐标系 | `header.frame_id = odom`，`child_frame_id = base_footprint` |
| QoS | 默认 RELIABLE |

### 4.4 `/map`（占用栅格地图）

| 项 | 内容 |
| --- | --- |
| 类型 | `nav_msgs/msg/OccupancyGrid` |
| 发布者 | `nav2_map_server`（导航阶段）/ `slam_toolbox`（建图阶段） |
| 分辨率 | 0.05 m/格 |
| QoS | **TRANSIENT_LOCAL**（订阅者若用 VOLATILE 可能收不到） |
| 约束 | 两个发布者**不得同时运行**（§6.3 单一地图源） |

### 4.5 `/cmd_vel`（速度指令）

| 项 | 内容 |
| --- | --- |
| 类型 | `geometry_msgs/msg/Twist` |
| 唯一发布者 | Nav2 `controller_server`（正常情况下） |
| 例外 | `safety_guard_node` 在 `allow_cmd_vel_override=true` 且紧急时发布零速 |
| 约束 | **严禁**在其他模块中发布 `/cmd_vel`（NFR-09） |

### 4.6 `/clock`（仿真时钟）

| 项 | 内容 |
| --- | --- |
| 类型 | `rosgraph_msgs/msg/Clock` |
| 发布者 | Gazebo `ros_gz`/`gazebo_ros` 插件 |
| 用途 | 所有节点 `use_sim_time=true` 时的时间源 |
| 校验 | `ros2 topic hz /clock` 应有输出；若无输出说明 `use_sim_time` 配置错误 |

## 5. 参数接口

### 5.1 `patrol_node` 参数

| 参数名 | 类型 | 默认值 | 取值范围 | 说明 | 动态可改 |
| --- | --- | --- | --- | --- | --- |
| `waypoint_x` | `double[]` | `[]` | 任意有限数 | 航点 x 坐标（m） | ✗ 需重启 |
| `waypoint_y` | `double[]` | `[]` | 任意有限数 | 航点 y 坐标（m） | ✗ |
| `waypoint_yaw` | `double[]` | `[]` | 任意有限数 | 航点偏航角（rad），自动归一化 | ✗ |
| `waypoint_wait` | `double[]` | `[]` | ≥ 0 | 航点停留时间（s） | ✗ |
| `loop_count` | `int` | `0` | ≥ 0 | 0 = 无限循环 | ✗ |
| `max_retries` | `int` | `2` | ≥ 1 | 单航点最大尝试次数（含首次） | ✗ |
| `skip_failed_waypoint` | `bool` | `true` | — | 重试超限后跳过 | ✗ |
| `waypoint_timeout_sec` | `double` | `60.0` | ≥ 0（0 = 不限） | 单航点超时 | ✗ |
| `auto_start` | `bool` | `false` | — | 启动后自动巡逻 | ✗ |
| `global_frame` | `string` | `"map"` | — | 目标位姿参考坐标系 | ✗ |
| `action_name` | `string` | `"navigate_to_pose"` | — | Nav2 Action 名 | ✗ |
| `status_topic` | `string` | `"/patrol/status"` | — | 状态话题名 | ✗ |
| `markers_topic` | `string` | `"/patrol/markers"` | — | 可视化话题名 | ✗ |
| `mode_service` | `string` | `"/patrol/set_mode"` | — | 控制服务名 | ✗ |
| `safety_topic` | `string` | `"/safety/emergency_stop"` | — | 安全标志来源 | ✗ |
| `use_safety_hold` | `bool` | `true` | — | 是否响应安全标志 | ✗ |
| `tick_period_ms` | `int` | `100` | 10–1000 | 状态机 tick 周期 | ✗ |
| `status_publish_hz` | `double` | `1.0` | 0.1–20 | 状态发布频率 | ✗ |

> **约束**：4 个 `waypoint_*` 数组长度必须完全一致，且 `waypoint_wait` 各元素 ≥ 0，
> 否则节点启动时报 ERROR，且 START 服务返回 `NO_WAYPOINTS`（VL-01 / VL-02 / VL-03）。

### 5.2 `safety_guard_node` 参数

| 参数名 | 类型 | 默认值 | 取值范围 | 说明 | 动态可改 |
| --- | --- | --- | --- | --- | --- |
| `scan_topic` | `string` | `"scan"` | — | 激光话题名 | ✗ |
| `fov_deg` | `double` | `60.0` | (0, 360] | 前向扇区总视场角（度） | ✗ |
| `range_min` | `double` | `0.02` | ≥ 0 | 有效距离下限（m） | ✗ |
| `range_max` | `double` | `3.50` | > range_min | 有效距离上限（m） | ✗ |
| `stop_distance` | `double` | `0.30` | > 0 | 触发紧急的距离阈值（m） | ✗ |
| `resume_distance` | `double` | `0.60` | **> stop_distance** | 解除紧急的距离阈值（m） | ✗ |
| `emergency_topic` | `string` | `"/safety/emergency_stop"` | — | 标志话题名 | ✗ |
| `distance_topic` | `string` | `"/safety/nearest_obstacle_distance"` | — | 距离话题名 | ✗ |
| `allow_cmd_vel_override` | `bool` | `false` | — | 是否允许直接发 `/cmd_vel` | ✗ |
| `cmd_vel_topic` | `string` | `"cmd_vel"` | — | 接管发布的话题名（仅当 `allow_cmd_vel_override=true` 时创建发布者） | ✗ |

> **强校验**：`resume_distance <= stop_distance` 时节点**拒绝启动**（抛异常退出），
> 而不是静默降级——这是 NFR-09 的要求（参数非法必须显式失败）。

### 5.3 运行时查看与修改参数

```bash
# 查看全部参数
ros2 param list /patrol_node
ros2 param dump /patrol_node

# 查看单个参数
ros2 param get /patrol_node waypoint_x

# 修改日志级别（唯一支持的运行时调整）
ros2 param set /patrol_node log_level debug
```

> **说明**：本项目参数均为启动期参数（声明后未注册 `on_set_parameters` 回调）。
> 运行时修改会返回 `successful=False`，这是**有意设计**：
> 航点与阈值在运行中变化会让状态机语义复杂化。若需改航点，修改 YAML 后重启节点即可。
> 动态参数支持列入 v0.3 Roadmap。

## 6. 接口约束与契约

### 6.1 命名约定

| 类别 | 命名规则 | 示例 |
| --- | --- | --- |
| 自研话题 | `/<模块>/<对象>`，小写下划线 | `/patrol/status`、`/safety/emergency_stop` |
| 自研服务 | `/<模块>/<动词>` | `/patrol/set_mode` |
| 外部话题 | 沿用 ROS/Nav2 惯例，不加前缀 | `/scan`、`/odom`、`/cmd_vel` |
| 节点名 | 小写下划线，与包名风格一致 | `patrol_node`、`safety_guard_node` |

### 6.2 QoS 策略矩阵

| 接口 | Reliability | Durability | History | Depth | 理由 |
| --- | --- | --- | --- | --- | --- |
| `/patrol/status` | RELIABLE | VOLATILE | KEEP_LAST | 10 | 周期状态，丢一帧可接受 |
| `/patrol/markers` | RELIABLE | **TRANSIENT_LOCAL** | KEEP_LAST | 1 | 晚启动的 RViz 也要看到航点 |
| `/safety/emergency_stop` | RELIABLE | **TRANSIENT_LOCAL** | KEEP_LAST | 1 | 安全状态必须可靠且可回溯 |
| `/safety/nearest_obstacle_distance` | RELIABLE | VOLATILE | KEEP_LAST | 10 | 高频数值，用于绘图 |
| `/scan`（订阅端） | BEST_EFFORT | VOLATILE | KEEP_LAST | 5 | `SensorDataQoS`，兼容性最好 |
| `/map`（订阅端） | RELIABLE | TRANSIENT_LOCAL | KEEP_LAST | 1 | 与 map_server 发布端匹配 |

### 6.3 单一权威原则（Single Source of Truth）

| 数据 | 唯一权威 | 违规风险 |
| --- | --- | --- |
| `/cmd_vel` | Nav2 `controller_server` | 控制权竞争 → 机器人抖动 |
| `map → odom` TF | Nav2 `amcl` | TF 树冲突 → 定位跳变 |
| `odom → base_footprint` TF | Gazebo 差速插件 | 同上 |
| `/map` | `map_server`（导航）或 `slam_toolbox`（建图），二者不同时运行 | 地图冲突 → 路径规划混乱 |
| 时间 | `/clock`（仿真） | 时间戳不一致 → TF 超时 |

### 6.4 错误码定义

| 码值 | 常量名 | 触发条件 | 恢复方式 |
| --- | --- | --- | --- |
| 0 | `ERR_NONE` | 无错误 | — |
| 1 | `ERR_NO_WAYPOINTS` | 航点参数无效，START 被拒 | 修正 YAML 后重启 |
| 2 | `ERR_NAV_SERVER_UNAVAILABLE` | 启动期等待 Action Server 超时（10 s）；或运行期发送目标时就绪检查失败 | 确认 Nav2 已启动后重启 patrol_node |
| 3 | `ERR_WAYPOINT_TIMEOUT` | 单航点导航超过 `waypoint_timeout_sec` | 自动重试；持续失败需检查航点可达性 |
| 4 | `ERR_MAX_RETRIES_EXCEEDED` | 重试次数超限 | `RESET` + 修正航点 |
| 5 | `ERR_GOAL_REJECTED` | Nav2 拒绝目标 | 检查目标是否在代价地图可通行区域 |

> 错误码在 `PatrolStatus.error_code` 中发布，并在日志中以 WARN/ERROR 记录。
> **设计原则**：错误码只增不减，含义不随版本变化（向后兼容）。

### 6.5 接口版本与兼容性

| 项 | 策略 |
| --- | --- |
| 接口版本 | 与包版本同步（当前 0.1.0） |
| 向后兼容 | 新增字段只允许追加在 `msg` 末尾；不得删除或改变已有字段类型 |
| 破坏性变更 | 必须提升主版本号并在 14 文档中记录迁移说明 |
| 常量值 | `MODE_*` / `ERR_*` / `REQ_*` 的数值一经发布不得修改 |
| 话题/服务名 | 改名视为破坏性变更；如需改名，必须通过参数保持旧名可用一个版本周期 |

## 7. 接口验证方法

| 编号 | 接口 | 验证命令 | 期望 |
| --- | --- | --- | --- |
| IV-01 | 自定义消息存在 | `ros2 interface show patrol_interfaces/msg/PatrolStatus` | 输出字段与 §2.1 一致 |
| IV-02 | 自定义服务存在 | `ros2 interface show patrol_interfaces/srv/SetPatrolMode` | 输出字段与 §3.1 一致 |
| IV-03 | 状态话题 | `ros2 topic echo /patrol/status` | 1 Hz 输出，`mode` 随巡逻变化 |
| IV-04 | 状态频率 | `ros2 topic hz /patrol/status` | ≈ 1.0 Hz |
| IV-05 | Marker 话题 | `ros2 topic echo /patrol/markers --once` | 含 `patrol_waypoints` 与 `patrol_labels` |
| IV-06 | Marker QoS | `ros2 topic info /patrol/markers --verbose` | Durability = TRANSIENT_LOCAL |
| IV-07 | 安全标志 QoS | `ros2 topic info /safety/emergency_stop --verbose` | Durability = TRANSIENT_LOCAL |
| IV-08 | 安全标志变化 | 手动发布 `ros2 topic pub --once /safety/emergency_stop std_msgs/msg/Bool "{data: true}"` | patrol_node 日志出现"安全标志变化"并暂停导航 |
| IV-09 | 服务 START | `ros2 service call ... "{mode: 0}"` | `success=True, current_mode=1` |
| IV-10 | 服务幂等 | 连续两次 `START` | 第二次 `success=False, message='NO_STATE_CHANGE'` |
| IV-11 | 参数校验 | 把 `waypoint_x` 改成长度与 y 不同 | 启动日志 ERROR，START 返回 `NO_WAYPOINTS` |
| IV-12 | 安全参数校验 | 设 `stop_distance=0.8, resume_distance=0.6` | 节点抛异常退出，日志 FATAL |
| IV-13 | Nav2 Action 可达 | `ros2 action list \| grep navigate_to_pose` | 列出 `/navigate_to_pose` |
| IV-14 | Nav2 Action 手动验证 | `ros2 action send_goal ...`（§4.1） | 机器人移动到指定点 |
