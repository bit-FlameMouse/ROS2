## 1. 环境基线

本项目**只**在以下组合上验证。ROS 2 的发行版与 Ubuntu 版本强绑定，混用会出现编译与运行期问题。

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Ubuntu | 22.04.5 LTS (Jammy Jellyfish) | Humble 官方支持的 LTS |
| ROS 2 | Humble Hawksbill | LTS，支持至 2027-05 |
| Gazebo | Classic 11 | **重要**：Humble 下 TurtleBot3 仿真使用 Gazebo Classic；不要安装 `ros-humble-ros-gz` 系列（那是 gz-sim / Ignition） |
| TurtleBot3 | Burger | `TURTLEBOT3_MODEL=burger` |
| 编译器 | GCC 11.4 | Ubuntu 22.04 自带 |
| C++ 标准 | C++17 | `-std=c++17` |
| CMake | 3.22.1 | Ubuntu 22.04 自带 |
| Python | 3.10 | 仅用于工具链，不用于本项目业务代码 |
| 中间件 | Fast DDS（默认）/ CycloneDDS（推荐） | 见 §5.4 |

### 1.1 为什么必须用 Ubuntu 22.04

ROS 2 Humble 的二进制包只对 Ubuntu 22.04 发布（另有 RHEL/Windows 的实验性支持，但 Gazebo 与 TurtleBot3 栈不完整）。
更高版本（24.04）对应 Jazzy，`ros-humble-*` 包无法直接安装。

## 2. 运行环境方案选型

开发主机为 Windows，必须额外提供 Linux 环境。三种方案对比：

| 方案 | 优点 | 缺点 | 推荐度 |
| --- | --- | --- | --- |
| **A. VMware Workstation（推荐）** | 3D 加速稳定、快照回滚、可整机拷贝备份、Gazebo 渲染流畅 | 占磁盘 40 GB+，需分配一半内存 | ★★★★★ |
| B. VirtualBox | 免费、界面友好 | 3D 加速较弱，Gazebo 常掉帧；USB/显卡驱动偶有问题 | ★★★ |
| C. 双系统（Ubuntu 实机） | 性能最好，接近真机体验 | 分区有风险、切换麻烦、Windows 与 Linux 文件互访不便 | ★★★ |
| D. WSL2（Ubuntu 22.04） | 启动快、与 Windows 文件互访方便 | Gazebo GUI 需 WSLg，渲染性能差且常有 OpenGL 问题；**不推荐用于本项目演示** | ★★ |

### 2.1 本方案选用：VMware Workstation + Ubuntu 22.04

#### 虚拟机配置建议

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| CPU | 4 核（物理核，非超线程计数） | Nav2 生命周期管理器并发激活多个节点，2 核会明显卡顿 |
| 内存 | 8 GB（宿主 16 GB 以上）；宿主 16 GB 以下给 6 GB | Gazebo + Nav2 + RViz 常驻约 4–5 GB |
| 磁盘 | 60 GB（SCSI，单文件便于移动） | 系统 20 GB + ROS 20 GB + 地图/录屏/快照 20 GB |
| 显卡 | **开启「加速 3D 图形」**，显存 1 GB+ | 关闭会导致 Gazebo 无法渲染或帧率极低 |
| 网络 | NAT（默认） | 无需外部访问机器人 |
| 共享文件夹 | 开启（`/mnt/hgfs/`） | 仅用于传文件，**不要把 ROS 工作空间放在共享目录**（inotify 与符号链接不可靠） |

> **重要**：ROS 工作空间必须放在虚拟机本地磁盘（如 `~/ros2_ws`），
> 不要放在 Windows 共享目录。共享目录的文件系统不支持可靠的符号链接与文件监控，
> 会导致 `colcon build --symlink-install` 行为异常。

#### 安装后必做的 5 项虚拟机优化

```bash
# 1. 安装 open-vm-tools（共享剪贴板 / 拖拽 / 自适应分辨率）
sudo apt update && sudo apt install -y open-vm-tools open-vm-tools-desktop

# 2. 关闭 Ubuntu 自动休眠与锁屏（演示时避免黑屏）
gsettings set org.gnome.desktop.session idle-delay 0
gsettings set org.gnome.desktop.screensaver lock-enabled false

# 3. 提升 VMware 显卡 3D 性能（可选，写入 /etc/environment）
#    SVGA_VGPU10=0  —— 使用较新的 SVGA3D，部分环境帧率更好
echo 'SVGA_VGPU10=0' | sudo tee -a /etc/environment

# 4. 验证 3D 加速是否可用
sudo apt install -y mesa-utils && glxinfo | grep -i "OpenGL renderer"
# 期望出现 llvmpipe（软件渲染，能跑但慢）或 SVGA3D / VMware（硬件加速，理想）

# 5. 关闭 unattended-upgrades，避免演示中途弹窗升级
sudo systemctl disable --now unattended-upgrades
```

## 3. Ubuntu 22.04 基础配置

### 3.1 更换 APT 源为国内镜像（加速）

```bash
# 备份原源
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

# 替换为清华镜像（Ubuntu 22.04 / jammy）
sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g; s|http://security.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list

sudo apt update && sudo apt upgrade -y
```

### 3.2 基础工具

```bash
sudo apt install -y \
  build-essential cmake git curl wget gnupg lsb-release \
  python3-pip python3-colcon-common-extensions python3-rosdep \
  python3-argcomplete terminator tree htop net-tools \
  mesa-utils
```

> `terminator` 用于同时开多个终端跑不同节点，演示时比多窗口更整洁。也可用 VSCode 集成终端。

## 4. ROS 2 Humble 安装

### 4.1 方式一：官方 deb 安装（推荐，可控）

```bash
# 1. 启用 universe 仓库
sudo apt install -y software-properties-common
sudo add-apt-repository universe

# 2. 添加 ROS 2 GPG Key
sudo apt update && sudo apt install -y curl
sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
  -o /usr/share/keyrings/ros-archive-keyring.gpg

# 3. 添加 ROS 2 apt 源（使用清华镜像加速）
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
https://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
  | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null

# 4. 安装
sudo apt update
sudo apt install -y ros-humble-desktop        # 含 RViz2、Demos、rclcpp（约 2 GB）
sudo apt install -y ros-dev-tools             # 含 colcon、rosdep、ros2cli 扩展
```

### 4.2 方式二：鱼香 ROS 一键安装（备选，快但黑盒）

```bash
wget http://fishros.com/install -O fishros && bash fishros
# 按提示选择：1(安装) → 3(ROS2) → 1(humble) → 换源 → 安装桌面版
```

> 一键脚本适合快速起环境，但**排障时难以定位问题**。生产/演示环境建议用 4.1 的官方方式。

### 4.3 环境变量配置

```bash
# 写入 ~/.bashrc（注意顺序：先 ROS，再工作空间）
cat >> ~/.bashrc << 'EOF'

# ===== ROS 2 Humble =====
source /opt/ros/humble/setup.bash
source /usr/share/gazebo/setup.sh

# ===== TurtleBot3 仿真 =====
export TURTLEBOT3_MODEL=burger
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:/opt/ros/humble/share/turtlebot3_gazebo/models

# ===== DDS 配置 =====
export ROS_DOMAIN_ID=30          # TurtleBot3 官方示例使用 30；同网段多人时须各自不同
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

# ===== 项目工作空间（按需修改）=====
# source ~/ros2_ws/install/setup.bash
EOF

source ~/.bashrc
```

> **`ROS_DOMAIN_ID` 提示**：同一局域网内不同人使用相同 domain 会互相看见对方的节点，
> 在教室/多人环境会造成 `ros2 topic list` 出现一堆陌生话题。独自开发时保持 30 即可。

### 4.4 初始化 rosdep

```bash
sudo rosdep init
rosdep update
```

> 若 `rosdep update` 因网络失败，可配置代理或使用 `rosdepc`（鱼香 ROS 的国内源版本）。

### 4.5 安装验证

```bash
ros2 doctor            # 期望：无 error（warning 可接受）
ros2 pkg list | head   # 应列出 ament_cmake、rclcpp 等
ros2 run demo_nodes_cpp talker   # 另开终端 ros2 topic echo /chatter
```

### 5.2 一键安装脚本

仓库提供 `scripts/install_deps.sh`：

```bash
#!/usr/bin/env bash
# scripts/install_deps.sh
# 用途：安装本项目全部运行时与编译依赖
set -euo pipefail

if [ "${ROS_DISTRO:-}" != "humble" ]; then
  echo "错误：请先 source /opt/ros/humble/setup.bash" >&2

echo "==> 更新 apt 索引"
sudo apt update

echo "==> 安装 Gazebo 与 TurtleBot3 仿真栈"
sudo apt install -y \

  ros-humble-turtlebot3 \
  ros-humble-turtlebot3-msgs \
  ros-humble-turtlebot3-simulations \
  ros-humble-turtlebot3-navigation2

echo "==> 安装 Nav2 与 SLAM"
sudo apt install -y \
  ros-humble-navigation2 \
  ros-humble-nav2-bringup \
  ros-humble-nav2-msgs \
  ros-humble-slam-toolbox

echo "==> 安装 TF / 可视化 / 中间件"
sudo apt install -y \
  ros-humble-tf2 ros-humble-tf2-ros ros-humble-tf2-geometry-msgs \
  ros-humble-tf2-tools ros-humble-visualization-msgs \
  ros-humble-rmw-cyclonedds-cpp \
  ros-humble-teleop-twist-keyboard

echo "==> 安装测试与规范检查工具"
sudo apt install -y \
  ros-humble-ament-cmake-gtest \
  ros-humble-ament-lint-auto \
  ros-humble-ament-lint-common

echo "==> 用 rosdep 补齐剩余依赖"
sudo rosdep init 2>/dev/null || true
rosdep update || echo "警告：rosdep update 失败，请检查网络"
rosdep install --from-paths src --ignore-src -r -y || true

echo "==> 依赖安装完成"
```

## 7. 常见环境问题排查

### 问题 1：Gazebo 打开黑屏 / 无机器人

**原因**：模型路径未设置，或 3D 加速不可用。

```bash
# 检查模型路径
echo $GAZEBO_MODEL_PATH
# 应为 /opt/ros/humble/share/turtlebot3_gazebo/models

# 手动补充
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:/opt/ros/humble/share/turtlebot3_gazebo/models

# 检查渲染
glxinfo | grep "OpenGL renderer"
```

若 `GLX` 报错，在 VMware 中开启 3D 加速，或改用软件渲染：

```bash
export LIBGL_ALWAYS_SOFTWARE=1   # 帧率低但能跑，仅作应急
```

### 问题 2：`[gazebo-1] process has died` 或 GAZEBO 崩溃

```bash
# 清理残留进程
killall -9 gzserver gzclient gazebo 2>/dev/null
# 删除锁文件
rm -rf ~/.gazebo/lock ~/.ignition 2>/dev/null
# 若模型库损坏，重下
rm -rf ~/.gazebo/models && ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
```

> **受限网络注意**：gzserver 启动时会尝试访问在线模型库（models.gazebosim.org），
> 内网/无外网环境下会阻塞数分钟。手工启动前 `export GAZEBO_MODEL_DATABASE_URI=""`；
> 本仓库 `simulation.launch.py` 已内置该加固（见 04 §14.2 #6）。

### 问题 3：机器人掉进地面 / 抖动

**原因**：虚拟机 CPU 性能不足导致物理步进跟不上，或 `use_sim_time` 不一致。

- 提高虚拟机 CPU 核心数与优先级。
- 在 Gazebo 中降低 `real_time_update_rate`（World → Physics）。
- 确认所有节点 `use_sim_time:=true`。

### 问题 4：`ros2 topic list` 看到不认识的话题

**原因**：`ROS_DOMAIN_ID` 与同网段其他人冲突。

```bash
export ROS_DOMAIN_ID=$((RANDOM % 100 + 1))   # 临时换一个
# 或长期写入 .bashrc
```

### 问题 5：`Package 'turtlebot3_gazebo' not found`

```bash
# 确认安装
dpkg -l | grep turtlebot3
# 若缺失
sudo apt install -y ros-humble-turtlebot3 ros-humble-turtlebot3-simulations
# 确认 source
source /opt/ros/humble/setup.bash && ros2 pkg list | grep turtlebot3
```

### 问题 6：`colcon build` 报缺少 `nav2_msgs`

```bash
sudo apt install -y ros-humble-nav2-msgs ros-humble-navigation2
```

### 问题 7：虚拟机磁盘占满

```bash
# 清理 apt 缓存与日志
sudo apt clean
sudo journalctl --vacuum-size=200M
# 清理 colcon 中间产物
rm -rf build/ install/ log/
```

### 问题 8：`use_sim_time` 相关的 TF 超时警告

表现为 `Lookup would require extrapolation into the future` 或
`TF_OLD_DATA ignoring data from the past`。

- 确认 Gazebo 在发布 `/clock`：`ros2 topic hz /clock`
- 确认每个节点都设置了 `use_sim_time:=true`
- 详见 [06 坐标变换与 TF 设计](06-坐标变换与TF设计.md) §5

## 8. 目录与工作空间约定

```bash
# 创建工作空间（路径可自定，推荐 ~/ros2_ws）
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src

# 方式 A：Git 克隆（推荐）
git clone <your-repo-url> ros2-patrol-robot-sim
ln -s ros2-patrol-robot-sim/src/* .    # 或直接把 src 内容作为工作空间 src

# 方式 B：手工拷贝（从共享目录复制到本地磁盘，不要直接在共享目录编译）
cp -r /mnt/hgfs/ROS展示项目/src/* ~/ros2_ws/src/

# 编译
cd ~/ros2_ws
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

| 目录 | 内容 | 是否纳入 Git |

## 9. 开发工具建议

| 工具 | 用途 | 安装 |
| --- | --- | --- |
| VSCode + ROS 扩展 | 代码编辑、CMake 智能提示 | `sudo snap install code --classic` |

## 10. 环境快照建议（重要）

环境搭建成功后，**立刻创建虚拟机快照**，命名如 `env-humble-ok`。
后续任何"调崩了"的情况都能 5 分钟内回滚，这是 3 天交付周期里最重要的一条风险管理措施。

快照策略：

| 快照名 | 时机 | 用途 |
| --- | --- | --- |
| `00-clean-ubuntu` | 系统装好、未装 ROS | 极端回滚 |
| `01-ros-humble-ok` | ROS 2 装好并通过 V-01~V-04 | 环境基线 |
| `02-deps-ok` | 全部依赖装好并通过 V-05~V-11 | **日常开发起点** |
| `03-demo-ready` | 演示前夕，功能全通 | 演示兜底 |
