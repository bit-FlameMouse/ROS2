## 0. 本文档的定位

本项目有三份容易混淆的文档，分工必须清楚：

| 文档 | 回答的问题 | 性质 | 粒度 |
| --- | --- | --- | --- |
| **02 系统架构设计说明书** | 「系统**长什么样**、**为什么**这么设计」 | 描述性（Descriptive） | 层 / 包 / 节点 / 场景 |
| **16 架构规范与设计约束**（本文档） | 「架构上**必须**怎么做才不算跑偏」 | **规范性（Normative）** | 约束条款（可判定） |
| **07 C++ 开发规范与编码指南** | 「每一行 C++ **怎么写**」 | 规范性（Normative） | 命名 / 内存 / 格式 / Git |

一句话区分：

> **02 是「设计」，16 是「架构上的不许」，07 是「代码上的不许」。**
> 02 变更 = 架构演进（需 ADR）；16/07 违反 = 缺陷（需整改）。

**为什么单独要一份 16**：架构决策写在 02 里是「叙述」，无法在评审时判定是否被违反。
本文档把 02 中的架构意图**翻译成带编号、可检查、可追溯的强制条款**，使架构可以被 Code Review、
被脚本检查（§15 架构适应度函数）、被验收清单逐条核对。

## 1. 规范等级与编号

### 1.1 等级定义

| 等级 | 含义 | 违反后果 |
| --- | --- | --- |
| **MUST**（L1 强制） | 不可协商的硬约束 | 代码不得合入；架构评审不通过 |
| **MUST NOT**（L1 禁止） | 明确禁止的行为 | 同上 |
| **SHOULD**（L2 建议） | 默认遵守，偏离需说明理由 | 需在 PR 描述或 14 文档中登记理由 |
| **MAY**（L3 可选） | 允许的自由度 | 无 |

### 1.2 编号规则

- 架构规范条款编号为 **`AS-xx`**（Architecture Specification），全局唯一、连续。
- 引用写法：`AS-36`；跨文档引用写作「16 §8 AS-36」。
- 条款**只增不删**：废弃条款标记为 `[DEPRECATED]` 并保留编号，不得回收复用。
- 编号含义一经发布不得改变（与 05 §6.5 的错误码同一原则）。

### 1.3 与其他编号体系的关系

| 前缀 | 所属 | 含义 |
| --- | --- | --- |
| `FR-xx` / `NFR-xx` / `AC-xx` | 01 | 功能需求 / 非功能需求 / 验收标准 |
| `AS-xx` | **16（本文档）** | 架构规范条款 |
| `M-xx` / `P-xx` / `C-xx` / `N-xx` | 07 | 内存 / 参数 / 并发 / 命名等**章节内局部**条款 |
| `TC-U/I/S/P/E-xx` | 08 | 测试用例 |
| `K-xx` / `R-xx` / `TD-xx` / `ADR-xx` | 11 / 14 / 02 | 技术坑 / 风险 / 技术债 / 架构决策 |

> **注意**：07 文档中的 `R-xx` 是「ROS 2 专项规范」的**章节内局部编号**（仅 §8 有效），
> 与 11 文档的 `R-xx` **风险编号**同名但不同体系。跨文档引用时必须写全
> 「07 §8 R-04」，不得单独写 `R-04`。

## 2. 分层架构规范

16 文档中「层」的定义沿用 [02 §2](02-系统架构设计说明书.md)：
L1 仿真层 / L2 抽象层 / L3 导航与建图层 / L4 任务层（自研） / L5 交互层。

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-01** | MUST | L4 任务层只能通过 ROS 接口（Action / Topic / Service / Parameter）访问 L3，**不得**链接或调用 L3 的内部库、头文件与私有类。 |
| **AS-02** | MUST NOT | 禁止跨层跳跃：L4 不得直接向 L1 的控制入口（仿真插件话题）发布数据，不得绕过 L3 自建控制回路。 |
| **AS-03** | MUST NOT | L4 自研代码中不得出现仿真器/机型特有标识字符串（`gazebo`、`turtlebot3`、`burger`、`waffle`）。这些名称只允许出现在 `patrol_robot_bringup` 的 launch/YAML 与文档中。 |
| **AS-04** | MUST | L4 与外部的一切运行时数据交换必须走 ROS 接口；禁止用共享内存、临时文件、环境变量在节点间传运行态数据（launch 传参除外）。 |
| **AS-05** | MUST | 自研代码不得反向依赖：任何 L4 代码不得被 L3 引用（不得向 Nav2 注册插件式回调，除非在 02 中补 ADR）。 |

**分层判定速查**（写代码前先问自己）：

```
我要加的功能，属于哪一层？
  物理世界/传感器数据      → L1（第三方，只配置，不改）
  通信原语                 → L2（ROS 2，只使用）
  建图/定位/规划/控制       → L3（Nav2/slam_toolbox，只配置与调用）
  任务编排/安全策略/状态    → L4（★ 这里才是自研代码该在的地方）
  可视化/人机接口           → L5（RViz2 + ros2 CLI，尽量不加自研 UI）
```

## 3. 包与依赖规范

### 3.1 包结构（固定）

```
src/
├── patrol_interfaces/        # 接口定义包（ament_cmake + rosidl）
├── patrol_robot_core/        # 核心实现包（ament_cmake，C++17）
└── patrol_robot_bringup/     # 启动与配置包（ament_cmake）
```

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-06** | MUST | 功能包固定为上述三个；新增包必须先补 02 文档 ADR 并说明「为什么不能放进现有的包」。 |
| **AS-07** | MUST NOT | `patrol_interfaces` 不得依赖 `patrol_robot_core` / `patrol_robot_bringup`；`patrol_robot_core` 不得依赖 `patrol_robot_bringup`。 |
| **AS-08** | MUST | 依赖方向严格单向：`patrol_robot_bringup` → `patrol_robot_core` → `patrol_interfaces`。 |
| **AS-09** | MUST | `patrol_interfaces` 只允许依赖 `rosidl_default_generators` 与基础消息包（`std_msgs`、`geometry_msgs`）；**禁止**依赖 `rclcpp`、`nav2_msgs`、`sensor_msgs`。 |
| **AS-10** | MUST | 包间只通过导出的接口头文件交互（`#include "patrol_robot_core/nav_client.hpp"`）；禁止用相对路径 `../../` 直接 include 其他包源码。 |
| **AS-11** | MUST | 新增任何第三方依赖，必须同步更新 `package.xml` 的 `<depend>` 与 [03 依赖清单](03-环境搭建与依赖清单.md)；只改 CMake 不改 `package.xml` 视为缺陷。 |
| **AS-12** | MUST | 禁用 `ament_cmake` 之外的构建系统；不使用 `ExternalProject`、`FetchContent` 拉取第三方源码（保证 `apt` 可复现）。 |

### 3.2 依赖矩阵（允许 / 禁止一览）

| 包 ＼ 依赖 | patrol_interfaces | patrol_robot_core | patrol_robot_bringup | rclcpp | nav2_msgs | launch_ros | turtlebot3_gazebo |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `patrol_interfaces` | — | ✗ 禁止 | ✗ 禁止 | ✗ | ✗ | ✗ | ✗ |
| `patrol_robot_core` | ✓ | — | ✗ 禁止 | ✓ | ✓ | ✗ | ✗ 禁止 |
| `patrol_robot_bringup` | ✓ | ✓ | — | ✗ | ✗ | ✓ | ✓ |

> **反直觉但重要**：`patrol_robot_core` **不得**依赖 `turtlebot3_gazebo` / `launch_ros`。
> 核心包是"能在真车上跑"的部分，一旦依赖仿真包，可移植性承诺（02 §9）即失效。

## 4. 节点与进程粒度规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-13** | MUST | 每个可执行文件只创建并 `spin` **一个**节点；禁止一个可执行文件内 `spin` 多个节点（调试信息与线程模型会失控）。 |
| **AS-14** | MUST | 节点职责单一。**不得**用同一节点同时承担「任务编排」与「传感器级安全判定」两类职责（依据 ADR-08）。 |
| **AS-15** | MUST | 节点名、可执行文件名、launch 中的 `name` 参数三者一致，均为 `snake_case`（`patrol_node`、`safety_guard_node`）。 |
| **AS-16** | MUST | 节点必须支持命名空间与话题重映射；代码中不得出现以 `/` 开头的硬编码话题名（默认名由参数给出，参数默认值不含前导 `/` 之外的逻辑）。 |
| **AS-17** | MUST | 节点启动流程必须显式分四段：**构造 → 参数声明与校验 → 依赖就绪等待 → 进入运行**；参数校验失败或依赖不可用必须退出（见 AS-43、AS-51）。 |
| **AS-18** | SHOULD | 自研节点数量控制在 2–3 个。新增节点须同步更新 [02 §5.1 节点拓扑图](02-系统架构设计说明书.md) 与 [05 §6.3 单一权威表](05-接口设计说明书.md)。 |
| **AS-19** | MUST | 节点不得持有另一节点的对象引用；节点之间只能通过 ROS 通信交互（禁止"编译期耦合 + 运行期各自 spin"的伪解耦）。 |

## 5. 接口规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-20** | MUST | **接口先行**：先冻结 msg/srv/话题契约（写入 05 文档），再写实现。代码与 05 不一致时以 05 为准并提缺陷。 |
| **AS-21** | MUST | 命名规则：自研话题 `/<模块>/<对象>`，自研服务 `/<模块>/<动词>`，全小写下划线；外部话题（`/scan`、`/odom`、`/cmd_vel`）沿用生态惯例，**不加**自研前缀。 |
| **AS-22** | MUST | 单位一律 SI：长度 m、角度 **rad**、时间 s、速度 m/s。任何以度（deg）为单位的参数名必须带 `_deg` 后缀并在代码入口立即转为弧度。 |
| **AS-23** | MUST | 带 `header` 的消息必须填 `stamp`（`this->now()`）与 `frame_id`；位姿类消息的 `frame_id` 默认为 `map`（经 `global_frame` 参数覆盖）。 |
| **AS-24** | MUST | 消息字段**只允许在末尾追加**；不得删除字段、不得改变字段类型或语义。已发布常量（`MODE_*`/`ERR_*`/`REQ_*`）的数值不得变更。 |
| **AS-25** | MUST NOT | 不得用 `string` 传递枚举或错误类型；枚举一律 `uint8` + 命名常量，错误一律数值 `error_code` + 可选 `error_message`。 |
| **AS-26** | MUST | 跨节点传递的"状态"必须使用**标志语义**（描述事实），不得使用**命令语义**（要求对方动作）。订阅方自行决策，避免隐式耦合（依据 ADR-06）。 |
| **AS-27** | MUST | 状态/标志类话题必须使用 `TRANSIENT_LOCAL` durability，保证晚启动订阅者能取到当前值，不得让订阅者依赖周期刷新。 |
| **AS-28** | MUST | 对外接口必须能表达失败：不允许存在"静默失败"的接口（无返回值的服务、无错误码的状态）。 |
| **AS-29** | SHOULD | 接口设计中若出现"两个节点都要写同一个数据"，说明接口划分有误，应拆为「一个权威发布者 + 多个订阅者」（见 05 §6.3）。 |

## 6. QoS 规范

QoS 是 ROS 2 中最容易"能跑但不可靠"的地方。本节条款**全部为 L1**。

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-30** | MUST | 所有自研发布者与订阅者必须**显式**构造 QoS 对象，禁止依赖 `create_publisher` 的隐式默认值。 |
| **AS-31** | MUST | 高频传感器话题（`/scan`）订阅一律使用 `rclcpp::SensorDataQoS()`（BEST_EFFORT），保证与各种发布端兼容。 |
| **AS-32** | MUST NOT | 禁止在传感器话题上使用 `RELIABLE` + 大 depth：会造成背压、延迟累积与内存增长。 |
| **AS-33** | MUST | 周期数据用 `VOLATILE` + `KEEP_LAST(depth ≤ 10)`；状态/标志/一次性资产用 `TRANSIENT_LOCAL` + `KEEP_LAST(1)`。 |
| **AS-34** | MUST | 每个 QoS 选择必须在代码中附注释说明理由，并与 [05 §6.2 QoS 策略矩阵](05-接口设计说明书.md) 完全一致；三者（代码、05 文档、运行态）不一致即为缺陷。 |
| **AS-35** | MUST | QoS 不兼容问题必须在启动期暴露：订阅者若在预期时间内收不到数据，须打印 WARN（含话题名与期望 QoS），不得"静默无数据"。 |

**QoS 决策速查表**：

| 数据类型 | Reliability | Durability | Depth | 依据 |
| --- | --- | --- | --- | --- |
| 周期状态（`/patrol/status`） | RELIABLE | VOLATILE | 10 | 丢一帧可接受 |
| 状态标志（`/safety/emergency_stop`） | RELIABLE | **TRANSIENT_LOCAL** | 1 | 必须可靠且可回溯 |
| 可视化（`/patrol/markers`） | RELIABLE | **TRANSIENT_LOCAL** | 1 | 晚启动 RViz 也要看到 |
| 传感器订阅（`/scan`） | BEST_EFFORT | VOLATILE | 5 | `SensorDataQoS` |
| 静态资产（`/map`） | RELIABLE | **TRANSIENT_LOCAL** | 1 | 与 map_server 匹配 |

## 7. 时间与仿真一致性规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-36** | MUST | 仿真链路上所有节点（含自研节点）必须 `use_sim_time=true`；由 launch 统一注入，**不得**依赖使用者手动设置。 |
| **AS-37** | MUST | 时间运算一律用 `this->now()`；禁止 `std::chrono::system_clock`、`steady_clock` 与 `rclcpp::Clock(RCL_SYSTEM_TIME)` 参与业务计时。 |
| **AS-38** | MUST NOT | 禁止用挂钟时间（wall clock）做业务超时判断——仿真时间与真实时间不成固定比例，超时会随机误判。 |
| **AS-39** | MUST | 依赖时间的功能在开始计时前必须确认时间源已就绪（`/clock` 有输出）；`use_sim_time=true` 但 `/clock` 未发布时，`this->now()` 返回 0，由此产生的"瞬间超时"必须被防御。 |
| **AS-40** | MUST | 单次启动只允许一个时间源：建图阶段由 Gazebo 提供 `/clock`，不得同时混用系统时间或第二个时钟发布者。 |

## 8. TF 与坐标系规范

TF 树的完整设计见 [06 文档](06-坐标变换与TF设计.md)，本节只固化**架构级约束**。

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-41** | MUST NOT | 自研节点**不得发布任何 TF**（`/tf` 与 `/tf_static` 均不可）。TF 树的唯一来源是 L1/L3（见 AS-42）。 |
| **AS-42** | MUST | TF 权威固化，不得出现第二个发布者：<br>`map → odom`：Nav2 `amcl`；`odom → base_footprint`：Gazebo 差速插件；`base_*` 静态链：`robot_state_publisher`。 |
| **AS-43** | MUST | 自研代码只做 TF **查询**（`tf2_ros::Buffer`），查询必须带超时并处理失败分支；**禁止**在回调中无限等待 TF。 |
| **AS-44** | MUST NOT | 坐标系名不得硬编码为字符串字面量；必须通过参数（`global_frame`、`base_frame`）注入，为真车迁移预留。 |
| **AS-45** | MUST | 位姿在 `map` 与 `odom` 之间转换必须显式走 TF，不得假设两系重合（在仿真中常"碰巧"重合，上真车即失效）。 |

## 9. 控制权与安全规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-46** | MUST | `/cmd_vel` 的唯一发布者是 Nav2 `controller_server`；参数 `allow_cmd_vel_override` 默认 `false`，且开启后必须在日志中打印醒目 WARN。 |
| **AS-47** | MUST | 安全职责分层固定：**安全节点负责"感知与判断"，任务层负责"决策与执行"**。安全节点不得越权执行取消/停车动作。 |
| **AS-48** | MUST | 安全阈值必须具备**迟滞**：`stop_distance < resume_distance`，禁止用单阈值判定（否则会在边界抖动）。 |
| **AS-49** | MUST | 参数非法必须**显式失败**：抛异常 + `FATAL` 日志 + 非零退出码。禁止静默降级、静默钳位、静默使用默认值。 |
| **AS-50** | MUST | 任何降级运行（headless 仿真、关闭 Nav2 恢复行为等）必须在日志中标注 `DEGRADED`，并在 [14 变更记录](14-变更记录与迭代规划.md) 登记。 |
| **AS-51** | SHOULD | 安全链路上不得引入不可控延迟：从 `/scan` 到任务层做出反应的路径长度必须可枚举（当前为 1 跳话题 + 1 个 tick），新增中间环节需 ADR。 |

## 10. 并发与执行器架构规范

并发策略的完整说明见 [07 §7](07-C++开发规范与编码指南.md)；本节为架构级硬约束。

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-52** | MUST | 执行器类型与线程数必须显式声明并在 04 文档登记；本项目 `patrol_node` 固定使用 `MultiThreadedExecutor(2)`。 |
| **AS-53** | MUST NOT | **禁止在 ROS 回调中阻塞等待**（`.get()`、`wait_for`、`spin_until_future_complete`）。Action 结果只能由 `result_callback` 写入内部状态，再由 tick 轮询。 |
| **AS-54** | MUST | **单点更新模型**：状态机的状态只允许在 tick 定时器线程中修改；回调只允许置标志位或写 `NavClient` 内部状态。 |
| **AS-55** | MUST | 跨线程共享的成员必须在头文件注释中声明保护策略（`std::mutex` 或"仅 tick 线程访问"）；未声明保护策略的共享成员视为缺陷。 |
| **AS-56** | MUST | 定时器周期 ≥ 10 ms（本项目 100 ms）；热路径（tick / 回调）内禁止日志、禁止动态分配、禁止 `get_parameter`。 |
| **AS-57** | SHOULD | 优先用「状态迁移 + 定时轮询」而非「条件变量 / 自定义线程」。自研线程需在 02 文档补 ADR。 |
| **AS-58** | MUST | 状态迁移代码必须可重入安全：同一 tick 内多次事件触发只允许产生一次有效迁移。 |

## 11. 启动与生命周期规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-59** | MUST | 启动依赖顺序必须在 launch 中显式表达：**Gazebo + spawn → robot_state_publisher → Nav2（lifecycle activate）→ 自研节点**。 |
| **AS-60** | MUST | 使用 Action / Service 前必须显式等待服务端就绪（`wait_for_action_server` / `wait_for_service`），并设置超时与对应错误码（`ERR_NAV_SERVER_UNAVAILABLE`）。 |
| **AS-61** | MUST NOT | 禁止假定"外部依赖一定先于自己启动"。订阅端必须通过 QoS（AS-27）与超时重试自行收敛，不依赖启动顺序。 |
| **AS-62** | MUST | 启动失败必须可见：日志 `ERROR`/`FATAL` + 非零退出码。**禁止**出现"进程活着但功能不可用"的静默失败状态。 |
| **AS-63** | MUST | `patrol_robot_bringup` 的 launch 必须提供分级入口（最小链路 / 建图链路 / 巡逻链路 / 演示链路），每个入口都能独立验证一段链路（对应 09 §5 四条链路）。 |
| **AS-64** | SHOULD | launch 中使用 `IncludeLaunchDescription` 复用官方 launch（Nav2、TurtleBot3），不得复制官方 launch 文件到本仓库修改。 |

## 12. 可测试性规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-65** | MUST | 纯逻辑类（`PatrolStateMachine`、`SafetyEvaluator`、`WaypointLoader` 的算法部分）**不得 include 任何 ROS 头文件**，必须能在无 ROS 运行时下编译与测试。 |
| **AS-66** | MUST | 纯逻辑类不得直接读取时钟、参数或话题；其外部输入（时间戳、配置结构体）必须**作为函数参数注入**（依赖注入），以便测试构造任意时序。 |
| **AS-67** | MUST | 每个公共类必须有对应 gtest 单元测试（`TC-U-*`），且测试不得依赖仿真器与网络。 |
| **AS-68** | SHOULD | 纯逻辑类行覆盖率 ≥ 85%，整体 ≥ 70%；覆盖率报告不作为硬门槛，但显著下降需在 PR 中说明。 |
| **AS-69** | MUST | 涉及并发/超时/重试的逻辑，必须提供可注入的伪时钟或可缩短的超时参数，禁止依赖"真的等 60 秒"来测试。 |
| **AS-70** | SHOULD | 集成测试优先用 `launch_testing`（进程级）而非手工步骤，使 AS-59 的启动顺序可被自动验证。 |

## 13. 可观测性规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-71** | MUST | 每个自研节点必须发布可观测的运行状态（`/patrol/status` 或等效），使外部**无需读源码**即可判断当前状态与错误。 |
| **AS-72** | MUST | 状态迁移必须成对记录：`from → to (触发事件/原因)`。只记录目标状态视为缺陷。 |
| **AS-73** | MUST | 任何对外可见的失败必须携带错误码（[05 §6.4](05-接口设计说明书.md)），且错误码只增不改。 |
| **AS-74** | SHOULD | 关键中间量（最近障碍距离、剩余距离、重试计数）应提供独立话题或状态字段，便于 `rqt_plot` / `ros2 topic echo` 直接观察。 |
| **AS-75** | MUST | 日志级别使用必须遵循 [07 §6](07-C++开发规范与编码指南.md)；热路径（100 ms tick、`/scan` 回调）中禁止 `INFO` 及以上级别的无条件输出。 |

## 14. 参数化与可移植性规范

| 编号 | 等级 | 规则 |
| --- | --- | --- |
| **AS-76** | MUST | 所有可调量必须参数化，**禁止魔法数字**（NFR-06），且参数名必须体现含义与单位（`waypoint_timeout_sec`、`stop_distance`）。 |
| **AS-77** | MUST | 参数默认值只在 `declare_parameter` 出现**一次**；YAML 是运行时唯一覆盖源。同一参数在代码与 YAML 各写一套默认值视为缺陷。 |
| **AS-78** | MUST | 参数必须有类型与范围校验，越界即拒绝启动（AS-49）；参数之间的约束（如 `resume > stop`、四个 `waypoint_*` 等长）必须显式校验。 |
| **AS-79** | MUST | 所有拓扑相关标识必须参数化：坐标系名、话题名、Action 名、节点名、服务名。为「自定义机器人 / 真车迁移」预留出口（02 §9）。 |
| **AS-80** | MUST | 参数不得在运行中被依赖为可热改（除非注册了 `on_set_parameters` 回调并更新 05 文档的"动态可改"列）。未支持的参数被修改必须返回 `successful=False`。 |
| **AS-81** | SHOULD | 新增参数必须同步更新 [05 §5 参数表](05-接口设计说明书.md) 与 `config/*.yaml`；三处不一致即为缺陷。 |

## 15. 架构适应度函数（自动化检查）

「适应度函数」（Fitness Function）指把架构约束变成**可自动执行的检查**，使架构不会随时间被侵蚀。
以下检查应在提交前或 CI 中执行。

| 编号 | 保护的条款 | 检查命令 | 通过标准 |
| --- | --- | --- | --- |
| **AF-01** | AS-03、AS-41、AS-46、AS-53 | `grep -rniE "gazebo\|turtlebot3\|burger\|waffle\|cmd_vel\|broadcast_transform\|sendTransform" src/patrol_robot_core/` | 无匹配（保留命中需注释豁免理由） |
| **AF-02** | AS-07、AS-08、AS-09 | `grep -n "<depend>" src/*/package.xml` | `patrol_interfaces` 不含 rclcpp/nav2_msgs；`patrol_robot_core` 不含 launch_ros/turtlebot3 |
| **AF-03** | AS-65 | `grep -rn "rclcpp\|rosidl\|sensor_msgs" src/patrol_robot_core/src/patrol_state_machine.cpp src/patrol_robot_core/src/safety_evaluator.cpp` | 无匹配（纯逻辑类零 ROS 依赖） |
| **AF-04** | AS-53 | `grep -rn "\.get()\|spin_until_future_complete\|wait_for(" src/` | 无匹配（除 `wait_for_action_server` / `wait_for_service` 启动等待） |
| **AF-05** | AS-37 | `grep -rn "system_clock\|steady_clock\|RCL_SYSTEM_TIME" src/` | 无匹配 |
| **AF-06** | AS-30、AS-31、AS-32 | `grep -rn "create_publisher\|create_subscription" src/` 后人工核对每个调用的 QoS 实参 | 全部显式传入 QoS 对象 |
| **AF-07** | AS-16、AS-44、AS-79 | `grep -rnE "declaration\s*\(\s*\"/" src/`、`grep -rn "\"map\"" src/patrol_robot_core/` | 无硬编码含前导 `/` 的默认名；`"map"` 仅出现在参数默认值处 |
| **AF-08** | AS-76 | `grep -rnE "[^a-zA-Z_](0\.[0-9]+\|[0-9]+\.[0-9]+f)" src/patrol_robot_core/src/` 后人工核对 | 命中的数值仅出现在 `declare_parameter` 默认值处 |

## 17. 规范例外与变更流程

### 17.1 例外申请（豁免）

架构规范允许例外，但**必须留痕**，否则规范会以「这次先这样」的方式被逐步侵蚀。

| 步骤 | 动作 |
| --- | --- |
| 1 | 在 PR 描述中写「违反条款编号 + 原因 + 影响范围 + 计划修复版本」 |
| 2 | 在该代码处加注释：`// AS-EXEMPT(AS-46): 原因… 计划 v0.3 修复` |
| 3 | 若属长期例外（跨版本），必须在 [14 技术债](14-变更记录与迭代规划.md) 登记 `TD-xx` |
| 4 | L1 条款的例外需评审人显式同意 |

> 例外**不得**用于「时间紧」这一理由。时间紧应当走 10 文档的降级预案（缩范围），而不是破坏架构约束。

### 17.2 规范本身如何变更

| 情形 | 流程 |
| --- | --- |
| 新增条款 | 直接追加编号，同步更新 §18 索引 |
| 修改条款含义 | 视为**架构变更** → 先在 02 补 ADR，再改 16，并更新版本号与 14 变更记录 |
| 废弃条款 | 标记 `[DEPRECATED]` + 指明替代条款，**编号不回收** |
| 与 07 冲突 | 以更严格者为准；同时在两份文档中互加交叉引用消除歧义 |
